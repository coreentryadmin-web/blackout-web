## Meridian: an unrated earnings print read as "high impact" — the strongest bucket, not the weakest — FIXED

Fourth product in the "check product by product" audit sweep (SPX Slayer #3192, Helix #3193, Vector #3194). Confirmed by hand against the actual source (not taken on a subagent's word), with a constructed repro run under `node --import tsx --test` on Node 20.

| Field | Detail |
|---|---|
| **Symptom** | `impactFromEarningsImportance` (`meridian-benzinga-earnings-core.ts:43`) returned `"high"` — the strongest impact bucket — whenever Benzinga's `importance` field was `null`/`undefined`/non-finite. `impactFromEarningsImportance(null)` returned `"high"`, identical to a confirmed `importance: 5` mega-cap print. |
| **Root cause** | Benzinga leaves `importance` unrated for a large share of names (that's exactly why `meridian-earnings-data-inventory.mjs` needed a `--min-importance` cohort guard — sampling by date alone returns micro-caps Benzinga has never rated). This function collapsed "we don't know how important this print is" into the *maximum* impact bucket. This codebase already states the correct rule elsewhere, in `meridian-em-priority.ts`'s comments on `scoreOrNull`/`importanceScore`: "unknown ranks BELOW a real 0 — 'we do not know how important this is' is weaker evidence than 'we know it is unimportant'". `impactFromEarningsImportance` did the opposite of that stated rule. |
| **Why this matters** | `impactFromEarningsImportance` feeds `meridian-timeline.ts:224`'s `impact` field on every earnings timeline item, which in turn feeds: `MeridianDesk.tsx:342`'s "High Impact" strip (`allItems.filter(i => i.impact === "high").slice(0, 6)`) — any unrated name crowds out real high-importance names from the 6-item slice; `meridian-snapshot.ts:36,141`'s `high_impact` count (inflated by every unrated name); and the "High"/"High impact" chip rendered directly in `meridian-ui.tsx:188-189` and `MeridianEventDetailPanel.tsx:125`. |
| **Fix** | `impactFromEarningsImportance` now maps an absent/non-finite `importance` to `"low"` — the weakest of the three buckets `MeridianImpact` supports (`"high" \| "medium" \| "low"`, no separate "unknown" tier exists) — rather than `"high"`. Real ratings still bucket `>=4` high, `>=2` medium, else low, unchanged. |
| **Blast radius** | `meridian-timeline.ts` (`impactFromEarningsImportance` call site), `MeridianDesk.tsx` (High Impact strip), `meridian-snapshot.ts` (`high_impact` count), `meridian-ui.tsx`/`MeridianEventDetailPanel.tsx` (impact chips). Only one call site of the function exists in the codebase. |
| **Why not caught earlier** | Zero test coverage existed for `impactFromEarningsImportance` at all (`grep` on `meridian-benzinga-earnings-core.test.ts` for the function name returned no matches) — this is the one function in the file that skipped the "unknown must not read as a real, let alone extreme, value" discipline every neighboring function in this module applies. |
| **Also investigated, NOT fixed (out of scope for this PR)** | `earningsWhenFromTime` (same file, line 28) buckets any Benzinga time with `hour < 12` as `"premarket"` else `"afterhours"` — no mid-session/ambiguous case, unlike its sibling `classifyPrintTiming` in `meridian-reaction-core.ts` which explicitly returns `"unknown"` for a genuinely mid-RTH timestamp. On inspection this only affects the `EarningsTimelineInput.subtitle`/`time` DISPLAY fallback, and only in the narrow case where a row's precise `report_time` (from `earningsReportTimeEt`) is ALSO absent AND the company name is blank — `earningsReportTimeEt` already derives an exact `HH:mm` from the same `time` field whenever it parses, so the fallback bucket this function feeds is rarely reached and never touches the reaction-timing calculation (`classifyPrintTiming`, used correctly elsewhere, already has its own null-safe "unknown" bucket). Flagged here for a future pass rather than widened into this PR, which stays scoped to the higher-impact, broadly-reachable bug above. |
| **Regression guard** | Added: `impactFromEarningsImportance: an unrated print reads as the WEAKEST bucket, never the strongest` and `impactFromEarningsImportance: real importance still buckets high/medium/low` (`meridian-benzinga-earnings-core.test.ts`). Both fail against the pre-fix code (would assert `"low"` where the old code returned `"high"`) and pass post-fix. |
| **Gates** | `npx tsc --noEmit` clean. `node --import tsx --test` on the two touched test files: 36/36 pass (Node 20). |
| **Status** | FIXED — PR pending. |
