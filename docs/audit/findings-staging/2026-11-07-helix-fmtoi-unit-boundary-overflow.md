## 2026-11-07 — `fmtOi` renders "1000.0K" instead of "1.0M" at the K→M unit boundary — FIXED

| **Status** | Fixed |
|------------|-------------------|
| **Symptom** | `fmtOi()` in `src/features/helix/lib/helix-flow-format.ts` — the shared open-interest formatter used by both `HelixFlowTable.tsx`'s live tape OI column and `ContractDrilldownDrawer.tsx`'s "Open int." stat — renders `fmtOi(999_950)` through `fmtOi(999_999)` as `"1000.0K"` instead of promoting to `"1.0M"`. |
| **Root cause** | The M-vs-K branch decision (`n >= 1_000_000`) runs on the RAW value, before any rounding, while the K branch's own display (`(n / 1_000).toFixed(1)`) rounds to one decimal afterward. For `n` in `[999_950, 999_999]`, the raw value is `< 1_000_000` so it takes the K branch, but `(n / 1000).toFixed(1)` rounds UP to `"1000.0"`, producing the nonsensical `"1000.0K"` — four digits past the clean K/M boundary. This is the exact same unit-boundary rounding bug already fixed, independently, in `src/lib/fmt-money.ts`'s `fmtPremium` (K→M and M→B), `src/lib/thermal-discord-card.ts`'s `fmtCompactHeatMoney`, `src/lib/darkpool-discord-format.ts`'s `fmtShares`, and `src/lib/discord-context-enrichment.ts`'s `formatAdvShareLabel` — each of those carries a comment pointing to "the same bug shape" in a sibling file, but `fmtOi` was never one of the siblings checked. It predates all of those fixes (round 296's `fmtOi` change only touched the `n === 0` branch, not the K/M boundary) and had no regression test covering it. |
| **Evidence** | `npx tsx --experimental-test-module-mocks --test src/features/helix/lib/helix-flow-format.test.ts` — before the fix: the new assertion `fmtOi(999_950) === "1.0M"` fails with `actual: '1000.0K'` (confirmed RED on the pre-fix source). After the fix: all 34 tests pass, including `fmtOi(999_949) === "999.9K"` (just below the boundary, unchanged) and `fmtOi(999_999) === "1.0M"`. |
| **Blast radius** | `fmtOi` has exactly two call sites, both already covered by this one shared function: `HelixFlowTable.tsx`'s tape OI cell and `ContractDrilldownDrawer.tsx`'s drilldown stat. A visually distinct, unrelated local function of the same name exists in `src/features/nighthawk/lib/option-chain-prompt.ts` (Night Hawk domain, out of scope for this fix) and does not share this code path. No other caller imports `fmtOi` from `helix-flow-format.ts`. |
| **Fix rationale** | Applied the identical round-first-then-promote guard already used by the four sibling formatters named above: compute `k = n / 1000`, and if `Math.round(k * 10) / 10 >= 1000`, render via the M branch instead of the K one. Kept the existing `.toFixed(1)` precision for the K branch (open interest counts are commonly in the tens/hundreds of thousands, where one decimal of K-precision is the existing, deliberate choice) and left every other branch (0, negative, `>= 1_000_000`) untouched. |
| **Verify** | `npx tsx --experimental-test-module-mocks --test src/features/helix/lib/helix-flow-format.test.ts` (new assertions pass); `npx tsc --noEmit` clean; full `npm test` run clean (see PR). |
