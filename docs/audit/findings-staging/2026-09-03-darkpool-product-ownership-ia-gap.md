## 2026-09-03 — [FINDING, P2 Marketing/IA] Dark Pool was promised platform-wide but no canonical product description credited it, even though it's already live in two products — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Operator report (2026-09-03, same message as the homepage Gamma incident): "Dark Pool capability appearing in platform-wide promises but not clearly owned by any of the 7 product descriptions — an IA/discoverability problem." |
| **Investigation** | Confirmed both halves. **Platform-wide promises exist**: the homepage "what you get" list (`RedesignHome.tsx`), `/about`'s SEO metadata/JSON-LD/body copy, and `/vs/others`'s comparison table all mention "dark pool" as part of the overall platform experience. **No canonical product entry credited it**: `src/lib/marketing/product-manifest.ts` (`PRODUCT_MANIFEST` — the ONE source that actually drives the homepage cards, pricing bullets, FAQ, and structured data for all 7 products) had zero mention of dark pool anywhere in any product's `capabilities`/`positioning`/`lifecycle`, except a passing FAQ mention on Largo describing it as a querying layer over other tools' data, not an owned capability. Notably, `/about`'s hand-authored "Seven modules" prose *does* correctly attribute dark pool to HELIX ("block prints, and dark pool transactions") — but that text is a separate, non-canonical copy block that doesn't match the manifest it should be sourced from, so the two public surfaces disagreed with each other. |
| **What this was NOT** | Critically, this is not "dark pool has no real home in the product" — the opposite is true. Dark pool is already fully implemented and live in two products: **HELIX** ships a dedicated `DarkPoolPanel` (prints, sparkline, bias) rendered directly in its flow-tape UI, backed by `helix-darkpool-bias.ts`. **Vector** overlays live dark-pool price levels on its chart via `VectorDarkPoolToggle`, pre-warmed by the `vector-dark-pool-warm` cron. Two more products consume it as signal without a dedicated UI: SPX Slayer/Night Hawk's shared Cortex gate reads it as a confluence-bonus evidence source (`darkpool-confluence.ts`), and Meridian's earnings cards read dark-pool bias (`shapeMeridianDarkPool`). So the fix is a copy/IA correction, not new engineering — the data layer, UI panels, and cron warm path all already existed and were live. |
| **Fix** | Added a capability bullet + FAQ-answer clause to the canonical `PRODUCT_MANIFEST` entries for the two products that actually render dark pool to a member: HELIX (`capabilities: [..., "Dark pool prints and bias, in the same tape"]`, `faqAnswer` now mentions "a dedicated dark pool panel (prints, sparkline, bias)") and Vector (`capabilities: [..., "Dark pool levels overlaid on the chart"]`). Since these are the canonical manifest entries, every public surface that reads from `PRODUCT_MANIFEST`/`MARKETING_PRODUCTS` (homepage cards, pricing, structured data) now surfaces this consistently — no per-surface copy edits needed. `/about`'s existing (already-correct) HELIX prose was left untouched — it now agrees with the manifest instead of disagreeing with it. |
| **Blast radius** | Copy-only change to two `capabilities` arrays and one `faqAnswer` string. No behavior change to any product's actual UI/data — the dark-pool panel and chart overlay were already shipping; this only makes their existence discoverable in the product descriptions. Left deliberately untouched: SPX Slayer/Night Hawk and Meridian's manifest entries — their dark-pool usage is internal signal (a confluence factor / earnings-card input), not a member-facing dark-pool UI surface, so crediting them the same way would overstate what a member actually sees when they open those desks. No dedicated `/darkpool` route exists and none was added — the operator's report was about product-description ownership, not information architecture at the route level, and creating a new page was out of scope for a copy fix. |
| **Regression guard** | `product-manifest-consistency.test.ts`: new test `"HELIX and Vector's manifest entries credit dark pool — the products that actually render it"` asserting both `capabilities` arrays contain a dark-pool mention and HELIX's `faqAnswer` does too. Confirmed RED pre-fix (`git stash` the source file, keep the test: 1/10 tests fail — exactly the new assertion) and GREEN post-fix (10/10). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: see PR for the run result. |
| **Status** | FIXED |
