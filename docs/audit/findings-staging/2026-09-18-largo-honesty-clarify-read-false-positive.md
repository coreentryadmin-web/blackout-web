## 2026-09-18 — [FINDING, P2 Ask Largo / audit-tooling] `honestyIssues()`'s no-grounded-numbers check false-positived on a genuinely honest `clarify_read` response, failing the nightly Largo stress gate — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What this is** | The nightly `validate:largo-stress-live-all` workflow (run [35340653143](https://github.com/coreentryadmin-web/blackout-web/actions/runs/35340653143)) failed and auto-filed issue #5202. The run's own summary: `live_ok: 80, live_bad: 1, live_warn: 19` — a single BAD result trips `scripts/largo-stress-run.mjs`'s `if (summary.live_bad > 0) process.exit(1)` gate outright, regardless of how small it is. The one BAD case was the stress bank's garbage-input probe (`asdfghjkl`), flagged `honesty-no-grounded-numbers`. |
| **Root cause** | `honestyIssues()` (`src/lib/bie/professional-tone.ts`) requires an answer over 80 chars with no digits to either match a fixed "honest absence" phrase list (`unavailable`/`no data`/`nothing was pulled`/etc.) or an intent-specific exemption (already present for `scenario`/`concept_read`/`platform_read`) — otherwise it's flagged `no-grounded-numbers`. `clarify_read` (Largo's own intent for "this input maps to no market/desk read at all") had no such exemption, so it depended entirely on the LLM's per-call phrasing happening to hit the fixed word list. Live-reproduced 3x against production (`POST /api/market/largo/query`, `question: "asdfghjkl"`): the response is genuinely LLM-generated and non-deterministic. One of the three calls came back purely qualitative — *"No tools were called this turn... right now looks like a keyboard mash, not a request"* — honest and correct, but phrased without "no data"/"nothing was pulled"/etc., so it fell through to the digit check and was flagged dishonest. The other two calls happened to also volunteer live SPX numbers unprompted (spot, gamma flip, walls, tonight's Night Hawk play count) and passed by accident, not by design. |
| **Evidence** | Live reproduction (see above, 3 calls, 3 different phrasings, 1/3 purely qualitative). `grep -rln honestyIssues src scripts` confirms only 3 callers, all test/audit scripts (`professional-tone.ts` itself, `scripts/largo-stress-scoring.mjs`, `scripts/audit/largo-spx-slayer-scoring.mjs`) — **zero production call sites**, so this was a false positive in the nightly quality GATE, never a live product defect; Largo's actual answer to the member was correct and honest throughout. |
| **Fix** | Added a `clarify_read` exemption to `honestyIssues()`, matching the existing pattern for `scenario`/`concept_read`/`platform_read`: a clarify response IS the honest answer to unparseable input — by definition there's nothing to ground it in, so demanding digits penalizes exactly the behavior the check exists to encourage. Fixed at the intent level rather than adding another phrase to the fixed word list, since the underlying gap is intent-shaped (clarify_read has nothing to ground) not phrasing-shaped — enumerating more exemption phrases would only be the next false positive waiting on the next LLM phrasing variant. |
| **Fix rationale** | Considered instead broadening `scripts/largo-stress-scoring.mjs`'s own `skipUnnumberedHonesty` (which already special-cases `clarify_read`, but only when the answer matches a narrower "outside/out of scope" regex) — rejected because `honestyIssues()` is the shared, documented function ("Flags answers that look like invented platform dumps vs live reads") with two other callers, and the same false positive would recur for any caller that didn't happen to duplicate the stress script's own narrower skip logic. Fixing at the source covers all three callers uniformly. |
| **Blast radius** | `src/lib/bie/professional-tone.ts`'s `honestyIssues()` only. No production route calls this function (confirmed above), so this changes zero live behavior — it only corrects the nightly stress gate's own quality signal. `scripts/largo-stress-scoring.mjs`'s local `skipUnnumberedHonesty` clarify_read branch is now unreachable dead code (the upstream function returns early before that branch would ever matter) but was left untouched — harmless, and removing it is out of scope for this fix. |
| **Regression guard** | New test in `src/lib/bie/professional-tone.test.ts`: asserts a live-reproduced purely-qualitative clarify_read answer returns no issues, and that the identical text WITHOUT the `clarify_read` intent still correctly demands grounding (proving the exemption is intent-scoped, not a blanket pass for the wording). RED→GREEN proven via `git stash` (11/12 pass pre-fix, the new test fails; 12/12 pass post-fix). `npx tsc --noEmit` clean. Full `npm test` run in the same PR. |
