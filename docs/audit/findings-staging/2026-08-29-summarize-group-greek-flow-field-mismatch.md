## 2026-08-29 — [FINDING, P2 SPX Slayer/Largo data-correctness] `summarizeGroupGreekFlow` reads field names that don't exist in the real UW response — always returns null — OPEN

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | `summarizeGroupGreekFlow(group, rows)` (`src/lib/group-greek-flow-summary.ts`) is used to derive `mag7_greek_flow` on the SPX desk (`spx-desk.ts:344`, `market-wide.ts:389`) and the "Mag7 dealer greek flow" line in Largo's live-feed builder (`largo-live-feed.ts:637`). Found while measuring a separate transport-truncation fix (see the companion finding filed alongside this one): calling it against the REAL live `fetchUwGroupGreekFlow("mag7")` response (391 rows, measured 2026-08-29) returns `null`, not a summary. |
| **Root cause** | `num(row, ...keys)` (the same file) looks for `net_delta`/`delta`/`net_deltas` (for delta), `call_delta`/`call_deltas`, `put_delta`/`put_deltas`, and `net_gamma`/`gamma`/`net_gex`/`gex` (for gamma) on each row. A real row from `fetchUwGroupGreekFlow("mag7")` carries none of these — its actual keys are `dir_delta_flow`, `total_delta_flow`, `otm_dir_delta_flow`, `otm_total_delta_flow`, `net_call_premium`, `net_put_premium`, `otm_net_call_premium`, `otm_net_put_premium`, `net_call_volume`, `net_put_volume`, `dir_vega_flow`, `otm_dir_vega_flow`, `otm_total_vega_flow`, `total_vega_flow`, `transactions`, `volume`, `timestamp`, `flow_group` — **there is no gamma field in this endpoint's response at all**, and the delta-flow fields are named differently than every key `num()` tries. So `num()` returns `0` for every field on every row, `netDelta`/`netGamma` both accumulate to exactly `0`, and `if (netDelta === 0 && netGamma === 0) return null;` fires unconditionally. |
| **Evidence** | Live sample row (`fetchUwGroupGreekFlow("mag7")`, 2026-08-29): `{"timestamp":"2026-08-28T13:30:00Z","transactions":19985,"volume":114624,"flow_group":"mag7","net_call_volume":5247,"net_call_premium":"5396993.00","net_put_volume":-4844,"net_put_premium":"126779.0000","dir_delta_flow":"308034.7794623153583075000","dir_vega_flow":"150179.6952321463253319000","otm_dir_delta_flow":"133454.5984677336416875000","otm_dir_vega_flow":"116039.0750319682828980500","otm_net_call_premium":"2521181.00","otm_net_call_volume":2681,"otm_net_put_premium":"116596.00","otm_net_put_volume":-4927,"otm_total_delta_flow":"877546.1264256275621754300","otm_total_vega_flow":"637902.2087909039674435600","total_delta_flow":"1578426.2143724109873554300","total_vega_flow":"824468.2845911837618771100"}`. Running `summarizeGroupGreekFlow("mag7", <391 real rows>)` directly (in-process, `UW_API_KEY` live) returns `null` for every row set tested. |
| **Blast radius** | (1) SPX desk's `mag7_greek_flow` field (`spx-desk.ts`, `market-wide.ts`) is `null` on every real build, not just sometimes — any consumer reading it (`format.ts:188`/`:305`'s `mag7Line`, `bie/spx-desk-intel.ts:260`) silently gets nothing. (2) Largo's live-feed "Mag7 dealer greek flow" section (`largo-live-feed.ts:637-643`) never renders — `summary?.headline` is never truthy — so a member asking about mag7 dealer positioning never sees this context, with no error or empty-state signal, it simply never appears. (3) `get_group_greek_flow`'s own `summary` field in the Largo tool response (`run-tool.ts`) is `null` for the realistic default call, meaning the ONLY useful signal that tool can currently return to the model is the raw `rows`/`greek_flow` array itself — the derived summary this function exists to provide has never worked for the real data source. |
| **Why not caught earlier** | No test in the repository constructs a fixture from the REAL UW response shape — `scorer-direction.test.ts`'s fixtures pass already-summarized `{net_delta, net_gamma, bias, row_count}` objects directly to the SCORER, never exercising `summarizeGroupGreekFlow` against a raw UW row at all. The summarizer's own correctness was never independently tested against real field names. |
| **Not fixed here** | This is a distinct root cause from the transport-truncation fix filed alongside it (that fix bounds the SIZE of what's returned; this is about the CONTENT being wrong/empty regardless of size) and requires a real design decision, not a mechanical change: `dir_delta_flow`/`total_delta_flow` are plausible delta proxies but the choice affects the computed `bias`/`headline` math, and **there is no gamma field in this endpoint at all** — `net_gamma` may need to become permanently `0`/omitted for this data source rather than mapped to anything, which changes what the function can honestly claim about "gamma" for a group-flow read. That's a product-facing calibration call belonging to whichever lane owns `mag7_greek_flow`'s meaning (SPX Slayer/Largo), not something to guess through under a transport-cap PR. |
| **Suggested next step** | Map `num()`'s delta lookup to include `dir_delta_flow`/`total_delta_flow` (or decide which is the intended "net delta" for this context), decide what `net_gamma` should honestly report for a data source with no gamma field (omit rather than fabricate a `0` that reads as "measured, no exposure"), and add a test fixture built from a REAL sampled row (as measured here) so a future field-name drift is caught immediately rather than silently. |
| **Status** | OPEN — characterised and evidenced; fix requires a product decision on field mapping, out of scope for the transport-cap fix that surfaced it. |
