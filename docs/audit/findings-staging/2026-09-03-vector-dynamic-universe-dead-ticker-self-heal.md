## 2026-09-03 — [FINDING, P2 Vector] Dead dynamic-universe tickers (NFLIX/LAST/SOX) had no removal path — write-side guard (#3348) stopped new bad writes but left old ones stuck for up to 14 days — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Live 4-engine monitor cycle (2026-09-03, ~07:07 UTC) hit `GET /api/market/vector/universe` as part of the standing correctness sweep and found several rows that did not fit the expected "null = no data, illiquid/off-hours name" pattern: `"NFLIX"` (not a real symbol), `"LAST"`, and `"SOX"` all carried `spot: 0` rather than being absent or genuinely illiquid — a garbled/typo-ticker shape, not an off-hours gap. |
| **Root cause** | `touchDynamicUniverse` (`vector-dynamic-universe.ts`) validates `spot > 0` before WRITING a new entry into the shared, cron-recorded dynamic-universe map — the fix task #71 shipped for exactly this "NFLIX" typo shape. But that guard only ever blocked *new* dead writes. Nothing in the module ever REMOVED an already-bad entry: `pruneDynamicUniverse` only drops entries by age (retention window / cap), never by whether the ticker still resolves to a real chain. So an entry pinned before the write-guard shipped — or one whose chain later stopped resolving for any reason — sat in the map, and every reader of `listSharedUniverseTickers()` (the `/api/market/vector/universe` route via `buildVectorUniverseSnapshot`, the bead recorder cron, Thermal's shared warm path) kept serving it a permanent `spot: 0` row, for up to `DYNAMIC_UNIVERSE_RETENTION_DAYS` (14 days), regardless of when the write-side fix landed. |
| **Confirmed live, not assumed** | The 4-engine check hit `/api/market/vector/universe` directly and observed `NFLIX`/`LAST`/`SOX` all `spot: 0`, well after the write-guard (#3348 + its same-day P2 follow-up, both already merged and referenced in this file's own history) had shipped — direct confirmation that the write-side fix alone could not have prevented this, since these are exactly the class of already-pinned entries it has no mechanism to touch. |
| **Fix** | Added `removeDynamicUniverseTicker(ticker)` (`vector-dynamic-universe.ts`) — the read-side counterpart to `touchDynamicUniverse`'s write-side guard: no-ops for static-allowlist tickers (never dynamic, never removable this way), deletes the entry from the shared Redis map if present, best-effort/fire-and-forget like every other function in this module. Wired into `buildVectorUniverseRow` (`vector-universe.ts`) — the single row-builder shared by the universe snapshot route, the bead recorder, and the 5-min cron — so that whenever a ticker's freshly fetched matrix fails the same `spot > 0` test the write-guard already applies, the dead entry is dropped from the dynamic map within that one read instead of surviving out the full retention window. |
| **Blast radius** | `buildVectorUniverseRow` is the ONE shared row builder (confirmed via `grep -n "buildVectorUniverseRow"` — no duplicate implementation elsewhere), so this self-heals from every caller: the live universe route, the 5s bead-recorder sweep, and the 5-min snapshot cron all now prune a dead dynamic entry the moment they encounter it, not just on the route a member happens to load. Static-allowlist tickers (SPY, SPX, QQQ, …) are explicitly excluded — a static ticker briefly failing to resolve (a real Polygon outage) must never be evicted from the platform's core universe, only ever-dynamic member-viewed names are removable this way. |
| **What was deliberately left unchanged** | `DEL`, `SMC`, and `FR` — also flagged by the same live check as unfamiliar-looking tickers alongside the real dead rows — were investigated and are legitimate, distinct real symbols (Delek US Holdings, Summit Midstream, First Resources-class tickers) that happen to sit near visually similar full names (`DELL`, `SMCI`) in the universe list; not a duplicate/truncation bug, and correctly left untouched. |
| **Regression guard** | `vector-dynamic-universe-touch.test.ts`: 3 new tests — `removeDynamicUniverseTicker` drops an already-pinned dead entry while leaving a live one untouched; no-ops for a static-allowlist ticker; never throws on a missing/empty map. Confirmed RED pre-fix (`git stash` both source files, keep the tests: 3/6 fail in this file) and GREEN post-fix (6/6). `vector-universe.test.ts`'s existing 5 tests still pass unmodified — the new self-heal call is additive and does not change any row-building behavior for a ticker that resolves normally. |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: see PR for the run result. |
| **Status** | FIXED |
