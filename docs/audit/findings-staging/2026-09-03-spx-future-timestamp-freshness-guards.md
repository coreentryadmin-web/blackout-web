## 2026-09-03 — [FINDING, P2 correctness, SPX Slayer] 5 SPX Slayer staleness/freshness checks read a future-dated cross-process timestamp as trustworthy — including a live ENTRY GATE and an EXECUTION-SIM contract — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | This session already found and fixed 16 instances of the same bug shape (a naive `now - eventTimestamp` freshness/staleness check with no guard against a future-dated timestamp, which produces a negative age that trivially passes any threshold check) across Helix/Thermal/Meridian/Largo and shared cron-freshness helpers. Swept SPX Slayer, Night Hawk, Vector, and Banger — areas not yet checked for this specific pattern this session — for more instances. Banger had none (only same-process `duration_ms` logging). This entry covers the 5 confirmed SPX Slayer sites; a companion entry covers the 3 Night Hawk sites and 1 Vector site found in the same sweep. |
| **Root cause / sites** | (1) `spx-play-engine.ts`'s `getNhConfluenceBonus` rejected a Night Hawk edition older than 20h via `ageHours = (Date.now() - publishedAt.getTime())/3.6e6 > 20` — a future-dated `published_at` (written by a separate Night Hawk cron) never exceeds 20, so an untrustworthy edition would be used as a valid morning-prior bias input. (2) `spx-play-gates.ts`'s `evaluatePlayGates` computed `deskStaleSec = (Date.now() - new Date(polledAt).getTime())/1000` for its **live entry gate** — a future `polled_at`/`as_of` (written by a separate warm cron) never trips the `> playGexStaleMaxSec()` block, so a member could enter on stale/corrupted desk data with the "stale" gate silently passing. (3) `playbook-option-execution-contract.ts`'s `isOptionQuoteStale` fed the **execution-sim contract**: a `quote_timestamp_ms` from the future (external option-quote provider clock skew) never exceeded `optionQuoteMaxAgeSec()`, so a bad quote timestamp priced into the sim as trustworthy. (4) `spx-desk-lane-freshness.ts`'s `laneStatus` (browser/server clock skew on a client-rendered `asOf`) always read "live" for a future timestamp. (5) `spx-play-watch.ts`'s `checkPromoteEligibility` computed WATCH-record age from `rec.first_at` (a Redis/DB record a restart or replica could write with skewed clocks) — a future `first_at` never exceeded `maxAge`, extending an untrustworthy record's WATCH→ENTRY promotion eligibility indefinitely instead of expiring it. |
| **Why this matters more than the earlier UI-badge fixes** | Sites 1 and 5 are UI/scoring inputs (same severity class as the earlier freshness-badge fixes), but sites 2 and 3 are LIVE TRADING LOGIC — an entry gate and an execution-simulation contract, not just a display. A future-dated `polled_at`/`quote_timestamp_ms` reaching either of these silently defeats the exact protection they exist to provide (never let stale desk data or a stale quote drive a real decision). |
| **Fix** | All five now guard against a timestamp more than `ZERODTE_MARK_FUTURE_TOLERANCE_MS` (60s, the existing constant `marks-math.ts`'s `isZeroDteMarkStale` already uses for option marks) ahead of `now`, treating it as untrustworthy/stale rather than freshest-possible. Site 1 calls `isZeroDteMarkStale` directly (boolean predicate, exact fit). Sites 2-5 needed the raw numeric age (for message formatting, `Math.max` merges with a second age source, or a distinct "expire the record" action) so they import just the shared `ZERODTE_MARK_FUTURE_TOLERANCE_MS` constant and apply the same bound locally, rather than force-fitting the boolean-only helper. No thresholds, schedules, or unrelated logic changed. |
| **Incidental second bug fixed in site 1** | The old `ageHours > 20` comparison also silently passed for a genuinely unparseable `published_at` (`NaN > 20` is `false`), so a malformed edition timestamp was ALSO treated as fresh. `isZeroDteMarkStale`'s `!(asOfMs > 0)` guard rejects `NaN` too (`NaN > 0` is `false`), closing both gaps with the same fix. |
| **Blast radius** | Five files, one call site each. No schedules, thresholds, or SQL changed — only the freshness/staleness predicate itself. |
| **Regression guard** | Proper behavioral tests for the 3 easily-testable sites: `playbook-option-execution-contract.test.ts` (4 new `isOptionQuoteStale` tests — future beyond tolerance is stale, a few hundred ms ahead is not, genuinely old is stale, fresh-in-the-past is not), `spx-desk-lane-freshness.test.ts` (1 new test), `spx-play-gates.test.ts` (1 new end-to-end `evaluatePlayGates` test asserting the real entry gate blocks on a future `polled_at`). Source-text regression tests for the 2 DB-backed/unexported-function sites, matching this repo's established convention for that case: extended `spx-play-engine.test.ts` with a source assertion, and a new `spx-play-watch-freshness.test.ts`. Confirmed RED pre-fix (`git stash` all 5 source files, keep the tests: exactly the 6 new assertions fail) and GREEN post-fix (41/41 across all 5 test files). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: 11967 passed / 5 failed / 2 skipped — the 5 failures are the documented pre-existing sandbox-only DB-connectivity artifact (same signatures as every other run this session, unrelated files). |
