## Largo: cross-product contract adapters hardcoded `ticker_class` per product instead of deriving it from the ticker — correct only for SPX — FIXED

> **kind:** `FINDING`

Ninth product-surface pass in the "check product by product" audit sweep — a Largo product-read contract compliance audit (`docs/audit/LARGO-PRODUCT-CONTRACT.md`, C4 identity).

| Field | Detail |
|---|---|
| **Symptom** | `src/lib/largo/contract/product-adapters.ts`'s `helixContribution`, `vectorContribution`, and `nighthawkContribution` each hardcoded a constant `ticker_class` — `"equity"` for helix, `"index"` for vector and night hawk — regardless of what ticker was actually queried. |
| **Root cause** | The adapters imported a different, string-only `canonicalTicker` from `./product-read` (which normalizes the ticker string but carries no instrument classification) and never called the codebase's actual classifier (`canonicalTicker` in `src/lib/largo/core/entities.ts`, which returns `{ kind: "equity" \| "etf" \| "index", ... }` and is already reused elsewhere, e.g. `helixTickerIdentity`). Each adapter's author appears to have hardcoded the constant that happened to be correct for the SPX-only fixture they were testing against, rather than deriving it. |
| **Why this matters** | The contract's own rationale (`product-read.ts`, C4) states: "SPX ≈ 10 × SPY. A cross-product comparison that mixes them produces a plausible wrong number" — `ticker_class` exists precisely so a consumer never has to guess. With the hardcoded constants, every `ProductSignal` these three adapters build for any ticker other than the one the constant happens to match is internally self-contradictory: asking the live `get_cross_product_read` tool about `"TSLA"` returned `ticker: "TSLA"` alongside `ticker_class: "index"` from both vector and night hawk (TSLA is an equity), and asking about `"SPX"` returned `ticker_class: "equity"` from helix (SPX is an index). |
| **Fix** | Added `tickerClassFor(ticker)`, which calls the real classifier (`@/lib/largo/core/entities`'s `canonicalTicker`) and falls back to `"equity"` only when the ticker cannot be classified at all (matching that module's own default for an unrecognized symbol) — replacing all three hardcoded constants. |
| **Blast radius** | `product-adapters.ts` only — `thermalContribution` and `meridianContribution` never set `ticker_class` (they contribute no directional signal by design) and are unaffected. Every existing test in `product-adapters.test.ts` used `ticker: "SPX"` fixtures throughout and passed unmodified, confirming the SPX-only blind spot. |
| **Why not caught earlier** | No test in `product-adapters.test.ts` ever asserted on `ticker_class`, and every fixture ticker was `"SPX"` — the one ticker for which two of the three hardcoded constants happened to be right. |
| **Regression guard** | New test: `helixContribution`/`vectorContribution`/`nighthawkContribution` for `"TSLA"` must report `ticker_class: "equity"` (not the old hardcoded index/equity constants), and `"SPX"`/`"SPY"` must report `"index"`/`"etf"` respectively. Confirmed **failing** against pre-fix code (`git stash` toggle: 1/11 failed) and passing post-fix (11/11). |
| **Gates** | `npx tsc --noEmit` clean · `product-adapters.test.ts` 11/11 pass (Node 20.20.2) · full `npm test` — see PR. |
| **Status** | FIXED |
