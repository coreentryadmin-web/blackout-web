## 2026-09-04 — [FINDING, P2 correctness, Night Hawk 0DTE exit ledger] A thesis/plan/flat 0DTE exit's frozen `exit_pnl_pct` can read a flat 0% for a play the engine itself just exited at a real loss — the exit-detail prose and the numeric field disagree on the SAME exit event — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Routine "4-engine live monitor" correctness pass (SPX Slayer / Legacy / Night Hawk 0DTE / Vector) against production. `GET /api/market/zerodte/board` (authenticated, temp Clerk admin+premium session via `mintClerkPremiumSession`) returned a `CRCL` ledger row with `exit_reason: "thesis"`, `exit_detail: "Thesis broken (veto) at -0.22% — exiting the remaining position at market, not hoping: ..."`, yet the same row's `exit_pnl_pct: 0`, `entry_premium: 2.27`, `last_mark: 2.27` — the human-readable exit reason states a real -0.22% loss while the numeric field members/Largo/grading consumers actually read says the exit was flat. |
| **Root cause** | `buildExitContext` (`src/lib/zerodte/exit-engine.ts`) freezes the exit record from `mark = resolveExitMark(decision, entryPremium, observedMark)`. For every NON-floor-honored exit family (`thesis_break`, `plan_stop`, `flat_theta_bleed` — anything whose reason doesn't start with `ratchet`/`runner_floor`), `resolveExitMark` returns `round2(observedMark)` — the raw mid rounded to the nearest CENT. `buildExitContext` then computed `pnl_pct: pinnedLivePnlPct(entryPremium, mark)` off that cent-rounded price. Meanwhile `evaluateExitState`'s own decision (a few lines earlier in the SAME call chain, `src/lib/zerodte/exit-engine.ts:483`) computes `pnlPct = pinnedLivePnlPct(entryPremium, currentMark)` off the UNROUNDED `currentMark` and bakes that exact percentage into `decision.detail` via `fmtPct` (which rounds only the *percentage*, to 2dp, not the underlying price). `observedMark` is `zeroDteMidOf(bid, ask)` — `(bid+ask)/2` kept to 4 decimal places (`src/lib/zerodte/marks-math.ts`) — so it routinely lands on a legitimate half-cent (e.g. bid $2.26 / ask $2.27 → mid $2.265). Rounding that mid to the cent *before* dividing by `entryPremium` can erase up to `0.5¢ / entryPremium` of real P&L: exactly ±0.22 points on the observed $2.27 CRCL premium, and proportionally worse on cheaper 0DTE lotto premiums. |
| **Blast radius** | One function, `buildExitContext` in `src/lib/zerodte/exit-engine.ts` — its `pnl_pct` output feeds `entry_context.exit.pnl_pct`, read back by `readExitStampFromEntryContext` (`src/lib/zerodte/play-timeline.ts`) into `zerodte-service.ts`'s board/ledger row (`exit_pnl_pct`) AND into `mfe_capture_pct` (`mfeCapturePct(exitStamp.pnl_pct, ...)`, `zerodte-service.ts:494`) — both member-facing. `peak_pnl_pct` on the same context object is NOT affected (computed from the un-rounded `peakPremium` parameter directly, no intermediate cent-rounding). Floor/stop-HONORED exits (`ratchet_*`/`runner_floor`) are also unaffected by design — for those, `mark` is the constructed floor/stop price, which correctly *is* the assumed fill and correctly drives `pnl_pct` (see the pre-existing "floor breach honors the floor mark" test, unchanged). |
| **Fix** | In `buildExitContext`, compute `pnl_pct` from `observedMark` (the raw, un-rounded mid) whenever the exit is NOT floor/stop-honored, and from `mark` (the constructed floor price) when it is. This makes the persisted `exit_pnl_pct` agree exactly with the percentage already embedded in `decision.detail` for every thesis/plan-stop/flat exit, while leaving `mark`/`mark_observed`/`mark_honored` (the *displayed* frozen price and its provenance flag) and the floor-honored path completely unchanged — no schema change, no new field, additive one-line branch plus a `markHonored` local to avoid computing the honored-check twice. |
| **Why this wasn't caught earlier** | Every existing `buildExitContext` test used entry/mark fixtures that were already whole cents (`4.0`, `3.48`, `3.2`, `3.9`) — none exercised a half-cent mid, so the cent-rounding-before-division precision loss had no fixture that could expose it. The bug only manifests when the raw mid, rounded to the cent, lands exactly on (or near) the pinned entry premium — an edge case, not the common case, which is exactly why it read as a "flat exit" instead of a visibly wrong number. |
| **Regression guard** | New test in `src/lib/zerodte/exit-engine.test.ts`: `ENTRY = 4.0`, `rawMark = 3.996` (`round2(3.996) === 4.00 === ENTRY` — the exact "rounds back to entry" trap), a thesis-break veto forces the exit. Asserts `decision.detail` states the real `-0.1%` move, `ctx.mark === 4.0` (display price still cent-rounded, unchanged), `ctx.mark_honored === false`, and `ctx.pnl_pct === -0.1` (previously `0`). Confirmed RED pre-fix via `git stash` on just `exit-engine.ts` (test failed `0 !== -0.1`) and GREEN post-fix.
