## 2026-09-03 — [FINDING, P3 correctness, public gamma snapshot] Public `/api/public/gex-snapshot` served raw unrounded IEEE-754 floats (spot/change_pct) while every other consumer of the same canonical matrix rounds — FIXED

| Field | Detail |
|---|---|
| **What prompted this** | Found during a BLACKOUT AUTOPILOT discovery-mode pass (task `BO-P3-GEXSNAP-ROUND`, claimed via `scripts/agent-ops/claim-task.mjs` — see `.blackout-agent/`), demonstrating the "empty queue -> discovery -> claim -> begin work" loop end to end rather than describing it. Started from `round-floats.ts`'s own documented systemic bug class ("money-math produces IEEE-754 floats with 6-13 spurious decimal digits, e.g. `7499.360000000001`... across ~16 endpoints") and checked whether the public gamma-snapshot endpoint — the exact page examined for a separate finding earlier the same day (`2026-09-03-gamma-canonical-source-copy-verified.md`) — was one of the ~16 already fixed. |
| **Root cause** | `src/lib/public-gex-snapshot.ts`'s `buildSnapshotFromHeatmap` copies `spot`/`change_pct`/`call_wall`/`put_wall`/`flip` straight off `fetchGexHeatmap`'s own return value with no rounding. `fetchGexHeatmap` itself does NOT pre-round these fields — confirmed by reading `src/app/api/market/gex-heatmap/route.ts` (Thermal's own route, reading the exact same shared matrix), which explicitly wraps its response in `roundFloats({...heatmap, ...})` before serving it. `spot` in particular is frequently derived as `spy.price * 10` (SPX synthesized from SPY, `polygon-options-gex.ts`), which readily produces the documented `X.360000000001`-style noise. |
| **Blast radius** | One function, one file (`public-gex-snapshot.ts`). Two consumers: `GET /api/public/gex-snapshot` (unauthenticated, rate-limited) and the ISR-seeded `/tools/gamma-snapshot` page + homepage `HomeGammaPromo` widget (via `readPublicGexSnapshotSeed`, which reads the same cached/persisted snapshot this fix rounds at the source — no second fix site needed there). No other file duplicates this logic. |
| **Why this one was missed by the earlier ~16-endpoint sweep** | This endpoint is public/unauthenticated marketing surface, not a `/api/admin/*` or member-desk route — the kind of surface a sweep organized around "endpoints members hit" would not naturally reach. It also sits one layer removed from the obviously-named `gex-heatmap` route that already got the fix. |
| **Fix** | Wrapped `buildSnapshotFromHeatmap`'s return object in `roundFloats(...)` (default 2dp, same as Thermal's route) — the same shared utility, not a re-implementation. Applied only to the freshly-computed object, not `degradedFromLastGood`/`emptySnapshot`, which either spread an already-rounded persisted snapshot or carry no floats at all. |

Confirmed RED pre-fix (`git stash` on just `public-gex-snapshot.ts`, keeping the test: `5499.360000000001` served verbatim, assertion fails) and GREEN post-fix (2/2).
