## 2026-09-01 — [product, gate-calibration] G-14 late-window block silently widened from 14:00 to 15:30 ET, reopening the toxic bucket its own evidence describes — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Context** | User asked for a live deep-dive on Night Hawk 0DTE + Vector through today's session, explicitly targeting fewer, higher-quality ("beast") plays instead of yesterday's mostly-flat outcomes. Investigated whether any commit gate had drifted since its original calibration. |
| **Root cause** | `gates.ts`'s G-14 late-afternoon block (`LATE_AFTERNOON_BLOCK_ET_MINUTES`) was hardcoded to 14:00 ET when it shipped (FINDINGS 2026-07-28, evidence: 14:00-15:30 bucket ran 14.3% WR / −19.02% avg P&L, 90-day/101-play prod record). On 2026-08-03 (commit `f2ff0ddf`, PR #1591 "Night Hawk session 10:00–3:30 commit, 3:50 flat exit"), G-14 was re-aliased to `NEW_PLAY_CUTOFF_ET_MINUTES` — the *general* session-exit constant, which that same PR widened to 15:30 ET "to align session discipline with operator intent." Because G-14 was defined as a straight alias rather than its own constant, it silently inherited the widening: the directional late-window block moved from 14:00 to 15:30 along with the unrelated exit-time change, reopening the exact 14:00-15:29 window the gate exists to close. `confluence.ts`'s `ENTRY_CUTOFF_ET_MINUTES` (feeds `timing_ok`, part of the G-12 confluence score/floor) carried the same alias and moved with it. |
| **Evidence this is still live, not stale history** | Pulled `GET /api/market/zerodte/record?days=90` live (2026-09-01). The `late 14:00-15:30` time-of-day bucket: **n=19, win rate 21.1%, avg P&L −12.72%** — materially unchanged from the original 14.3% WR / −19.02% finding that motivated the gate in the first place. All 19 of these plays post-date the 2026-08-03 widening, so this is the reopened window bleeding in real time, not a pre-fix artifact. Cross-checked the `flat_scratch` exit family separately (44 rows/90d): the `flat_theta_bleed` rule itself is **net protective**, not the culprit (36 scratches saved an avg 16.21% loss vs 8 that cost an avg 7.40% of forgone upside) — ruled out as a place to loosen. |
| **Fix** | Split `LATE_AFTERNOON_BLOCK_ET_MINUTES` (G-14, `gates.ts`) and `ENTRY_CUTOFF_ET_MINUTES` (`confluence.ts`, feeds G-12's `timing_ok`) off the shared `NEW_PLAY_CUTOFF_ET_MINUTES` and onto a new, dedicated `DIRECTIONAL_LATE_CUTOFF_ET_MINUTES = 14 * 60` constant (`plan.ts`), with the full history documented inline so a future change to the unrelated condor/exit-time cutoff can't silently drag this along again. `NEW_PLAY_CUTOFF_ET_MINUTES` itself is UNCHANGED at 15:30 ET — it still correctly governs the condor-eligible discovery window (`scan.ts`'s `pastCutoff`) and the persist-layer backstop, both of which are deliberately condor/backstop concerns per the 2026-08-03 PR, not the directional-quality question G-14 answers. |
| **What was deliberately NOT changed** | `NEW_PLAY_CUTOFF_ET_MINUTES` (15:30 ET) — condors still get the wider window (they benefit from late theta crush, per the gate's own condor-exempt logic, unaffected by this fix). `intel.ts`'s "Xm left in the entry window" countdown on already-OPEN plays — a different, advisory-only code path (adding to an existing position, not a new commit), not touched to keep the PR scoped to the actual gating/scoring defect. The `flat_theta_bleed` exit thresholds (25min / ±10% band) — measured net-positive above, left alone. |
| **Blast radius checked** | Grepped every reader of `NEW_PLAY_CUTOFF_ET_MINUTES`: `scan.ts` (`pastCutoff`, condor-only fresh discovery — correctly still 15:30, no change needed since G-14 itself still blocks any directional candidate that slips through), `plan.ts` (own backstop, unchanged), `intraday.ts` (a display label, unchanged, still accurate for the persist-layer boundary it describes), `intel.ts` (OPEN-play advisory countdown, left as noted above). Only the two call sites that feed an actual commit/score decision (G-14, G-12's `timing_ok`) were moved. |
| **Regression guard** | `gates.test.ts`: updated the G-14 boundary tests to the new 14:00 boundary (block-at-14:00, commit-at-13:59, still-blocked-at-15:45, condor-exempt-at-15:15 unchanged since condors were never gated by this). `confluence.test.ts` needed no changes — all its `nowEtMinutes` fixtures are well before 14:00. Full `src/lib/zerodte/*.test.ts` suite: 1212 pass / 0 fail / 1 pre-existing skip (Node 20, `--experimental-test-module-mocks`). `npx tsc --noEmit` clean. |
| **Status** | FIXED — PR pending. |
