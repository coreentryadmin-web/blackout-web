### Root cause

`resolveHeatmapDividendYieldUncached` (the ETF dividend-yield fallback path, `polygon-options-gex.ts:2059`)
calls `trailingTwelveMonthDividendYield(dividends, spot, Date.now())` with the REAL current time — it
has no injectable clock, unlike the pure `trailingTwelveMonthDividendYield` function itself, whose own
sibling test correctly passes a fixed `nowMs`.

The ETF-fallback test ("dividend-yield resolve falls back to trailing dividends when ratios has no row
(ETF)") went through this real-clock path but supplied **hardcoded absolute** `ex_dividend_date` fixture
values, with a comment asserting the exclusion "from a 2026-08-28 'now'". That was true in August and
became false the moment the real calendar's trailing-12-month window caught up to the fixture's oldest
"included" date — a deterministic time bomb, not a flake. It fired live: on 2026-09-19 the test failed
with `expected ~0.01, got 0.0075` — one row (`2025-09-19`) that was meant to read as safely inside the
window had aged past it, dropping the count from 4 qualifying dividends to 3.

This was caught as a spot-check while chasing an unrelated PR (#5238, cross-desk-coaching disclosure
fix, a different lane's work) whose CI `verify` gate went red on this same test — confirming the failure
was real and reproducible on `main` itself, unrelated to that PR's diff (already flagged there in a
coordinator comment before this fix was written).

### Evidence

Reproduced on `main` before any fix: `npx tsx --experimental-test-module-mocks --test
src/lib/providers/polygon-options-gex.test.ts` → `not ok 62 ... error: 'expected ~0.01, got 0.0075'`.
Traced to the resolver's real `Date.now()` call plus the test's stale absolute-date comment; confirmed
the underlying pure function (`trailingTwelveMonthDividendYield`) already supports an injected `nowMs`
via its own separate test two tests below, which is why only this one hardcoded-date test was affected.

### Fix

Rewrote the fixture to use dates computed relative to the REAL `Date.now()` the resolver itself reads
(`daysAgo(n)` helper), rather than absolute calendar dates pinned to a comment-only assumption about
when the test would run. The four "included" dividends are now 90/180/270/360 days back (all inside any
possible trailing-12-month window regardless of run date) and the one "excluded" dividend is 400 days
back (outside it regardless of run date) — the test now asserts the same real behavior with zero
calendar-drift risk, permanently.

### Fix rationale

No production code change was needed or made: `resolveHeatmapDividendYieldUncached` has no test-time
clock injection point today, and adding one purely to make one test's fixture dates absolute would be
strictly more invasive than fixing the fixture itself to stop assuming a frozen "now". The minimal,
permanent fix is entirely inside the test.

### Blast radius

Single test, single file. No other test in this suite hardcodes an absolute date against a real-clock
code path in the same way (checked: the sibling `trailingTwelveMonthDividendYield` test already injects
`nowMs` correctly and is unaffected).
