## Vector: play-intel CONFLUENCE/WALL chips hard-truncate their trailing data value on mobile — FIXED

> **kind:** `FINDING`

Found via a live production visual audit (proxy-tunnel Chromium, `/vector?ticker=SPY` at 430×932) — a real rendered defect confirmed with a screenshot, a DOM computed-style read, and the untruncated source string, not inferred from the diff.

| Field | Detail |
|---|---|
| **Symptom** | On `/vector` at mobile width, the CONFLUENCE chip under the play card rendered `771.53 (0.29% above) — golden pocket + call wall · score…` — the trailing score number was cut off entirely, replaced with an ellipsis. The WALL chip carries the same risk (same CSS, same "full sentence + trailing value" shape) but happened to render a short-enough note (`772C firm — held 100% of last 6m, clustered`) to stay under the cutoff in this capture. |
| **Root cause** | `VectorPlayIntelStrip.tsx` renders `confluence?.[0]` and a computed `wallNote` — both full-sentence strings built by `vector-confluence.ts`'s `describeConfluenceZone` (`` `${center} (${pct}% ${side}) — ${kinds} · score ${z.score}` ``, confirmed complete at the source, no truncation there) and `vector-wall-integrity.ts`'s note builder. `globals.css`'s `.vector-play-intel-chip-value` applied Tailwind's `truncate` utility (`white-space:nowrap; overflow:hidden; text-overflow:ellipsis`) unconditionally to every chip value, including these two long ones. The parent `<span>` in `VectorPlayIntelStrip.tsx` carries `title={...}` with the full string, so desktop members recover it on hover — but there is no hover on a touch device, so the mobile member never sees the actual score/wall-integrity value at all, only the label plus a truncated fragment ending in "…". Confirmed live: DOM read showed `whiteSpace: nowrap, overflow: hidden, textOverflow: ellipsis` on `.vector-play-intel-chip-value`, box width 378px, and the untruncated string is 60 characters — well past what fits on one line at 11px in that width. |
| **Fix** | `globals.css`: removed `truncate` from `.vector-play-intel-chip-value`, replaced with `whitespace-normal break-words` so long values wrap onto a second line instead of being cut. `.vector-play-intel-chip` was widened from `max-w-full` to a fixed `max-w-[15rem]` so a wrapped value has a sane width to wrap within, rather than stretching to the full flex-wrap row. REGIME and MOVE chips (short single-word/short-phrase values) are unaffected — they simply never wrap, since they fit on one line already. |
| **Blast radius** | Single CSS rule pair, `.vector-play-intel-chip` / `.vector-play-intel-chip-value` in `globals.css`. Applies to all four chip variants (`--calm`/`--volatile` regime, `--em`, `--conf`, `--wall`) since they share the base `-value` class, but only the confluence/wall chips carry strings long enough to be affected in practice. |
| **Why not caught earlier** | The desktop hover `title=` tooltip fully masked the defect for anyone testing on a mouse-driven device — the truncated text still *looked* like a plausible (if terse) label, and the missing information (a numeric score) is easy to not notice is missing unless compared against the untruncated string. |
| **Gates** | `npx tsc --noEmit` clean (CSS-only change). `npx stylelint src/app/globals.css` — 2 pre-existing unrelated issues at different lines (a deprecated `word-break` keyword and a duplicate `overflow` property elsewhere in the file), none introduced by this change. |
| **Status** | FIXED — confirmed live pre-fix (screenshot + DOM computed style + source string) against production `/vector` at 430×932 before writing the fix; no live UI test harness exists for this component to verify the DEPLOYED fix from this sandbox (same limitation as the sibling Night Hawk filterbar-overlap fix earlier today), so a post-deploy re-screenshot of `/vector` at 430px is the recommended follow-up per the repo's "a merge is not a verification" discipline. |

### How this was investigated
This item was originally logged as "not yet fixed" in `docs/audit/findings-staging/2026-08-30-nighthawk-mobile-filterbar-overlap.md`'s "Other live UI defects" list, alongside four other items from the same audit pass. Re-screenshotting all five live rather than guessing at CSS fixes blind found that **four of the five do not reproduce** (retracted in a separate docs PR): the `/heatmap` tab-strip clip was a harness artifact reading `.textContent` through `display:none` descendants; the `/heatmap` NET FLOW dollar column is intentional horizontal-scroll content with an existing scroll-fade cue; the `/terminal` Night Hawk desk-picker card renders identically to its siblings; and the `/terminal` composer "clip" is a deliberate 20s-looping CSS marquee caught mid-frame. This CONFLUENCE/WALL truncation is the one item of the five that reproduced exactly as originally reported, with a confirmed root cause and fix.
