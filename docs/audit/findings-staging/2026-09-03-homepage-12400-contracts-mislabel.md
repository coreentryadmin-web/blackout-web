## 2026-09-03 — [FINDING, P2 Marketing copy] Homepage/"Why BlackOut" claimed "12,400+ contracts scanned daily" — the real, measured number is US stocks, not options contracts — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Operator report (2026-09-03, same message as the homepage Gamma incident): "'12,400+ contracts scanned daily' needing provenance — should be a derived/rolling metric, not a static hardcoded number." |
| **Investigation** | The literal string "12,400+" was hardcoded in three places: `WhyBlackoutContent.tsx:20` ("Our engine scans 12,400+ contracts daily..."), `RedesignHome.tsx:85` (hero credibility bullet), and `RedesignHome.tsx:228` (pipeline "ingress" stage label). A real, measured number this traces to DOES exist: Polygon's grouped-daily endpoint returns every US stock for a session (~12,400/day) — documented in `scripts/audit/market-banger-scan.mjs`'s own header comment, `docs/audit/0DTE-RESEARCH.md`, a live 2026-07-27 measurement in `docs/audit/MONDAY-RTH-READINESS.md`/`FINDINGS.md` ("grouped-daily 12,410 stocks"), and this repo's own CLAUDE.md audit-toolkit section. That figure powers the whole-market Bangers momentum scanner. `git log -S"12,400"` shows the marketing string was introduced directly in landing-page PRs (#1167, #1169, #1471) with no accompanying data-sourcing commit — the copy appears to have lifted the "~12,400" number straight from the engineering docs above and relabeled "stocks" as "contracts." No aggregate options-contract count is computed anywhere in the codebase (confirmed via grep across `src/lib/providers/`, `src/features/vector/`, and searches for `contracts_scanned`/`contract_count` — zero hits) — so "12,400+ contracts" was a genuinely false claim as written: it never counted contracts, and no code path ever has. |
| **Fix** | Corrected the unit on all three instances from "contracts" to "stocks"/"tickers," matching the real, measured metric: `WhyBlackoutContent.tsx` → "Our engine screens the entire U.S. stock market — 12,400+ tickers — every day"; both `RedesignHome.tsx` instances → "12,400+ stocks screened daily". The number itself (12,400+) is left as-is since it's the real measured figure for the US equity universe Polygon's grouped-daily endpoint returns — only the mislabeled unit was wrong. |
| **Scope note** | Wiring this to a LIVE/rolling metric (rather than a hardcoded "12,400+" string, which the operator's report also floated) was considered and deliberately deferred: it would require new plumbing — a public route or cached value exposing the Bangers scanner's actual daily grouped-daily row count to the marketing pages, which are otherwise fully static/ISR. That's a real, larger follow-up (new API surface + cache + client wiring), out of scope for what is fundamentally a one-word factual correction. The number stays accurate to within Polygon's normal day-to-day US-listing count fluctuation (~12,300–12,500), same tolerance the audit toolkit itself already treats as "~12.4k." |
| **Blast radius** | Copy-only change to two components, three text nodes. No behavior, data, or layout change. No other public surface (FAQ, pricing, structured data) referenced the mislabeled figure — confirmed via grep, only these two files matched. |
| **Regression guard** | `WhyBlackoutContent.test.ts` and `RedesignHome.seo.test.ts`: new tests asserting neither file's source ever matches `/12,400\+?\s+contracts/i` again. Confirmed RED pre-fix (`git stash` the two source files, keep the tests: 2/15 tests fail — exactly the two new assertions) and GREEN post-fix (15/15). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: see PR for the run result. |
