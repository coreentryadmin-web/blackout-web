## 2026-09-04 — [FINDING, P3 test-infra, BLACKOUT Autopilot] `select-task` regression test read the LIVE `.blackout-agent/WORK_QUEUE.md` instead of a fixture, breaking on any PR that changed the live queue's task composition — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Reviewing three separate autopilot PRs today (#3441, #3447, #3449) that all independently hit the same `verify` failure: `scripts/blackout-agent/blackout-agent.test.mjs`'s `select-task returns highest-priority P1 task for cursor` test failing with `expected P1 task, got BO-P2-0003` (or similar). Each time it was diagnosed ad hoc as "this PR's bundled `.blackout-agent/WORK_QUEUE.md` edit broke a test" and left for the PR author to work around — but the actual defect is in the test itself, not in any of those PRs' logic. |
| **Root cause** | `select-task.mjs` reads `MARKDOWN_FILES.workQueue` — a hardcoded absolute path from `lib/paths.mjs` (`join(AGENT_ROOT, "WORK_QUEUE.md")`) with no env-var or cwd-based override. The test spawned `select-task.mjs` as a real subprocess and asserted the result always starts with `BO-P1-`, with zero isolation from the LIVE, checked-out `.blackout-agent/WORK_QUEUE.md`. That file is edited by essentially every autopilot handoff PR (marking tasks DONE, adding new QUEUED ones) as part of normal operation — so the test's correctness depended entirely on the live queue happening to still have an unclaimed P1 task at the moment CI ran, which is not an invariant anyone was maintaining. Confirmed live: on `origin/main` today (P1 tasks still queued) the test passes; replaying the exact queue state `#3447`/`#3449` land (`BO-P1-0004/0005/0007` all `DONE`, only `BO-P2-0003` `QUEUED`) against the *old* test code reproduces the identical CI failure (`expected P1 task, got BO-P2-0003`), confirming this is a test-isolation defect and not a bug in either PR's own diff. |
| **Blast radius** | One test, one file (`scripts/blackout-agent/blackout-agent.test.mjs`). Confirmed via `select-task.mjs`'s source that it has no other consumer of `MARKDOWN_FILES.workQueue` that this test's fixture-write could destabilize — `select-task.mjs` itself is stateless/read-only w.r.t. the queue. No other test in the file depends on `WORK_QUEUE.md`'s content. |
| **Fix** | Made the test hermetic: back up the real `WORK_QUEUE.md`, write a small fixture queue with a guaranteed-unclaimed `BO-P1-9901` (P1) and `BO-P2-9902` (P2) row, run `select-task.mjs` against the fixture, assert it picks the P1 fixture task specifically, then restore the original file content in a `finally` (so a crash mid-test can't leave the live queue corrupted). Matches the file's own existing convention of writing directly into `.blackout-agent/HEARTBEAT/*.json` for other tests (`claimLock` tests), just adds the missing restore step since `WORK_QUEUE.md` — unlike the heartbeat files — is meaningful committed content, not a scratch file. |
| **A trap worth naming** | The fixture's task IDs must match `select-task.mjs`'s own parser regex (`/^\|\s*(BO-P\d+-\d+)\s*\|.../` — i.e. `BO-P<digit>-<digits>`, no descriptive suffix). A first attempt using `BO-TEST-P1-FIXTURE` silently parsed to zero candidates (`selected: null`, exit code 3) rather than failing loudly — the regex just skips any row it can't match, so a malformed fixture ID reads as "queue is empty," not as "fixture ID is wrong." Caught by manually running `select-task.mjs` against the fixture before trusting the test's own PASS. |
| **Regression guard** | The fix *is* the regression guard — the test is now independent of `.blackout-agent/WORK_QUEUE.md`'s live contents by construction, so no future queue edit (by any lane) can silently break it again. |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). `node --test scripts/blackout-agent/blackout-agent.test.mjs` — 9/9 pass. `node --test scripts/blackout-agent/*.test.mjs` (full directory) — 21/21 pass. Confirmed RED pre-fix via `git stash` on just the test file, replaying the `#3447`/`#3449` queue state — reproduces `expected P1 task, got BO-P2-0003` exactly; GREEN post-fix under the same replayed queue state. |
| **Status** | FIXED |
