## 2026-08-30 — [FINDING, P3 Night Hawk/0DTE] `currentZerodteSessionAnchor`'s `nowMs` is silently ignored for `session_state`/`session_note` — OPEN, write-up only

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Severity** | P3 — currently benign in production (the only live call site passes no argument, so it happens to match real time anyway); real risk is latent, in any future caller that injects a non-"now" time. |
| **Where** | `src/lib/zerodte/session-phase.ts`, `currentZerodteSessionAnchor` (lines 54–65). Root cause upstream in `src/features/nighthawk/lib/session.ts`'s `todayEt()` (line 50) and `etNowParts()` (line 114). |
| **Symptom** | `currentZerodteSessionAnchor(nowMs: number = Date.now())` threads `nowMs` correctly into `as_of_et` (`etStamp(nowMs)`) and `session_date` (`etSessionDate(nowMs)`) — but computes `session_state`/`session_note` from `todayEt()` and `etNowParts()`, both called with **no argument**, so they silently read the REAL wall clock (`new Date()`) regardless of what `nowMs` the caller passed. Two of the anchor's four fields honor the injected time; the other two always reflect the actual moment the function runs. |
| **Concrete repro** | Verified live in-process (no code changes), Node 20, real wall-clock a Sunday (market closed): `currentZerodteSessionAnchor(Date.UTC(2026,7,21,9,0,0))` — a Friday 05:00 ET, normal weekday pre-market — returned `as_of_et: "2026-08-21 05:00 ET"` and `session_date: "2026-08-21"` (correctly reflecting the injected Friday), but `session_state: "CLOSED"` and a `session_note` saying the market is closed — reflecting the real Sunday, contradicting its own `as_of_et` in the same object. |
| **Why this is notable** | This exact module was built 2026-08-21 specifically to stop Largo from stating a session fact that contradicts the real clock (its own header comment documents the original defect: Largo said "the market opened at 9:30 ET" at 05:00 ET, in the present tense, because nothing told the model what time it actually was). The function's doc comment — "Reads the clock; no IO" — and a parameter defaulting to `Date.now()` both advertise deterministic, injectable behavior. Any caller that ever passes a non-default `nowMs` (a test, a backtest/replay harness, a scheduled-trigger simulation of a different session) gets exactly the `as_of_et`-vs-`session_note` self-contradiction this module exists to prevent. |
| **Root cause detail** | There are two different `todayEt`-named functions in the codebase: `@/lib/et-date`'s `todayEt(now: Date = new Date())` is already correctly parameterized, and callers that need real injectability (e.g. `src/lib/et-market-hours.ts`) already import it directly and pass a `now`. `@/features/nighthawk/lib/session.ts`'s own `todayEt()` is an unrelated, parameterless wrapper (`todayEtYmd()`, itself just an alias back to `et-date.ts`'s parameterized function — called with no argument) — and `etNowParts()` in the same file independently calls `new Date()` with no way to override it at all. `currentZerodteSessionAnchor` imports from the `nighthawk/lib/session` module, so it inherits the parameterless versions. |
| **Currently benign** | The one live call site, `src/lib/zerodte/rejections.ts:164`, calls `currentZerodteSessionAnchor()` with no argument, so `nowMs` defaults to real `Date.now()` and happens to match what `todayEt()`/`etNowParts()` read anyway. No live symptom today. |
| **Why not fixed directly this cycle** | `nighthawk/lib/session.ts`'s `todayEt()` and `etNowParts()` are called with no arguments in **60+ sites** across the most actively-developed files in the entire repo today — `src/lib/zerodte/scan.ts` alone (~20 call sites), plus `live-marks.ts`, `zerodte-service.ts`, `entry-context.ts`, `exit-sync.ts`, admin health checks, Vector, SPX. This is core Night Hawk/0DTE infrastructure in the single hottest lane this session, actively being edited by multiple concurrent agents. Even an additive optional-parameter change (safe in isolation, since every existing call keeps its current default behavior) is exactly the kind of shared-infrastructure edit that belongs to the owning lane's judgment, not an unrelated sweep session — a mistake here has real trading-logic blast radius. |
| **Suggested fix shape** | Add an optional `now: Date` parameter to `nighthawk/lib/session.ts`'s `todayEt()` (passing it through to the already-parameterized `todayEtYmd`/`et-date.ts` function it wraps) and to `etNowParts()` (using the injected `Date` instead of `new Date()` internally, still defaulting to `new Date()`) — purely additive, no existing call site's behavior changes. Then `currentZerodteSessionAnchor` calls both with `new Date(nowMs)` instead of no argument. |
| **Why not caught by tests** | `session-phase.test.ts` explicitly comments "The clock is real here (reads ET now)" and only asserts `session_state`/`session_note` against the real wall-clock. Its one test that passes an explicit `nowMs` (a pre-market Friday) never asserts on `session_state` — only on `as_of_et`/`session_date` formatting — so the broken parameterized path is never exercised; `npx tsx --test src/lib/zerodte/session-phase.test.ts` passes clean today despite the bug. |
| **Status** | OPEN — flagged for the Night Hawk/0DTE lane, no code change made |
