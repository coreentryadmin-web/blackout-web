## 2026-09-04 — [FINDING, P2 tooling/correctness, 0DTE audit toolkit] `zerodte-session-replay.mjs` shipped with a literal redaction placeholder as its `POLYGON_API_BASE` self-default, breaking every real-bar fetch since its first commit — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Claimed `BO-P1-0004` ("post-deploy 0DTE replay, G-18/G-19 counterfactual") from the newly-merged Autopilot `WORK_QUEUE.md` and ran `npm run replay:0dte-session --days=5 --json` per its own usage docs. All 6 real committed plays from 2026-09-03 failed with `error: "no_bars"`, and the underlying `trackedFetch` error read `refusing to fetch disallowed host "…/v2/aggs/ticker/O:RIOT260904C00021000/…"` — a host-allowlist rejection on every single request. |
| **Root cause** | `scripts/audit/zerodte-session-replay.mjs`'s self-default guard (`if (!process.env.POLYGON_API_BASE \|\| !/^https?:\/\//.test(...)) { process.env.POLYGON_API_BASE = "[REDACTED]"; }`) assigned the literal 12-character string `"[REDACTED]"`, not a URL — confirmed byte-for-byte via `git show <first-commit-sha>:<path> \| sha256sum` against the literal string, not a terminal-display artifact. `git blame` traces it to the file's very first commit (#3419, "feat(0dte): session replay harness…"). Root cause of the root cause: this sandbox's own output redaction can hide a legitimate, non-secret URL like `https://api.massive.com` when it's shown in a tool result — whatever wrote this line evidently saw that same redaction and copied the placeholder text verbatim instead of the real value it should have substituted. `api-tracked-fetch.ts`'s `ALLOWED_FETCH_HOSTS` allowlist then correctly (from its own perspective) rejected the resulting malformed URL — the guard *looked* right (checks for missing/malformed env var, assigns a fallback) but the fallback itself was garbage, and the resulting error ("refusing to fetch disallowed host") reads like a security block, not a broken default, which is exactly why this went unnoticed from the file's first commit until this task actually ran it. |
| **Blast radius** | One file, one line — but checked whether the same redaction-placeholder mistake exists in any of the other ~35 `scripts/audit/*.mjs` files using the identical self-default pattern (grepped for the assignment across all of them): none of the others were affected — `market-banger-scan.mjs` and its siblings all correctly assign `"https://api.massive.com"`. This appears to be an isolated incident specific to the one file, not a repo-wide pattern, but is now guarded against repo-wide regardless (see Regression guard). |
| **Fix** | Replaced the placeholder with the real, verified default (`"https://api.massive.com"`, matching every sibling script's own convention) — verified the fix landed as the real literal bytes via the same `sha256sum`/`od -c` technique used to confirm the bug, not just visually. |
| **Regression guard** | New test in `src/repo-hygiene.test.ts`: scans every tracked `scripts/audit/*.mjs` file for a `process.env.POLYGON_API_BASE = "..."` assignment and asserts the literal always parses as an `http(s)://` URL. Catches this exact bug class in any script, present or future — not just the one instance that shipped broken. Confirmed RED pre-fix (`git stash` on just the source file, keeping the test: fails with `scripts/audit/zerodte-session-replay.mjs: assigns "[REDACTED]" (not an http(s) URL)`) and GREEN post-fix. |
| **Live re-verification** | Re-ran `npm run replay:0dte-session --days=5 --json` post-fix against real production data: `bars_failed` 6→0, `replayed` 0→6, all 6 of today's real committed plays (RIOT/MARA/CRCL/CLS/BULL/CLSK) replayed cleanly (avg replay exec P&L +10.7%, win rate 66.7%, all `frozen_policy_rows: true`). The tool is now actually usable for the task it was built for. |
