## 2026-09-03 — [FINDING, P1 performance/infra] `heatmap-warm` cron had no cross-replica overlap guard — measured runtime (p50 46.5s, max 209.2s) routinely exceeds its own 20s in-app heal threshold, causing near-continuous overlapping runs — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Continuing the standing performance-audit mandate's cron-overlap-guard sweep (the pattern already fixed for `vector-pick-sweep`, `desk-warm`+`zerodte-warm`, `vector-dark-pool-warm` — see 2026-09-02 entries in this file). Per the mandate's own discipline ("check EVERY cron's own schedule against its own measured `elapsed=` runtime... do not add a lock to a cron that doesn't need one"), swept all 49 registered crons (`cron-registry.ts`) for missing guards, then measured real runtime for every unguarded candidate via CloudWatch before concluding anything needed a fix — most had comfortable margin and were correctly left untouched (`vector-bead-record`, `vector-walls-warm`, `meridian-warm`, `uw-cache-refresh`, `flow-ingest`, all milliseconds-to-low-seconds against multi-minute schedules). `heatmap-warm` was the one genuine outlier. |
| **Root cause** | `src/app/api/cron/heatmap-warm/route.ts` had NO `sharedCacheSetNx` guard despite being one of the RTH-leader-watched warmers: `rth-warm-leader-logic.ts`'s `RTH_WRITER_HEAL_AFTER_MIN["heatmap-warm"] = 20 / 60` (20 seconds) — the tightest heal threshold of any watched cron, chosen so "Thermal SPY/QQQ don't sit on minute-old asof while SPX Slayer force-refreshes organically." But the route runs fully synchronously (sequential Polygon chain fetches for up to ~100 tickers, one at a time in priority/core/rest tranches, plus per-ticker delta-broadcast work) — measured live 2026-09-03 via CloudWatch (`/ecs/blackout-production`, 48h, n=1000 runs dispatched through `rth-warm-leader.ts`'s `dispatchCronWarm`, which invokes this exact `GET` handler in-process, so the timing is genuine production runtime for this handler): **p50=46.5s, p90=81.1s, p99=181.1s, max=209.2s** — 2–3 orders of magnitude past the 20s heal threshold on nearly every run. So the leader (whose own in-process `inFlight` Set only prevents the LEADER from double-dispatching itself) treats an already-running warm pass as perpetually overdue and re-dispatches on almost every cycle, landing a second full sequential warm pass on top of one already in flight — both instances then sweeping the same shared ≤100-ticker universe concurrently through the same Polygon rate limiters and SSE delta broadcasts real member requests also depend on. The independent EventBridge 1/min trigger compounds this further, landing its own call into the same unguarded, already-running handler. |
| **Fix** | Added the same `sharedCacheSetNx` cross-replica lock pattern already proven for `vector-pick-sweep`/`swing-discovery`/`banger-discovery`/`thermal-discord`. Since this route runs synchronously (unlike `vector-pick-sweep`'s background-dispatch shape), the lock is acquired right after the existing warm-window gate and the whole warm sequence was extracted into a `runHeatmapWarm` helper, called inside a `try { ... } finally { release }` so the lock is freed on both the success and error paths. Fails OPEN on a Redis error (a missed guard is safer than a stuck cron, matching every sibling implementation). TTL = 240s, chosen as a safety-net ceiling comfortably above the measured max (209.2s) in case a release is ever missed (crash mid-warm). |
| **Blast radius** | Single file. No change to the warm logic itself, tickers warmed, or delta-broadcast behavior — a lost race now returns an idempotent `{ skipped: true, reason: "previous warm still in flight" }` instead of running a redundant concurrent pass, exactly mirroring the sibling fixes' behavior. |
| **Regression guard** | `route.test.ts` (new): 5 source-text tests mirroring `vector-pick-sweep/route.test.ts`'s exact assertions — lock acquired before the warm pass runs; a lost race returns the skip response before reaching `runHeatmapWarm`; the guard fails open on a Redis error; the lock releases in a `finally` block; the TTL constant is 240. Confirmed RED pre-fix (`git stash` the source file, keep the test: 5/5 fail) and GREEN post-fix (5/5). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: 11908 passed / 0 failed / 2 skipped. |
