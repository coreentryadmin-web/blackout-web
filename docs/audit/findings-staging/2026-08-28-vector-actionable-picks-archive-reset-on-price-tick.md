## 2026-08-28 — [FINDING, P1 Vector] Backfill/closed-picks archive reset on every price tick, defeating the PR that added it — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | #3023 ("backfill contract picks on Don't buy + closed plays strip") shipped `useVectorActionablePicks` to fix a real member complaint — when a ranked pick goes `dont_buy`, exclude it from the next rank and show it as "Closed" so a replacement can backfill. Reviewed independently before the bug could be fixed; the PR merged 40 seconds before the review comment posted. |
| **Root cause** | The archive-reset `useEffect` in `use-vector-actionable-picks.ts` depended on the SAME `contextKey` shape `useVectorContractPicks` uses to trigger its debounced re-fetch — `` `${emit.spot}|${emit.callWall}|${emit.putWall}|${play?.conviction}|${play?.headline}|${sessionFlows.length}|${bias}` `` — which embeds the raw live spot price. `emit.spot` changes on essentially every price tick during RTH, so the reset effect fired on nearly every tick, clearing `excludeOccs` and `archivedClosed` back to `[]` before the exclusion could survive even one fetch cycle. Sequence: pick invalidates → OCC added to `excludeOccs` → spot ticks (~1-2s later) → reset effect fires → `excludeOccs` back to `[]` → the very next debounced fetch (500ms, unguarded by the reset) queries WITHOUT the exclusion → the invalidated contract can come right back into the pool and the Closed strip empties. |
| **Why it was invisible** | The new unit tests (`vector-pick-partition.test.ts`) correctly test the pure `partitionVectorPicksByLiveStatus`/`mergeArchivedClosedPicks` functions in isolation — the bug lives entirely in the hook's `useEffect` dependency wiring, one layer up, which nothing exercised. |
| **Blast radius** | Vector desk + Compare play strip only (`VectorContractPicksCard`, `VectorPageShell`, `VectorComparePlayStrip`) — the exact feature #3023 added. No other consumer. |
| **Fix** | Introduced a separate `setupKey` for the reset effect — `` `${ticker}|${bias}|${play?.headline ?? ""}` `` — deliberately excluding spot/walls/conviction/flow-count. The fetch effect in `useVectorContractPicks` keeps its own price-sensitive `contextKey` unchanged (that one SHOULD refetch on price movement); only the archive-reset now keys off a genuine new setup. |
| **Evidence** | Regression test `use-vector-actionable-picks.test.ts` asserts the reset effect's key excludes `emit.spot`/`emit.callWall`/`emit.putWall`/`conviction` and depends on `[setupKey]`, not the raw contextKey. Full vector suite (63 tests across `use-vector-actionable-picks`, `vector-pick-partition`, `vector-play-candidates`, `vector-play-engine`, `vector-replay-play-engine-gate`, `VectorContractPicksCard`) green on Node 20. `tsc --noEmit` clean. |
| **Status** | FIXED — `src/features/vector/lib/use-vector-actionable-picks.ts`. |
