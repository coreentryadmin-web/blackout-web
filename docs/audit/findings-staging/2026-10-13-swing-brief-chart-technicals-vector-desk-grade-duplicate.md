## 2026-10-13 — [FINDING, P3 swing/correctness, data-honesty] Swing play-brief rendered the same stale Vector desk grade twice under two different section titles — FIXED

> **kind:** `FINDING`

| Field | Detail |
| --- | --- |
| **What was broken** | `GET /api/market/swing/play-brief`'s composed envelope could render the identical fact — "Vector desk grade: **C** (from prior snapshot)" — under BOTH the "Chart technicals" section AND the "Vector desk" section whenever the Vector snapshot was stale and both sections rendered standalone (true for every CLOSED brief, and any OPEN/WATCH brief not desk-detail-folded into "Trade manager read"). |
| **Root cause** | `chartTechnicalsSection` and `vectorDeskSection` (both `src/lib/swing/play-brief-intel.ts`) independently grew a near-identical "honest degrade" fallback for a stale Vector snapshot on different dates (chartTechnicalsSection's dates to the section's original 2026-09-12 bucket-gating fix; vectorDeskSection's own stale-grade handling was locked in by a test dated 2026-09-20) — each pushing "Last snapshot (~Xs old) — ... may lag spot" plus "Vector desk grade: X (from prior snapshot)" under its own title, with neither function referencing the other. `grade` is the Vector play engine's own field; its one conceptually correct home is `vectorDeskSection` ("Vector desk" — the section literally named for that engine's read), not "Chart technicals" (EMA/VWAP/RSI/MACD/structure). Two existing unit tests (`chartTechnicalsSection: stale Vector snapshot neutralizes bias...` and the Infinity-dataAgeMs sibling) explicitly asserted the duplicate grade line's presence, which is how the duplication survived undetected — the tests encoded the bug rather than catching it. |
| **Evidence** | Live production repro, fetched via `scripts/audit/lib/prod-clerk-session.mjs`'s `mintClerkPremiumSession`: `GET /api/market/swing/play-brief?playId=SWING:ASTS&ticker=ASTS&positionId=53&status=closed` (CLOSED position, Vector snapshot ~1426s stale) returned sections `["Verdict","Outcome","Trade manager read","Why this setup","Chart technicals","Levels on chart","GEX posture","Vector desk","Flow & positioning","Catalysts & news","Meridian catalysts","Since it closed","Lessons"]` with both "Chart technicals" (`"Last snapshot (~1426s old) — chart read may lag spot.\nVector desk grade: **C** (from prior snapshot)"`) and "Vector desk" (`"**Last snapshot** (~1426s old) — Vector desk read may lag spot.\n\nVector desk grade: **C** (from prior snapshot)"`) carrying the identical grade fact. |
| **Fix** | `chartTechnicalsSection`'s stale branch now returns `null` instead of a stub — when Vector is stale there is no fresh chart-technicals content to show, and the one remaining fact (grade) already has its canonical home in `vectorDeskSection`, while the staleness itself is already disclosed via `dataFreshnessSection`. `vectorDeskSection` is unchanged and remains the sole renderer of the stale grade. Updated the two existing tests that had locked in the duplicate line (now assert `null`) and added a dedicated cross-section regression test that calls both functions against the same stale fixture and asserts the grade fact appears in `vectorDeskSection`'s output only. |
| **Blast radius** | Grepped every non-test reference to `chartTechnicalsSection` repo-wide — the only real call site (`buildIntelSections`, same file) already handles a `null` section via the existing `if (technicals) out.push(technicals)` guard, so no caller required a change. The three other hits (`play-brief-narrative-coaching.ts`, `play-brief-narrative.ts`, `play-brief-ladder.ts`) are comments referencing the function conceptually, not calls. |
| **Fix rationale** | Considered keeping the grade line in `chartTechnicalsSection` and instead removing it from `vectorDeskSection` — rejected because "Vector desk" is the section whose entire remaining purpose (headline/conviction/entry-zone/targets/invalidation when fresh) is the play engine's own call, so its stale-branch grade mention is the semantically correct placement; "Chart technicals" has no other reason to exist once there are no fresh technicals, so omitting it entirely (Largo C3 absence discipline) is more honest than trimming it to a bare, now-pointless staleness notice that only restates what `dataFreshnessSection` already says. |
| **Status** | FIXED — `src/lib/swing/play-brief-intel.ts`, `src/lib/swing/play-brief-intel.test.ts`. RED confirmed against unmodified source (3 assertions failed with the predicted duplicate-line output) before the fix; full suite 15930/15930 pass post-fix; `tsc --noEmit` clean. |
