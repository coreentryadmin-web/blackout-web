## 2026-09-03 — [FINDING, P2 correctness, GEX matrix] `gex-matrix-deltas` SSE feed served raw unrounded GEX floats — the one route a 2026-08-06 sweep couldn't verify — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Standing sweep re-checking CLAUDE.md's "systemic unrounded floats" note (`7499.360000000001` served verbatim in ~16 endpoints, fixed via `roundFloats` at ~45 call sites). A 2026-08-06 sweep of 32 sibling `/api/market` routes found 14/15 clean but one — `gex-matrix-deltas` — timed out and was explicitly logged "unverified, not assumed fine." Investigated that specific gap. |
| **Root cause / sites** | (1) `src/app/api/market/gex-matrix-deltas/route.ts` — the SSE endpoint's initial `snapshot` event sent `fetchGexHeatmap(ticker)`'s return value directly, with no rounding at all — unlike its sibling REST route `gex-heatmap/route.ts`, which already wraps the same provider output in `roundFloats` + a two-level strike-total reconciliation (`reconcileCellStrikeTotals`/`reconcileStrikeTotal`) before serving it. (2) `src/lib/gex-matrix-delta.ts`'s `calculateMatrixDelta`/`calculateMatrixDeltaFull` — `gex_call`/`gex_put` are summed from the same raw, unrounded GEX cells (`polygon-options-gex.ts`'s dollar-gamma arithmetic: `signedGamma = sign * gamma * oi * sharesPerContract * spot * spot * 0.01`) and emitted straight into the wire `StrikeUpdate` with zero rounding, on EVERY subsequent delta update (not just the initial snapshot). |
| **Why this matters** | A member connected to the live SSE matrix-delta feed saw raw IEEE-754 float noise on first paint AND on every subsequent incremental update, even though a plain REST fetch of `/api/market/gex-heatmap` for the identical ticker at the identical moment was already clean — the exact "same data, two different-looking numbers depending on which endpoint served it" inconsistency `roundFloats`'s own design doc calls out as the reason to round once at the shared boundary. `calculateMatrixDelta` is also consumed by `src/lib/largo/gex-matrix-changes.ts` (a Largo tool-facing reader of the same delta stream), so the unrounded values reached a second consumer beyond the SSE route. |
| **Fix** | `gex-matrix-delta.ts`: wrapped all 4 return points of `calculateMatrixDelta`/`calculateMatrixDeltaFull` in `roundFloats(...)` — rounds `gex_call`/`gex_put`/`spot` to 2dp (money-math scale, matching the existing default), leaves the internal `gexChange >= CHANGE_THRESHOLD` significance comparison on the RAW sums untouched (rounding only at the output boundary, never perturbing which strikes qualify as "changed"). `gex-matrix-deltas/route.ts`: the SSE snapshot now goes through the SAME `roundFloats` + `reconcileStrikeTotal(reconcileCellStrikeTotals(...))` treatment `gex-heatmap/route.ts` already applies to `gex`/`vex`/`dex`/`charm` — deliberately scoped to JUST the numeric-precision fix, not replicating that route's off-hours shift-gating/overlay/cross-validation logic, which is presentation-layer scope this delta feed's snapshot doesn't carry. |
| **Blast radius** | Two files: the shared delta-calculation module (both its exported functions, and both its consumers — the SSE route and Largo's `gex-matrix-changes.ts` — inherit the fix automatically) and the SSE route's own snapshot construction. No schedule, threshold, or unrelated logic changed. |
| **Regression guard** | `gex-matrix-delta.test.ts` — new file (no test previously existed for this module at all): 7 tests covering existing behavior (no-previous returns null, over/under-threshold inclusion, spot-only-move branch) plus 4 new rounding assertions using the exact `7499.360000000001`-shaped float noise CLAUDE.md's own example cites, confirming `gex_call`/`gex_put`/`spot` come back clean in both `calculateMatrixDelta` and `calculateMatrixDeltaFull`. `route.test.ts` — new source-text regression guard (SSE/auth routes aren't practical to unit-test directly, matching this repo's established convention for that case) confirming the snapshot path imports and applies the same rounding treatment. Confirmed RED pre-fix (`git stash` each source file, keep its tests: 4/7 and 2/3 respectively fail — exactly the new assertions) and GREEN post-fix (10/10 across both files). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: 11985 passed / 5 failed / 2 skipped — the 5 failures are the documented pre-existing sandbox-only DB-connectivity artifact (same signatures as every other run this session, unrelated files). |
