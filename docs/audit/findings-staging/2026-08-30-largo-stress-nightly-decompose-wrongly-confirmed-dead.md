## Largo stress nightly broken since this morning: `decompose.ts` was wrongly "confirmed dead" and deleted, but a real non-test consumer used it — FIXED

> **kind:** `FINDING`

Found while sweeping GitHub Actions for failing scheduled workflows per the coordinator cycle's
"absence is a finding" discipline — `Largo stress nightly` (run 33310677170, 2026-08-30 12:08 UTC)
was RED, and every run since PR #3203 merged (~04:56 PT / 11:56 UTC same day) has been RED.

| Field | Detail |
|---|---|
| **Symptom** | `Largo stress nightly` (`.github/workflows/*` running `scripts/largo-stress-run.mjs`) fails with `Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../src/lib/bie/decompose.ts' imported from .../scripts/largo-stress-run.mjs`. The workflow's own follow-up "file an ops issue" step also fails (`Resource not accessible by integration`), so the failure produced no GitHub issue and no direct alert — it was sitting unrouted until this sweep. |
| **Root cause** | PR #3203 (this morning, same day) deleted `src/lib/bie/decompose.ts`/`decompose.test.ts` as "confirmed dead," reasoning from `docs/audit/findings-staging/2026-08-30-bie-orphan-files-more-entangled-than-noted.md`'s claim that `router.ts`, `composers.ts`, `decompose.ts` and `dynamic-format.ts` "now have zero non-test consumers outside `src/lib/bie/` itself." That claim was false for `decompose.ts` specifically: `scripts/largo-stress-run.mjs` (line 30) imports `isCompoundQuestion` from it directly, and it is not a vestigial import — a large fraction of the stress bank (`largo-stress-bank.mjs` through `-bank-4.mjs`) asserts `intent: "compound_lookup"` as the EXPECTED router intent for real bank entries, and `classifyBieIntent` (`router.ts`) itself never produces `"compound_lookup"` from anywhere else — the deleted `isCompoundQuestion` shortcut in the stress script's own `routeQuestion()` was the only producer. This is bug class (f) via file deletion: a "confirmed dead" sweep checked one file in a batch (`composers.ts`, empirically) and extended the conclusion to its siblings without independently checking each one's consumers — `decompose.ts` had a real, load-bearing consumer the sweep never grepped for (`scripts/`, outside `src/`). |
| **Why not caught earlier** | #3203's own empirical check (temporarily moving `composers.ts` aside, confirming `largo-terminal.test.ts` fails closed) was done for `composers.ts` only, then extended by inference to `decompose.ts`/`dynamic-format.ts` as "the same batch." `npm test` doesn't run `scripts/largo-stress-run.mjs` (it's a standalone script invoked only by its own scheduled workflow), so the deletion was invisible to the merging PR's own gates — CI (`verify`) stayed green, and the breakage only ever showed up on the separate nightly cron, whose failure-reporting step is itself broken (see Symptom). |
| **Fix** | Restored `src/lib/bie/decompose.ts` and `decompose.test.ts` verbatim from the commit immediately before the deletion (`5fc3ecd7d~1`) — pure, well-tested (10 tests), zero other dependents to break. `composers.ts`/`dynamic-format.ts` (and their test files) stay deleted — #3203's empirical check on those was real and specific, and neither has any surviving consumer (checked again here: `grep -rln` across `src/` and `scripts/` for both). Verified the actual broken script now runs clean end-to-end (`LARGO_STRESS_BANK=1 LARGO_STRESS_LIMIT=5 node --import tsx scripts/largo-stress-run.mjs` — 0 router mismatches). |
| **Blast radius** | `scripts/largo-stress-run.mjs` (the only real, non-test consumer) and its own nightly CI workflow. Nothing in `src/` was affected — `decompose.ts` still has no importer inside `src/lib/bie/` itself, which is why its production-code removal claim from #3203 remains correct for the app proper; only the deletion's scope (removing a file scripts/ still needed) was wrong. |
| **Regression guard** | `decompose.test.ts`'s original 10 tests restored (they test the pure splitter/detector logic directly, no mocking needed). Additionally ran the actual `largo-stress-run.mjs` end-to-end as a smoke test (not a unit test, since it's a standalone script outside `npm test`'s scope) to confirm the specific failure mode is gone. |
| **Gates** | `npx tsc --noEmit` clean · `decompose.test.ts` 10/10 pass · `largo-stress-run.mjs` smoke run clean (0 router mismatches, 5/5 questions) · full `npm test` 11466 pass / 0 fail / 2 skipped (Node 20.20.2). |
| **Status** | FIXED |
