## 2026-10-14 — [Ask Largo / Swing] Dealer VEX/DEX/CHARM were computed and already in every swing brief's hands, but never surfaced — FIXED

> **kind:** `FINDING`

### Root cause

`src/lib/providers/gex-positioning.ts`'s `getGexPositioning()` computes `net_vex`/`vanna_regime_read`
(non-nullable) and the nullable `net_dex`/`dex_regime_read`, `net_charm`/`charm_regime_read`
alongside `net_gex`/`gamma_posture` — the IDENTICAL function `src/lib/bie/thermal-read.ts`'s
`composeThermalRead`/`formatPositioningBlock` calls to build Thermal's own dedicated desk's
"Net GEX / VEX / DEX / CHARM" line. `play-brief-context.ts` wires `ctx.ecosystem.gex_positioning`
into every `SwingPlayBriefContext` with no extra fetch — but `play-brief-intel.ts`'s
`gexPostureSection`, the one place that narrates this object for the swing brief, only ever read
`gamma_posture`/`net_gex`. Repo-wide grep for `\bDEX\b|\bCHARM\b` across `src/lib/swing` returned
zero matches before this fix.

Live confirmation (2026-10-14): `GET /api/market/swing/play-brief?playId=SWING:RKLB` showed the
"Trade manager read" section sourcing call wall/put wall/GEX king from this exact
`gex_positioning` object (`freshness: live`), proving the object was live and fully populated on
the read, yet nothing in the brief ever surfaced its DEX/CHARM/VEX-regime fields. CHARM is
specifically relevant to a multi-day swing hold (the RKLB repro carried a 9 DTE contract into an
OpEx week) since charm-driven dealer delta decay intensifies pinning/acceleration behavior as
expiry approaches — a 0DTE-only reader never needs this, a swing holder does.

### Fix rationale

Extended `gexPostureSection` (`play-brief-intel.ts`) to render `net_vex`/`vanna_regime_read`,
`net_dex`/`dex_regime_read`, and `net_charm`/`charm_regime_read` the same way it already renders
`net_gex`/`gamma_posture`: same false-zero-safe `formatFixedNonZero` formatter, same `!stale`
staleness gate, same bucket-closed disclosure prefix, same C3 clean-omission when a field is null
— zero new fetch, since `ctx.ecosystem.gex_positioning` is already loaded for every brief.

### Blast radius

Additive only — three new conditionally-rendered lines in one section. No change to any other
section, to the envelope schema, or to any other product surface (Thermal's own
`formatPositioningBlock` is untouched).

### Alternative approaches not taken

1. **A single combined "dealer Greeks" line** (all four Greeks in one sentence) — rejected in favor
   of matching the existing file's established one-line-per-metric style (`gamma_posture`,
   `net_gex`, nearest wall, underlying session are already separate lines), for consistency and
   easier future per-field changes.
