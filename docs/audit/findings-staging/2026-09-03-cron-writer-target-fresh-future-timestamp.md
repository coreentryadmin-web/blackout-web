## 2026-09-03 — [FINDING, P3 infra/observability] `probeWriterTargetFresh`'s freshness checks had no lower bound on age — a future-dated timestamp could flip a genuinely dead cron job to "healthy" on the admin dashboard — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Continuing this session's sweep for the future-print-timestamp bug shape (10 sites already fixed across Helix/Dark Pool/Largo/zerodte/SPX Slayer via `signalWindowAgeMs`) into an area not yet checked — cron/writer-freshness code. `src/lib/cron-writer-target-fresh.ts` computes several `age = now - eventTime` values and checks `age <= threshold`, the exact shape that already produced 4 rounds of fixes elsewhere this session. |
| **Root cause** | Four age computations — `probePgFlowAlertsFresh`'s `flow_alerts` row age, `ageMinFromIso` (shared by the `heatmap-warm`, `desk-warm`, `zerodte-warm`, `vector-walls-warm` probes), and the `vector-bead-record` wall-history tail age — all did `Date.now() - eventMs` with no lower bound, then checked `age <= maxAge`. A future-dated event timestamp (clock skew between DB/Redis/app hosts, or a corrupted write) produces a NEGATIVE age, which trivially satisfies every one of those `<= maxAge` checks, so the probe reports `fresh: true`. |
| **Why this one matters even though it's not a trading-correctness bug** | `probeWriterTargetFresh`'s result is consumed by `admin-cron-health.ts`'s `TARGET_FRESH_OVERRIDE_KEYS` path (lines ~450-473): a cron job ALREADY flagged `stale`/`market_hours_stale` gets its status forcibly overwritten to `"healthy"` with `"cron handshake lag is benign"` whenever the probe returns `fresh: true`. So a single corrupted future-dated row in `flow_alerts`, a cached `asof`/`polled_at` field, or a wall-history sample would actively suppress a real dead-writer alert on the operational dashboard the team uses to catch outages — the opposite of "benign lag," a masked incident. |
| **Fix** | Routed all four age computations through the same `signalWindowAgeMs` helper (`@/features/helix/lib/helix-signal-detection`, 60s future tolerance for ordinary clock skew) already used to fix this exact shape elsewhere this session, rather than inventing a second implementation. `ageMinFromIso` (previously module-private) is now exported so its future-dated-rejection behavior is directly unit-testable. Every caller already treated a `null` age as "not fresh" (`ageMin != null && ageMin <= N`), so threading the guard through required no changes to any caller's own logic — a future-dated timestamp now correctly falls through to `fresh: false` instead of overriding a real staleness alert. |
| **Blast radius** | Single file, `src/lib/cron-writer-target-fresh.ts`. All 5 `TARGET_FRESH_OVERRIDE_KEYS` probes (`flow-ingest`, `heatmap-warm`, `desk-warm`, `zerodte-warm`, `vector-walls-warm`, `vector-bead-record`) share the fix since 4 of them route through `ageMinFromIso` and the other 2 (`flow-ingest`'s own PG probe, `vector-bead-record`) got the same `signalWindowAgeMs` call inline. `uw-cache-refresh` was untouched — it checks Redis TTL remaining, not an age-since-timestamp, so it isn't in this bug's shape at all. |
| **Regression guard** | `cron-writer-target-fresh.test.ts`: new tests on the newly-exported `ageMinFromIso` — an ordinary past timestamp reads its real age; a future-dated timestamp beyond the 60s tolerance returns `null` (previously silently produced a negative age that would pass a freshness check); a timestamp only a few seconds ahead stays within tolerance (ordinary clock skew isn't over-rejected). A source-text assertion confirms `probePgFlowAlertsFresh` and the `vector-bead-record` probe also route through `signalWindowAgeMs`, since those two aren't reachable through `ageMinFromIso` and would otherwise be untested. Confirmed RED pre-fix (`git stash` the source file, keep the tests: 4/5 fail) and GREEN post-fix (5/5). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: 11858 passed / 0 failed / 2 skipped. |
