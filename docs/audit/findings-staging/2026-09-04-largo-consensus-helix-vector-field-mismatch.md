## 2026-09-04 — [BUG, P2 dead-code] Largo's Helix/Vector directional-read extractors read field names that don't exist in the real payloads

> **kind:** FINDING

| Field | Value |
|-------|-------|
| **Status** | FIXED |
| **Found by** | Parallel live-production audit workflow, 2026-09-04 (Largo product-contract compliance area), independently confirmed by 2 adversarial verifiers who each traced the real payload shapes and the live request path. |
| **Evidence** | `extractHelixRead`/`extractVectorRead` (`src/lib/largo/consensus-read-extract.ts`) read field names (`call_volume`, `calls_premium`, `call_prints`, top-level `structure`/`bias`, numeric `magnet`) that exist on NEITHER real tool payload: `get_flow_tape`'s `FlowTapeSummary` nests skew under `pull_skew`, not `call_volume`; `get_helix_derived` has no call/put split at all; `VectorSnapshot`/`VectorFullState` (vector-play-engine.ts) has no top-level `structure` field, `bias` exists only nested at `play.bias`, and `magnet` is a `GammaMagnet` OBJECT (`{strike, distancePct, pull, posture, callout}`), not a number — so `magnet > spotPrice*1.005` coerced to `NaN` and was always false even when magnet was present. Every real invocation silently fell through to the hardcoded defaults (`HELIX: {strength:0, "No flow detected"}`, `VECTOR: {strength:5, direction:"neutral", "Structure neutral"}`) regardless of real flow/posture/magnet — a textbook C3 violation (absence presented as a measured reading). Confirmed dead code: traced the live Largo request path (`src/app/api/market/largo/query/route.ts` → `largo-terminal.ts` → `turn-pipeline.ts`) and every other Largo route — none reference `consensus-read-extract.ts`/`adaptive-response-orchestrator.ts`/`response-builder.ts`/`desk-read-decision.ts`; only test files and each other import this cluster. |
| **Root cause** | `extractHelixRead`/`extractVectorRead` were written against an imagined/legacy payload shape that never matched the real tool outputs the rest of the codebase serves. The module's own unit tests reinforced the blind spot by supplying synthetic fixtures shaped to match the extractor rather than the real payload — the identical failure mode already documented and fixed for `extractThermalRead` in the same file (PR #2422), but never applied to the Helix/Vector cases beside it. A naive "just read the real field" fix would have introduced a SECOND, worse violation for Helix: the closest-sounding real field, `pull_skew.call_pct` (a raw call/put PREMIUM SHARE), is explicitly documented across this codebase as NOT a direction — a bought call is bullish but a SOLD call is bearish, so a name can be 100% call premium and measurably bearish (measured live 2026-08-23: CG was exactly that). The authoritative aggressor-aware field, `session.direction`, exists only on `get_helix_tape_analytics`'s payload — a DIFFERENT tool than either one `extractConsensusFromTools` was feeding through this extractor. Similarly for Vector: `regime.posture` (dealer gamma posture) is the SAME non-directional concept `extractThermalRead` was already fixed to stop reading as direction — folding it onto a bullish/bearish axis would have reintroduced that identical anti-pattern in the very file that already documents why it's wrong. |
| **Fix** | Rewired `extractHelixRead` to read `get_helix_tape_analytics`'s real `session.direction`/`session.call_pct`/`session.direction_readable_pct`/`session.direction_minority_evidence` fields, mirroring `product-adapters.ts`'s `helixContribution` — the already-correct, already-battle-tested reference implementation for this exact rule (prefer `session.direction`, fall back to `directionFromCallPct` — imported from `product-adapters.ts` rather than reimplemented — ONLY when `direction` is entirely absent, never when it reads "undetermined"). `extractConsensusFromTools` now calls `extractHelixRead(toolResults.get_helix_tape_analytics)` instead of feeding it `get_flow_tape`/`get_helix_derived`, neither of which carries a comparable directional field. Rewired `extractVectorRead` to read `get_vector_full_state`'s real `play.bias` (`VectorPlay.bias`, an actual trade thesis) for direction and `magnet.pull` (`GammaMagnet.pull`, "up"\|"down"\|"at") as strength-only evidence (never a direction override, matching Thermal's "wall proximity is evidence, not a vote" posture) — `regime.posture` is deliberately NOT read as direction. `extractConsensusFromTools` now calls `extractVectorRead(toolResults.get_vector_full_state)` only, dropping `get_vector_pulse` (a structurally different differential-signals-log payload with no `play`/`magnet`/`spot` fields to read). Both extractors also now return `null` (no vote cast) rather than a fabricated neutral default when the payload carries an honest `available: false` envelope — missing evidence degrades, it does not get upgraded into a fake reading. |
| **Blast radius** | 1 file changed (`consensus-read-extract.ts`) + its test file. Confirmed dead code per both adversarial reviewers — this fix has zero effect on any live member-facing surface today; it closes the gap before a future wiring change (connecting `adaptive-response-orchestrator.ts` to the live Largo turn pipeline) would otherwise ship the violation live. `extractThermalRead`, `extractSpxRead`, `extractNightHawkRead`, and `extractMeridianRead` were not touched — out of scope for this finding (Thermal was already fixed in #2422; the other three were not flagged by the audit). Did not verify `get_helix_tape_analytics`'s exact live response shape against a running server (this module is unreachable from the live route, so there was nothing to validate end-to-end against) — the fix is built directly against `helixTapeAnalyticsForLargo`'s source (`product-reads.ts`) and `sessionFlowSkew`/`directionFields` (`helix-tape-analytics.ts`), the same functions `product-adapters.ts`'s already-correct, already-live `helixContribution` reads. |
| **Tests** | 2 new tests in `consensus-read-extract.test.ts` mirroring the existing Thermal regression-pin style: HELIX reads `session.direction` (not `call_volume`), proves `session.direction` wins over `call_pct` even when they disagree (the exact live CG incident), treats "undetermined" as a real refusal, degrades honestly on the old invented fields, excludes a genuine `available:false` failure from voting, and confirms `get_flow_tape`/`get_helix_derived` no longer contribute any vote at all. VECTOR reads `play.bias`/`magnet.pull` (not top-level `structure`/`bias`/numeric `magnet`), proves `regime.posture` alone never casts a directional vote, degrades honestly on the old invented fields, excludes an `available:false` failure, and confirms `get_vector_pulse` no longer contributes any vote. 3 pre-existing tests updated to use the corrected tool-name/field shapes (`get_flow_tape` → `get_helix_tape_analytics`, top-level `bias` → `play.bias`) since the old fixtures fed tools this extractor no longer reads. RED→GREEN proven via `git stash`: 5/6 failed pre-fix, 6/6 pass post-fix. `npx tsc --noEmit` clean (Node 20.20.2, confirms no import cycle from reusing `product-adapters.ts::directionFromCallPct`). Full `npm test` (Node 20): 12096/12104 pass — same 6 pre-existing sandbox-only baseline failures (`resolveGithubRepo`, board-ledger/commit-latch/tier-passthrough family), zero new failures. |
