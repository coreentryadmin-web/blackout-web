| **What this resolves** | Found during a dedicated Largo C3 (absence) audit of the Night Hawk Swings "Ask Largo" play-brief (`src/lib/swing/play-brief*.ts`), the one contract point that hadn't yet had its own top-to-bottom sweep this session (six other points had — C1/C2/C4/C5/C7/C8, all shipped this session). PR #5042 (Largo C7, 2026-09-15) added an "ancient" guard to `play-brief.ts`'s `evidenceFromContext()` after live-repro'ing FINRA short-interest reads up to ~9 years stale (MSTX/2017, CRCG/2025-12-31 ~258d, ECO/2025-12-31 ~258d) all rendering the identical `STALE` freshness tag as a genuinely few-days-old read. That fix only ever reached the one call site it was written in. |
| **Root cause** | `EcosystemArsenalFundamentals` (`src/lib/bie/ecosystem-context.ts`) carries a single `days_to_cover`/`short_volume_ratio`/`as_of` object read from exactly three production call sites. Only `play-brief.ts`'s `evidenceFromContext()` computed `fundamentalsAncient` (the 60-day ceiling check) before rendering. The other two — `catalystsSection()` (`play-brief-intel.ts:642-648`, a member-facing bullet under "Catalysts & news") and `shortInterestCoaching()` (`play-brief-narrative-coaching.ts:808-820`, a headline "Trade manager read" coaching line) — read `arsenal.fundamentals.days_to_cover`/`short_volume_ratio` unconditionally whenever non-null, with zero freshness or age check. So the same brief could show a value many months to years old, presented with the same unqualified confidence as a current one, in the two places a member would actually read it, while only the third (buried in `envelope.evidence`) correctly withheld it. Same shape as prior findings this repo documents repeatedly (a fix applied to one call site, an unpatched sibling reading the identical field left behind). |
| **Evidence** | Grepped every `days_to_cover`/`short_volume_ratio` production read (`play-brief.ts`, `play-brief-intel.ts`, `play-brief-narrative-coaching.ts`) — confirmed only `play-brief.ts` had `ancient`/staleness logic before this fix (`grep -n "ANCIENT\|ancient"` across the other two files returned nothing). Traced `EcosystemArsenalFundamentals.as_of` (`ecosystem-context.ts:213`) as the shared field all three sites read. Regression tests added at both broken call sites, git-stash proven RED against pre-fix source (see Regression guard). |
| **Fix** | Moved the guard to a shared home: `FUNDAMENTALS_ANCIENT_CEILING_MS`, `fundamentalsObservedMs()`, and a new `fundamentalsAncient(asOf, readMs)` helper now live in `play-brief-absence.ts` (already imported by all three files, so no circular-import risk — `play-brief.ts` imports `buildIntelSections` from `play-brief-intel.ts`, so the reverse direction was never available). `play-brief.ts`'s `evidenceFromContext()` now calls the shared `fundamentalsAncient()` instead of its own local copy (behavior unchanged there). `catalystsSection()` and `shortInterestCoaching()` each gained the same `!fundamentalsAncient(fund.as_of, Date.now())` guard before rendering any DTC/short-vol-ratio content. |
| **Blast radius** | Three files: `play-brief-absence.ts` (new shared exports), `play-brief-intel.ts` (`catalystsSection`), `play-brief-narrative-coaching.ts` (`shortInterestCoaching`). `play-brief.ts` itself only changed its import source, not its behavior. No `unavailableSources`/chip entry added — matching the established precedent at the one already-correct call site (silent omission, not a chip, since this is "the data exists but isn't trustworthy enough to present as current," not a fetch failure). No gate/scoring logic touched. |
| **Fix rationale** | Centralizing in `play-brief-absence.ts` (rather than duplicating the guard a third time, or exporting from `play-brief.ts` which isn't importable from `play-brief-intel.ts` without a cycle) matches how this codebase already centralized `confluenceZoneKindsLabel` after two unpatched siblings needed it. Reusing the existing 60-day ceiling and its comment (carried over verbatim, now with the three live repros it was built from) rather than inventing a second threshold. |
