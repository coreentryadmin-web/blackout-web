## Vector: live HELIX chart flash/pulse conflated option type with direction — a sold call flashed the chart bullish — FIXED

> **kind:** `FINDING`

A dedicated Vector bug-hunt pass (Vector's only prior fix today, PR #3216, was a `VectorRegimeBanner`
placeholder-rendered-as-live-value bug — unrelated to this one).

| Field | Detail |
|---|---|
| **Symptom** | On `/vector`, every live HELIX flow print flashes a labeled price line on the chart and pulses the candle's border for ~2s. That flash's color/tone read `option_type` alone — a CALL always flashed lime/"bull", a PUT always flashed red/"bear" — regardless of who initiated the trade. |
| **Root cause** | `pushHelixChartFocus` (`VectorPageShell.tsx`) computed `tone: isCall ? "bull" : "bear"` directly from `flow.option_type`, never reading `flow.ask_pct` (the aggressor side). This is the exact "option-type-only direction" conflation `helix-flow-aggression.ts`'s `flowDirection` exists to fix, and which this repo already fixed on every other surface that asserts a print's direction (HELIX's own `printBias`, `vector-play-platform.ts`'s `summarizeSessionFlowBias`) — `helix-flow-aggression.ts`'s own header cites a measured 44.6% per-ticker sign-flip rate between the two rules on live prod tape. A companion, **dormant** copy of the same bug — `toneFromFlowSide(optionType)` in `vector-flow-confluence.ts`, exported but with zero callers anywhere in the repo — carried the identical option-type-only logic under a canonical-sounding name, exactly the trap a future caller would reach for (the same class of bug X-content's `validateSessionClaim` stub was fixed for earlier today). A third, smaller defect compounded the first: the candle-pulse-tone derivation in `VectorChart.tsx` (`focusLevel.tone === "bull" ? "bull" : focusLevel.tone === "bear" ? "bear" : "bull"`) silently collapsed ANY non-bull/non-bear tone to `"bull"`, so even a correctly-computed neutral/undetermined tone would still have pulsed the candle bullish. |
| **Concrete example** | A HELIX print `{option_type: "CALL", strike: 550, ask_pct: 8, premium: $3M}` — an unambiguously SOLD call (`ask_pct` well below the 40% sold threshold) that `flowDirection` reads as **bearish** everywhere else in the product. Before the fix: the chart flashed the 550 price line lime and pulsed the nearest candle's border bullish for this print. |
| **Live-reachable** | Yes, on two real paths: `handleHelixFlowFlash` fires on every live SSE HELIX print ingested during market hours (`use-vector-helix-flows.ts`); `handleHelixStrikeFocus` fires when a member clicks any flow card in `VectorHelixRail`. Neither is admin/debug-only. |
| **Fix** | Extracted a new pure `chartFocusToneForFlow(flow)` (`vector-flow-confluence.ts`) that routes through `flowDirection`, mapping `"bullish"`→`"bull"`, `"bearish"`→`"bear"`, and (honestly) `"undetermined"`→`"sky"` — the same neutral tone already used for matrix-strike focus, rather than guessing bull or bear when the aggressor side isn't readable. `pushHelixChartFocus` now calls it instead of inlining `isCall ? "bull" : "bear"`. Fixed the dormant `toneFromFlowSide` to delegate to `flowDirection` too (its 2-value return type has no "undetermined" state, so it falls back to the option-type-only read only when the aggressor side genuinely can't be determined — same graceful-degradation pattern used elsewhere in this codebase). Fixed `VectorChart.tsx`'s pulse-tone collapse to only ever push a candle pulse for a genuine `"bull"`/`"bear"` tone, skipping the pulse entirely (rather than defaulting to bullish) for anything else. |
| **Blast radius** | `VectorPageShell.tsx`'s `pushHelixChartFocus` (the live bug), `vector-flow-confluence.ts`'s `toneFromFlowSide` (dormant duplicate, no callers, fixed proactively per this repo's own "wired to nothing yet but wrong is reportable" precedent), and `VectorChart.tsx`'s pulse-tone fallback (a second, smaller defect in the same code path). `VectorHelixRail.tsx`'s own `isCall` usage (line 62) is unrelated — it labels the print's literal option type ("CALL"/"PUT" text), never asserts a bull/bear signal, so it was left unchanged. |
| **Why not caught earlier** | No test exercised `pushHelixChartFocus`'s tone computation, and `toneFromFlowSide` had zero callers and zero tests, so its bug was entirely invisible. |
| **Regression guard** | 10 new tests in `vector-flow-confluence.test.ts`: `chartFocusToneForFlow` — bought call→bull, sold call→bear (the exact live regression), bought put→bear, sold put→bull, no `ask_pct`→sky, midpoint `ask_pct`→sky; `toneFromFlowSide` — sold call→bear, sold put→bull, undetermined falls back to the option-type-only read (documenting its own limitation). Confirmed **failing** pre-fix (`git stash` toggle: 9/14 failures) and passing post-fix (14/14). |
| **Gates** | `npx tsc --noEmit` clean · `vector-flow-confluence.test.ts` 14/14 pass · full `npm test` 11499 pass / 0 fail / 2 skipped (Node 20.20.2). |
| **Status** | FIXED |
