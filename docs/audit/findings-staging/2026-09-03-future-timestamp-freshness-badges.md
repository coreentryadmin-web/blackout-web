## 2026-09-03 — [FINDING, P3 correctness, Helix/Thermal/Meridian] 4 UI freshness badges read a future-dated upstream timestamp as freshest-possible instead of untrustworthy — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | This session already found and fixed 12 instances of the same bug shape (a naive `now - eventTimestamp` freshness check with no future-timestamp guard, so a bad/skewed upstream timestamp produces a negative age that trivially passes any `<= threshold` check) — most recently in `src/lib/cron-writer-target-fresh.ts`. Swept the areas none of those fixes had touched (Helix, Thermal, Meridian, Largo) for a fresh angle, since none had a commit in the last 60 on `main`. |
| **Investigation** | Grepped for `Date.now() -`/`now - t`/staleness comparisons across the four areas. Three already had the guard (`et-session-facts.ts`'s `ageSecondsFromIso`, `thermal-desk-state.ts`'s `classifyFreshness`/`shouldForceMatrixRefresh`, and every Largo caller of `signalWindowAgeMs`) and one (`helix-flow-format.ts`'s `timeAgo`) is purely a cosmetic relative-time string, not a threshold gate — all correctly left alone. Four genuine, reachable instances remained, all UI trust badges reading a real upstream/server timestamp with no future-timestamp guard. |
| **Root cause / sites** | (1) `FlowFeed.tsx`'s tape LIVE/STALE badge derived `newestAt` as a plain max over every print's `flowFreshnessAtMs`, including one dated in the future (UW clock skew / bad `alerted_at`) — `dataAgeMs = Date.now() - newestAt` went negative, failed `> 5min`, and painted green LIVE for a tape that could be dead; directly contradicts the surrounding comment's own stated guarantee. (2) `helix-session-pulse.ts`'s `printsLast15m` counter used a raw `nowMs - t <= 15min` check with the same UW timestamp — a future print inflated the count. (3) `GexHeatmap.tsx`'s `MatrixFreshness` computed `stale = Date.now() - t > MATRIX_STALE_MS` off the server `asof` — a future `asof` (clock skew) never satisfied `> 15s`, so the dot rendered green/fresh. (4) `meridian-viz.tsx`'s `MeridianFreshness` used `Math.max(0, now - t)` — a future `asOf` clamped straight to "updated 0s ago", the single freshest-looking label possible, exactly backwards. |
| **Why this matters** | Same class as the 12 already-fixed sites: a freshness/trust indicator that reads a bad timestamp as MORE trustworthy than a normal one defeats the entire point of the indicator — a member (or Largo, for the server-side sites already fixed) sees "live"/"fresh" for data that cannot actually be verified as recent. All four here are UI trust badges/counters, not order-execution or risk gates. |
| **Fix** | (1) `FlowFeed.tsx`: `newestAt`'s computation now skips any candidate whose `signalWindowAgeMs(ms, nowMs)` comes back `null` (imported from the shared `helix-signal-detection.ts`, the same guard the split/velocity detectors already apply to this exact field) — a bad print can never become the freshness anchor. (2) `helix-session-pulse.ts`: `printsLast15m` now gates on `signalWindowAgeMs(t, nowMs) <= FIFTEEN_MIN_MS` instead of a raw subtraction. (3) `GexHeatmap.tsx`: added a local `FUTURE_ASOF_TOLERANCE_MS = 5_000` (ordinary server/client clock skew) and `stale` now also fires when `ageMs < -FUTURE_ASOF_TOLERANCE_MS`. (4) `meridian-viz.tsx`: `stale` is now derived from the raw, unclamped `rawAgeMs` (`> staleAfterMs \|\| < -FUTURE_ASOF_TOLERANCE_MS`); only the DISPLAYED age label still clamps to 0 for legibility. |
| **Blast radius** | Four files, each a single isolated freshness computation — no shared helper needed changing beyond importing the existing `signalWindowAgeMs` into two more call sites. No behavior change for any normal (non-future) timestamp. |
| **Regression guard** | `helix-session-pulse.test.ts`: 2 new tests (a well-future print excluded from `printsLast15m`; a print a few seconds ahead — ordinary clock skew — still counted, matching `signalWindowAgeMs`'s own tolerance). The three component fixes (React components, not pure logic) got source-text regression tests matching this repo's established convention for that case (e.g. `HelixTideBar.test.ts`): `FlowFeed-freshness-badge.test.ts`, `GexHeatmap-matrix-freshness.test.ts`, `meridian-viz-freshness.test.ts` — one new file each, asserting the guard is present in source. Confirmed RED pre-fix (`git stash` each source file, keep its test: 6/6 new assertions across all four sites fail) and GREEN post-fix (6/6). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: 11948 passed / 5 failed / 2 skipped — the 5 failures are the documented pre-existing sandbox-only DB-connectivity artifact (unrelated files, same signatures as every other run this session). |
