| **What this corrects** | `docs/audit/findings-staging/2026-08-30-bie-orphan-files-more-entangled-than-noted.md` (this cycle, earlier) concluded it could not confirm `composers.ts`/`decompose.ts`/`dynamic-format.ts` were safe to delete because `largo-terminal.test.ts` — the one file in the whole repo that references `composers.ts` at all — "does not run in this sandbox," reportedly failing with `import_node_test.mock.module is not a function`. That conclusion was wrong: the failure was an invocation bug, not a sandbox limitation. |
| **Root cause of the earlier wrong conclusion** | `npx tsx --test <file>` (the ad-hoc invocation used to spot-check that file) omits `--experimental-test-module-mocks`, a flag Node's `node:test` requires for `mock.module` to exist at all. This repo's real test command — `npm test` → `scripts/run-tests.mjs` — always includes it (`["--import", "tsx", "--experimental-test-module-mocks", "--test", ...]`). Running the exact same file as `node --import tsx --experimental-test-module-mocks --test src/lib/largo-terminal.test.ts` passes **13/13** clean on Node 20.20.2. This is the second, independent confirmation this same cycle that the flag — not `mock.module` itself — was the actual gap; see the companion finding `2026-08-30-polygon-largo-cache-override-silently-ignored.md` for the first. |
| **The mock block in `largo-terminal.test.ts` is vestigial, not load-bearing** | The file's `before()` hook carried `mock.module("./bie/composers", { namedExports: { composeBieAnswer: ... } })`, with a comment claiming the suite "exists to prove the real router decision reaches the persisted row." Grepped every test assertion in the file: **every single test asserts `row.intent_bucket === "claude_fallback"`** (the Claude-tool-loop fallback path) — none asserts `"zerodte_plays"`, `"market_context"`, or any bucket the mocked `composeBieAnswer` would produce. `RICH_ENVELOPE`/`SHIM_ENVELOPE` (used at line 454-455 to test `isRichBieEnvelope()`) are built directly from `@/lib/bie/answer-envelope`, independent of the mock. The mock's stub function is registered but never exercised by anything in the file — dead scaffolding for a router path `largo-terminal.ts` itself no longer even imports (confirmed: zero references to `composeBieAnswer`/`bie/composers` in `largo-terminal.ts`). |
| **Empirical proof `mock.module` needs its target file to exist on disk** | Before touching anything for real, moved `composers.ts` to a temp path and re-ran the suite with the correct flag: all 13 tests failed with `ERR_MODULE_NOT_FOUND: Cannot find module '.../src/lib/bie/composers'`. Restored the file immediately. This confirms the mock block, not the code path, is what makes the test suite depend on the file's mere existence — exactly the trap the earlier write-up worried about, and exactly what this cycle now resolves by removing the mock block itself rather than working around it. |
| **`router.ts` and `composers-shared.ts` are NOT touched — still live** | `router.ts` (`BieRoute` type) has 5 real non-test importers (`live-data-enrich-detect.ts`, `live-data-enrich.ts`, `largo-status.ts`, `response-shape.ts`, `dynamic-format.ts` itself). `composers-shared.ts` (`BieComposed` type, `tierLine`) has 14+ real non-test importers across `src/lib/bie/*-read.ts` and `vector-pulse-brief.ts`/`verdict.ts`/`helix-read.ts`. Only `composers.ts` (1021 lines), `decompose.ts` (133 lines, zero importers anywhere except its own test), and `dynamic-format.ts` (397 lines, imported only by `composers.ts` and its own test) are dead. |
| **One more dead-code dependent found and fixed: `zerodte-service.test.ts`** | A second file had a load-bearing `readFileSync` on `composers.ts`: `test("BIE composers read zeroDtePlaysForLargo from shared scan module")` read the raw source of `composers.ts` and regex-matched `/zeroDtePlaysForLargo/` — a source-text test asserting an internal-consistency property of a file that no production code path ever reaches.
