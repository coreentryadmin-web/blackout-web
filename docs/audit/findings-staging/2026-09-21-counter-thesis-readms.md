| Field | Detail |
|---|---|
| **Symptom** | Second follow-up sweep to #5351 (`SwingPlayBriefContext.readMs` — the single canonical "now" `composeSwingPlayBrief` stamps once before any section builds) after #5353 fixed `dataFreshnessSection`/`collectBriefUnavailableSources`. Both fixes left the remaining `Date.now()` call sites across `play-brief-narrative.ts`/`play-brief-narrative-coaching.ts` as a documented follow-up. This cycle's Ask Largo deep-dive found `counterThesisLine` (play-brief-narrative.ts) — the function that renders the member-visible "Counter-thesis (bear/bull case)" bullet in "Trade manager read" (live TEM/CRDO briefs pulled this cycle both show this bullet) — sampling the wall clock with **five separate bare `Date.now()` calls** across one function body, none consulting `ctx.readMs`, and never even capturing a local snapshot to keep the five checks internally consistent with each other. `dealerPostureLine` had a milder version of the same bug: it captured one local `readMs = Date.now()` (internally consistent within itself) but never threaded `ctx.readMs`, and separately called `resolveGammaPosture(ctx, vec)` without passing its own `readMs`, so that helper defaulted to a SECOND, later `Date.now()` sample for the same `vec` snapshot the rest of the function had already judged. |
| **Root cause** | `counterThesisLine`'s Vector-bias check (`vectorSnapshotStale(vec, Date.now(), ...)`), its wall-fallback check (`vectorSnapshotStale`/`gexMatrixStale`, two more `Date.now()` calls), its EMA-stack check (`vectorSnapshotStale`, a fourth), and its `resolveGammaPosture(ctx, vec)` call (implicit fifth, via that helper's own `Date.now()` default) each independently asked "what time is it right now" instead of using the one instant `composeSwingPlayBrief` already pinned for the rest of the brief. Within a single synchronous function this is unlikely to cross a staleness threshold internally, but it can (and does) disagree with every OTHER section of the same brief that correctly uses `ctx.readMs` — e.g. `watchForSection`/`confluenceCoaching` (#5351) and `dataFreshnessSection`/`collectBriefUnavailableSources` (#5353) all judge the identical `vec`/`gex` snapshot's freshness off `ctx.readMs`, while `counterThesisLine` judged it off a later, independently-sampled clock read — the same "chip says stale, narrative says fresh" failure class #5353's own write-up describes, just for the counter-thesis bullet instead of the freshness chip. |
| **Evidence** | New regression test (`counterThesisLine: uses ctx.readMs, not the real wall clock, to judge Vector freshness`, `play-brief-narrative.test.ts`) sets `vec.asOf` to a fixed 2026-09-05 timestamp with no `dataAgeMs`, and `ctx.readMs` to that SAME instant (genuinely 0ms old under `ctx.readMs`) — while the real wall clock at actual test-run time (2026-09-21) is ~16 days later, past every staleness window. RED confirmed pre-fix via `git stash` on the source file only (test kept): assertion failed, `resolveGammaPosture` judged the snapshot stale off the real clock and dropped the "dealer long-gamma pins rallies" counter-thesis reason entirely. GREEN post-fix, 100/100 in `play-brief-narrative.test.ts`. Full suite (`npm test`, Node 20): pending — see PR. `tsc --noEmit` clean. |
| **Fix** | `counterThesisLine` now samples `const readMs = ctx.readMs ?? Date.now();` once at the top (with an in-code comment tracing the bug back to #5351/#5353) and threads it into all five staleness checks, including passing it explicitly into `resolveGammaPosture(ctx, vec, readMs)` (which already accepted an optional `readMs` param — the gap was purely the call site never passing it). `dealerPostureLine` gets the identical `ctx.readMs ?? Date.now()` anchor in place of its own bare `Date.now()`, and now threads that same `readMs` into `resolveGammaPosture` too, so its own internal two-clock disagreement (one local sample for its own checks, a second implicit one inside the helper it calls) is closed as well. |

The rest remain a follow-up, same scoping discipline #5351/#5353 both used. |
