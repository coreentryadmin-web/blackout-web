## 2026-10-18 — [FINDING, P2, Ask Largo swing play-brief] OPEN-bucket `pnlSection`'s Greeks and Liquidity/Spread lines carried zero staleness/sync disclosure, even though they're read off the identical contract snapshot the Mark line already flags — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Severity** | P2 — matches this file's own severity convention for member-visible disclosure-completeness gaps in the same section (e.g. the 2026-10-17 Peak/Trough fix was also P2). Not P1: no wrong trading recommendation, no crash, no financial miscalculation — purely a missing freshness caveat on values that are themselves computed honestly. |
| **Trigger** | Standing Ask Largo deep-dive sub-mandate (5-engine live monitor cycle), a background Workflow deep-dive scoped to the OPEN/CLOSED-bucket play-brief sections. |
| **Root cause** | `pnlSection` (`src/lib/swing/play-brief.ts`) discloses the Mark's sync/freshness state explicitly two different ways (`markGenuinelyUnknown` → "Mark: unknown (sync quote, no live price yet)"; `markUnsynced` → "Mark: $X (live quote, no freshness timestamp)"; and separately, the brief's own "Data freshness" section flags `optionMarkIsStale`). But the Greeks block (`if (play.greeks)`) and the Liquidity/Spread block (`if (play.liquidity && ...)`) — both derived from the identical `play.contract` snapshot the Mark came from (`adapters.ts`) — carried zero staleness/sync disclosure anywhere. An in-code comment at the Greeks block even argued this was deliberate ("`greeksFromContract` already only returns non-null when a field is real... so `if (play.greeks)` alone is sufficient here") — but that conflates two distinct Largo-contract principles: C3 absence (is the field present) vs. freshness (is it current). It only ever guarded presence, never staleness. |
| **Evidence** | Fetched real OPEN-bucket play-briefs. NVDA (positionId 62, `markGenuinelyUnknown` — never ticked since commit): Position section showed "Mark: **unknown** _(sync quote, no live price yet — do not read as flat)_" followed 4 lines later by "Greeks: Δ +0.59" with NO caveat, even though delta comes from the exact same never-synced read. TSLA/CRWV (positionId 60/61, both carrying a real `markAsOf` timestamp): the brief's own "Data freshness" section independently flagged "Option mark **stale** — last synced 2026-10-16 16:00 ET" for both, while the SAME envelope's Position section showed fully confident "Greeks: Δ +0.55 · Γ +0.01 · θ -0.94/day · ν +0.20 · IV 66%" and "Spread: **1.4%** (...)" with zero mention the quote behind both was the same one just flagged stale two sections away. Confirmed in code: `adapters.ts` builds `greeks`, `liquidity`, and `markAsOf`/`mark` all from the identical `src.contract` snapshot, substantiating the "same quote read" claim structurally, not just by inference. RED→GREEN proven: 2 new regression tests (`play-brief.test.ts`) failed against unmodified `main` (`git stash` isolating `play-brief.ts`), passed after the fix. `npx tsc --noEmit` clean; full `play-brief.test.ts` suite (153 tests) green. |
| **Blast radius** | One production file. `pnlSection` gains a `readMs: number` parameter (its sole call site, `buildVerdictBody`'s "open" branch, already computes `ctx.readMs ?? readMs` for a sibling section — `watchEntrySection` — so this follows an existing, identical convention). A single `staleCaveat` string is computed once (reusing the already-computed `markGenuinelyUnknown`/`markUnsynced` locals plus `optionMarkIsStale(play, readMs)`) and appended to the Greeks line, the Spread/comparison line, and the one-sided-book Quote line. `pnlSection` renders for every OPEN/HOLD/TRIM swing position brief — the gap fires whenever `markGenuinelyUnknown` is true (board-wide sweep during the investigation found 9/61 live positions in this state) or whenever `optionMarkIsStale` is true (effectively universal for any brief read outside the ~15-min swing-active-refresh cadence, e.g. overnight/weekend reads, which given Night Hawk Swings' usage pattern is a large share of real views). |
| **Fix rationale** | Disclose, don't suppress — the entry-time/aged values are still real, useful context (e.g. "what were my greeks when I entered"); omitting them would be a regression relative to current behavior and would lose real information, inconsistent with this file's established convention (Mark/Peak/Trough/Data-freshness all disclose with a qualifier rather than hide). The caveat tiers mirror the Mark line's own precedence (`markGenuinelyUnknown` > `markUnsynced` > `optionMarkIsStale` > fresh, no caveat) so a member reading the Position section gets one consistent story about data confidence across every line in it, not just the Mark line. |
| **Status** | FIXED — see PR (branch `fix/swing-pnl-greeks-staleness-caveat`). |
