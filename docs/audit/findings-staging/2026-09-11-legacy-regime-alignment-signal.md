## 2026-09-11 — Add regime-drift alignment signal to Legacy pick detail — SHIPPED

> **kind:** `FINDING`

| Field | Detail |
| --- | --- |
| **Status** | SHIPPED (enhancement, not a bug fix) |
| **Severity** | P3 (product enhancement — surfaces an already-known-but-unsurfaced signal, per the standing aggressive-improvement-hunting mandate) |
| **Component** | New `src/features/nighthawk/lib/regime-alignment.ts`; wired into `src/features/nighthawk/components/LegacyPlayTechnicalsRail.tsx` and `LegacyPickLogBoard.tsx` |
| **Gap identified** | A Legacy pick is a next-day digest — it can sit 12-16+ hours between its ~7pm ET evening publish and the next morning's open, and the broad market regime can genuinely flip overnight. Two regime signals already existed in the data — `play.regime` (captured at publish time, shown only as a small "sub" label on the Direction bullet) and `macro.regime` (today's live regime, shown once at the top of the board via `LegacyMacroStrip`) — but nothing ever compared them. A member had to mentally diff two separately-rendered strings in different parts of the UI to notice a pick's regime thesis had gone stale overnight — exactly the "a signal that exists but isn't surfaced" case the standing aggressive-improvement-hunting mandate calls out. |
| **What shipped** | A pure `regimeAlignmentNote(playRegime, currentRegime)` helper (case-insensitive exact-string comparison, returns `null` when either side is missing — never fabricates a comparison from partial data) rendered as a new "Regime" bullet in `LegacyPlayTechnicalsRail`'s "Gates & checks" section: `"Still {regime} — thesis regime intact"` (tone up) when aligned, `"Published in {play.regime}, market now {macro.regime} — validate before entry"` (tone warn) when drifted. |
| **Wiring** | `LegacyPickLogBoard.tsx` already threads `macroContext` through to `LegacyMacroStrip`; added one line passing `macroContext?.regime ?? null` as a new optional `currentRegime` prop to `LegacyPlayTechnicalsRail` (defaults to `null` so any caller without macro context, tests included, renders everything else unchanged). No existing prop signatures broken. |
| **Blast radius** | One new optional prop + one new conditional bullet. No change to any other field, to scoring, gating, or play-generation logic — purely additive display. |
| **Fix rationale** | Reused the exact honest-null-handling discipline already used throughout these detail-rail components (never render a comparison/derived value when an input is missing) rather than defaulting to a guess. Kept the comparison pure and dependency-free (no new data fetch — both inputs already flow through the existing component tree) so the feature costs nothing extra to compute. |
| **Regression test** | `regime-alignment.test.ts` (4 tests): matching regimes (including case-insensitive match) report "intact"/tone up; a real mismatch reports both regime names/tone warn; either side missing/blank renders nothing. `LegacyPlayTechnicalsRail.test.ts` (3 tests, new file for this component using the `renderToStaticMarkup` idiom already established by `PlaybookBriefingPanel.test.ts`): intact-regime bullet renders, drift-warning bullet renders with both regime names, and no bullet renders when regime is unknown. Full repo suite 13693/13693 pass / 0 fail, `tsc --noEmit` clean. |
