## 2026-09-15 — [FINDING, P2 correctness] SPX Slayer Live Desk brief claimed "neg-γ" on an unresolved gamma flip — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What this resolves** | Found during the standing Ask Largo × Night Hawk Swings deep-dive cycle (broadened this pass to the SPX Slayer desk per the 5-engine live monitor's own checklist item 1: "is `direction` consistent with the net signed weight?"). `GET /api/market/spx/desk` was observed live (2026-09-15, ~19:44 ET, post-close) with `gamma_flip: null` and `gamma_regime: "unknown"` — i.e. the gamma flip is genuinely unresolved this tick — yet `above_gamma_flip: false` was still present on the payload. |
| **Root cause** | `above_gamma_flip` is typed as a plain non-nullable `boolean` on `SpxDeskPayload` (`spx-desk.ts`), and every site that derives it defaults to `false` when `gamma_flip` is `null` (e.g. `above_gamma_flip: flip != null ? spot > flip : false` — several call sites in `spx-desk.ts`/`spx-desk-merge.ts`). That default is reasonable for a type that can't be null, but `src/lib/bie/spx-desk-brief.ts` (the deterministic Live Desk AI brief text members read) treated `!desk.above_gamma_flip`/`desk.above_gamma_flip === false` as proof of a *confirmed* negative-gamma (short-gamma/trend-fuel) regime in three places, without first checking whether `gamma_flip` was actually known: `gammaTag()` (returned `"neg-γ (trend fuel)"` whenever `above_gamma_flip === false`, regardless of `gamma_flip`), `buildWhy()`'s `!desk.above_gamma_flip && support && …` branch (fired a "drops feed toward X air" claim), and the `NEXT 5M` ternary chain (`composeSpxDeskBrief`)'s two `!desk.above_gamma_flip && resistance` branches (power-hour squeeze / expansion claims) plus its final fallback substituting current price for the unknown flip level (`n(desk.gamma_flip ?? price, 0)`) and calling it a "watch" level. This is exactly the "plausible wrong claim is worse than an honest absence" trap `docs/audit/LARGO-PRODUCT-CONTRACT.md`'s C3 (absence) section and multiple other files in this repo already document — here it wasn't caught because the boolean itself has no way to represent "unknown" at its own type level, so every consumer has to re-derive that fact from `gamma_flip`'s nullability, and this file's three call sites simply didn't. |
| **Evidence** | Live `GET /api/market/spx/desk` response (2026-09-15 ~19:44 ET): `"gamma_flip": null, "gamma_regime": "unknown", "above_gamma_flip": false`. Traced through `gammaTag()`/`buildWhy()`/`composeSpxDeskBrief`'s `next` ternary and confirmed (regression test, RED against pre-fix source) that feeding this exact shape through `composeSpxDeskBrief` produced body text containing `"neg-γ expansion into {{…}} air if {{…}} fails"` — a confident short-gamma call sourced entirely from the boolean's null-default, not from any real signal. |
| **Fix** | Added an explicit `desk.gamma_flip != null` (`flipKnown`) guard everywhere `above_gamma_flip === false`/`!above_gamma_flip` was previously trusted alone: `gammaTag()` now returns `"γ regime unresolved"` when neither `gamma_regime`/`regime` nor `gamma_flip` resolves the regime (the `amplification`/`mean_revert` fast paths, which don't depend on `above_gamma_flip` at all, are untouched); `buildWhy()`'s support-branch and the `NEXT 5M` ternary's two neg-γ branches now require `flipKnown` before firing; the ternary's final fallback distinguishes a genuinely resolved flip (unchanged behavior, uses `gammaTag()` + the real flip level) from an unresolved one (new: `"γ regime unresolved — watch {{price}} and TICK"`, honest about substituting current price rather than silently mislabeling it as the flip level). |
| **Blast radius** | One file (`src/lib/bie/spx-desk-brief.ts`) — the two branches that were ALREADY safe by construction (`desk.above_gamma_flip && …`, which simply can't fire on the `false` default) were left untouched, as was the existing, correctly-guarded `if (desk.gamma_flip != null)` block in `buildWhy()` this fix's pattern was copied from. No change to `spx-desk.ts`'s `above_gamma_flip` derivation itself (out of scope — the type staying a plain boolean is a legitimate, narrower design choice; the bug was in this file's consumption of it, not its production) and no change to any gate/scoring logic. |
| **Fix rationale** | Guarding at the consumption site (this file) rather than widening `above_gamma_flip` to `boolean \| null` across the whole `SpxDeskPayload` type was the smaller, correctly-scoped fix — that type is read by dozens of files (`spx-play-confirmations.ts`, `playbook-shadow-matcher.ts`, `spx-invalidation.ts`, `spx-premise.ts`, `spx-desk-synthesis.ts`, etc.), some of which already correctly gate on it or don't care about the unresolved case; widening the type would be a large, cross-cutting refactor with its own blast-radius risk for a bug that, on inspection, only actually manifested in this one brief-composition file. If a similar false-confidence pattern turns up in another consumer, that's the natural trigger to reconsider the type itself. |
| **Regression guard** | `src/lib/bie/spx-desk-brief.test.ts` — new test `"unresolved gamma flip never reads as a confident neg-gamma call"`: feeds a desk fixture with `gamma_flip: undefined`, `gamma_regime: "unknown"`, `above_gamma_flip: false` (the real server-default shape) through `composeSpxDeskBrief` and asserts the body never contains `/neg-γ/` and does contain `"γ regime unresolved"`. Git-stash proven: fails against pre-fix `spx-desk-brief.ts` (body contained `"neg-γ expansion into {{5,910}} air if {{5,885}} fails"`), passes post-fix (8/8 in the file). `npx tsc --noEmit` clean (Node 20). Full `npm test` run in progress at commit time. |
| **Gates** | `npx tsc --noEmit` clean (Node 20) · `spx-desk-brief.test.ts` 8/8 pass, RED→GREEN proven via `git stash` · full `npm test` result to follow in the PR. |
| **Status** | FIXED. |
