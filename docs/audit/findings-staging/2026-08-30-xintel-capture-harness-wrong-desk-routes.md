## X-intel capture harness pointed Helix, Thermal and Largo at the WRONG desk routes — FIXED

> **kind:** `FINDING`

X-content-lane audit pass following today's `#3217` fix (capture-diversity no-op + session-claim
stub). Looked for a different bug in the same lane per instruction, in
`src/lib/x-intel/*` / `src/lib/largo/x-post-capture-playbook.ts`.

| Field | Detail |
|---|---|
| **Symptom** | `src/lib/x-intel/capture-harness.ts`'s `CAPTURE_SURFACES` table — the per-product URL the harness navigates to and screenshots for an X-intel queue attachment — had three of its seven entries pointed at the wrong desk route: Helix `https://blackouttrades.com/terminal#tab=helix`, Thermal `https://blackouttrades.com/terminal#tab=thermal`, Largo `https://blackouttrades.com/dashboard#tab=largo`. |
| **Root cause** | `/terminal` and `/dashboard` are each a single, tier-gated product page, not a tabbed shell that answers a `#tab=` hash fragment. `(site)/terminal/layout.tsx` calls `requireDeskTool("premium", "largo")` specifically — `/terminal` IS the Largo page, full stop — and `(site)/dashboard/layout.tsx` gates generically on `requireTier("community")` for what `LARGO_PLATFORM_LINKS.desks.spxSlayer` (`platform-links.ts`) already names as the SPX Slayer route. So `/terminal#tab=helix` and `/terminal#tab=thermal` would each load and screenshot the LARGO page (the hash fragment is inert — nothing in the app reads a `tab=` query off `/terminal`), and `/dashboard#tab=largo` would load and screenshot the SPX SLAYER page. In every case the harness would still caption the frame as if it had captured the product it claims to ("Helix flow intelligence", "Thermal gamma structure", "Largo AI intelligence") and stamp `source_surface` accordingly — a confidently wrong label on a real screenshot of a different product, not a visible error. |
| **Why not caught earlier** | `captureForQueuePackage`/`captureSingleSource` (the only code that reads `CAPTURE_SURFACES[source].url`) has **no live caller yet** — `x-intel/route.ts` (the only wired cron) builds its own single "desk card" PNG via `renderDeskCardPng` and never calls into this harness. The table was previously exercised only by `capture-harness.test.ts`'s `validateCaptureSource`/`attachmentsFromCaptures` tests, none of which assert anything about the URLs themselves — so this is the same "wired to nothing yet, but wrong, and would ship wrong the moment it's wired" class of defect as today's earlier `#3217` fix in the same file, arriving from a different angle (a stale/copy-pasted route table rather than a no-op flag). |
| **Evidence** | Cross-checked the table against the canonical desk-route map used everywhere else in the repo: `LARGO_PLATFORM_LINKS.desks` (`src/lib/largo/platform-links.ts`) — `helix: /flows`, `thermal: /heatmap`, `largo: /terminal`, `spxSlayer: /dashboard` — and the independently-authored allowlist in `src/lib/x-intel/capture-guard.ts`'s `CAPTURABLE_SURFACE_PATHS`, which maps `/terminal` → `"largo"` and `/dashboard` → `"spx_slayer"` (not `"helix"`/`"thermal"`/`"largo"` respectively). Confirmed live in the repo: `grep requireDeskTool.*largo src/app/(site)/terminal/layout.tsx` shows the `/terminal` gate names `"largo"` explicitly. |
| **Fix** | Corrected the three wrong entries to the real per-product routes: Helix → `/flows`, Thermal → `/heatmap`, Largo → `/terminal`. Also dropped `spx_slayer`'s harmless-but-pointless `#tab=spx-slayer` fragment since `/dashboard` already IS the SPX Slayer page with no tabs to select. Vector, SPX Slayer's base path, Night Hawk and Meridian were already correct and are unchanged. |
| **Blast radius** | Only this one table (`CAPTURE_SURFACES`) — used at both `captureSingleSource`'s navigation URL and `attachmentsFromCaptures`'s `source_url` stamp, so the same wrong route would have both captured the wrong panel AND mislabeled its provenance on the same queue row. No other file duplicates this mapping (confirmed via repo-wide grep for `CAPTURE_SURFACES`) — `x-post-capture-playbook.ts`'s `LARGO_PLATFORM_LINKS`-based playbooks (the other, human-operator-facing capture instructions in this lane) were already correct throughout. |
| **Fix rationale** | Correct the table in place rather than deriving it from `LARGO_PLATFORM_LINKS.desks` at import time — this file is deliberately self-contained (no dependency on the Largo platform-links module) and the regression test below now pins every entry against the independent `capture-guard.ts` allowlist directly, which is the stronger check: it fails if this table's route ever stops resolving to the surface it claims, regardless of which canonical source drifts. |
| **Regression guard** | Exported `CAPTURE_SURFACES` (previously module-private) and added a new `capture-harness.test.ts` block that runs `checkCaptureUrl` (from `capture-guard.ts`) against every configured URL and asserts the returned `surface` equals the table's own key — this is exactly the check that would have failed on the pre-fix table (`/terminal` → `"largo"` ≠ `"helix"`/`"thermal"`; `/dashboard#tab=largo` → refused for carrying a query-adjacent hash the guard doesn't special-case, since `/dashboard` alone → `"spx_slayer"` ≠ `"largo"`). Confirmed RED on the pre-fix file (`git stash` the fix, re-run: 1 subtest failed) and GREEN after (32/32 pass). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2) · `node --import tsx --test src/lib/x-intel/capture-harness.test.ts` 32/32 pass, confirmed red-then-green via `git stash`. |
| **Status** | FIXED |
