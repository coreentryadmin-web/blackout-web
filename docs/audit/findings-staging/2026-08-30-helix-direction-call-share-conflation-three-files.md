## HELIX: option-type-only ("call-share") direction still lived on in three call sites the aggression-aware fix never reached — FIXED

> **kind:** `FINDING`

Fourteenth/fifteenth-plus product-surface pass — a dedicated Helix bug hunt. Earlier today's fixes
(`helix-direction-read.ts`, `helix-flow-aggression.ts`, and the aggression-aware `flowDirection`/
`directionalPremium`/`directionLabel` rewrite) correctly replaced "call premium alone = bullish"
with "call/put **× who was buying**" across `FlowFeed.tsx`, `ExpiryConcentration.tsx`,
`TickerDrawer.tsx`, `HelixTideBar`, and the signal ledger. But the fix was applied inconsistently:
the exact same conflation it eliminated survived, untouched, in three other call sites — one of
which feeds a real 0DTE scoring boost. This is bug class (f) from earlier today's findings
(Vector/Thermal/X-content): a fix landed in one file and a sibling's copy of the same logic was
never updated.

| Field | Detail |
|---|---|
| **Symptom 1 (highest severity)** | `aggregateHelixTapeByTicker` (`src/lib/zerodte/thesis/helix-tape-extras.ts`) computed `direction_bias` from `isCall ? call_premium += prem : put_premium += prem` then `callShare >= 0.6 -> "long"` — no `ask_pct` field even existed on its input type, so the aggressor side was discarded before the function could see it. |
| **Symptom 2** | `flowBiasFromPremiums` (`src/lib/largo/helix-thermal-compare.ts`) computed the Largo Flow-vs-Thermal compare card's `bias` the same way: `ratio = (callPrem - putPrem) / (callPrem + putPrem)`, no aggressor read. |
| **Symptom 3** | `helixContribution` (`src/lib/largo/contract/product-adapters.ts`) called `directionFromCallPct(session.call_pct)` — ignoring `session.direction`, the authoritative aggressor-aware field `directionFields` (`helix-tape-analytics.ts`) already stamps onto that exact payload shape, sitting right next to the field this adapter actually read. |
| **Root cause** | All three predate (or were simply never touched by) today's `helix-flow-aggression.ts` build-out. A call/put **share** cannot distinguish a bought call from a sold one, and the two mean opposite things — `helix-flow-aggression.ts`'s own header cites a measured 44.6% per-ticker sign-flip rate between the two rules on live prod tape (2026-08-23). |
| **Concrete example (Finding 1)** | 10 CALL prints, $8M total premium, all **sold** (`ask_pct` low → aggression-aware verdict: bearish) and $0 PUT premium → old code: `callShare = 1.0` → `direction_bias: "long"`. This is wired live in `scan.ts` into `helix_direction_bias`, which `legacy-bridge.ts`'s `crossProductCorroborationBoost` uses to add **+5 (+8 with the ≥$1M bonus)** to a live 0DTE setup's rail score whenever `helix_direction_bias === direction` — a false score boost from flow evidence that, correctly read, argues the opposite direction. |
| **Concrete example (Finding 3)** | `session = { call_pct: 100, direction: "bearish" }` (the real CG case documented in `helix-flow-aggression.ts`) → `helixContribution` returned `direction: "bullish"` while the very same object's own `direction` field said `"bearish"` — feeding the Largo cross-product join with a fabricated agreement/disagreement. |
| **Fix** | All three now compute direction from `directionalPremium`/`directionLabel` (`helix-flow-aggression.ts`) — the SAME shared aggressor-aware helper already used elsewhere — rather than re-deriving a cruder rule locally. `helixContribution` specifically now prefers the payload's own `session.direction` when present (falling back to the call-share rule only when the field is entirely absent — an older/partial payload shape — never when it reads `"undetermined"`, which is itself a real "no measurable direction" answer that must not be second-guessed by a call-share fallback). `helix-tape-extras.ts`'s `HelixFlowRow` and `helix-thermal-compare.ts`'s `FlowTapeRow` both gained an `ask_pct` field; `scan.ts`'s call site now passes it through (the raw `flows` already carry it — confirmed via `FlowAlert.ask_pct` in `src/lib/api.ts`). `call_premium`/`put_premium` (option-type sums, a legitimate separate metric) are unchanged in all three files — only the derived `bias`/`direction`/`direction_bias` field changed. |
| **Blast radius** | `src/lib/zerodte/thesis/helix-tape-extras.ts` (+ `scan.ts` call site), `src/lib/largo/helix-thermal-compare.ts`, `src/lib/largo/contract/product-adapters.ts`. Finding 1 is live-reachable via the real 0DTE thesis-rail scan (`thesisEnv.enabled || thesisEnv.shadow`). Finding 2 is a live Largo tool result (`get_helix_vs_thermal`/peer-compare cards). Finding 3 is a live cross-product-join input (`cross-product-read.ts`). |
| **Why not caught earlier** | Finding 1: no test file existed for `helix-tape-extras.ts` at all — only `thesis-followups.test.ts` incidentally imported it, and its one existing test asserted the (broken) call-share rule as intended behavior. Finding 2: `helix-thermal-compare.test.ts`'s fixtures never carried `ask_pct`, so the naive rule always saw exactly what it expected. Finding 3: `product-adapters.test.ts` never passed a `direction` field alongside `call_pct`. |
| **Regression guard** | New/updated tests across all three files' test suites (`thesis-followups.test.ts`, `helix-thermal-compare.test.ts`, `product-adapters.test.ts`) covering: a sold-call tape reads bearish not bullish; no `ask_pct` reads undetermined/unknown rather than guessing from call share; a `mixed` session.direction maps to neutral; an `undetermined` session.direction is never second-guessed by a call_pct fallback. Confirmed **failing** pre-fix (`git stash` toggle: 8 failures) and passing post-fix (50/50 in the targeted run; 11465/11465 in the full suite). |
| **Gates** | `npx tsc --noEmit` clean · targeted suite 50/50 · full `npm test` 11465 pass / 0 fail / 2 skipped (Node 20.20.2). |
