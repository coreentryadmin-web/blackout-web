## Cross-product consensus/regime synthesis: dealer gamma posture fabricated into a bullish/bearish vote (and a market "regime") twice more, gating real PLAY/NO_TRADE decisions — FIXED

> **kind:** `FINDING`

Largo cross-product synthesis audit, focused on `src/lib/largo/contract/` and its consumers per the
Largo product contract's C6 (confidence must be omitted, never fabricated, when a product cannot
calibrate) and the standing rule that cross-product disagreement is represented, never manufactured.

| Field | Detail |
|---|---|
| **Symptom** | The *live* cross-product synthesis path (`adaptive-response-orchestrator.ts` → `extractConsensusFromTools` → `evaluateDeskRead`, wired from `enrichWithConsensus`) folded Thermal's dealer-gamma posture onto a bullish/bearish axis in **two** places, and the resulting fabricated votes fed directly into the member-facing consensus matrix (`agreement.bullish/bearish`, `verdict`) and the PLAY/WAIT/NO_TRADE gate (`regimeAlignment === "counter"` blocks PLAY; `desk-read-decision.ts`). |
| **Root cause** | Dealer gamma is not a directional measurement: short gamma amplifies a move in EITHER direction and long gamma dampens a move in EITHER direction, so mapping either onto "bullish"/"bearish" asserts something the GEX matrix never measured. This is the *exact* live P0 (#2422) that `src/lib/largo/contract/product-adapters.ts::thermalContribution` was written to fix — Thermal deliberately casts no directional vote there — but the identical anti-pattern shipped again in two files that are not part of the `contract/` module and were never touched by that fix: (1) `consensus-read-extract.ts::extractThermalRead` mapped a "positive"/"bullish" posture to `direction: "bullish"` and "negative"/"bearish" to `"bearish"`, and additionally re-derived direction from call/put wall position relative to spot; (2) `adaptive-response-orchestrator.ts::extractRegime` inferred a `"bullish"`/`"bearish"` **market regime** the same way, which then gated `regimeAlignment` (`"counter"` blocks PLAY and adds a NO_TRADE reason in `desk-read-decision.ts`). Both also read the **wrong field name** — the real payload (`GexPositioning` from `get_positioning`/`get_gex_heatmap`) has no `gamma_flip` string field (`flip` is a *numeric* strike level); the actual posture enum is `gamma_posture: "long" \| "short" \| null`. So on real production data both functions silently no-opped (comparing a number/undefined against the strings `"positive"`/`"negative"`) while still matching any payload shaped with the old field — which is exactly the shape the repo's own pre-existing test suite used, so the bug was pinned as *expected* behavior (`consensus-read-extract.test.ts` asserted `{ gamma_flip: "positive" }` counts as a real bullish vote). |
| **Why this matters** | This is precisely the corruption the Largo product contract calls out: a lane inventing a directional/confidence signal it cannot calibrate corrupts cross-product ranking non-locally. Here it did so twice — once by adding a phantom vote to the bull/bear tally that decides `verdict`/`split` for a member-facing consensus read, and once by gating a real PLAY vs NO_TRADE trade decision on a "regime" the matrix never measured. A short-gamma book (amplifies both ways) or a long-gamma book (dampens both ways) is not evidence for either side of a trade, and treating it as such can both wrongly veto a good setup (spurious "counter-regime") and wrongly wave through a bad one (spurious "aligned"). |
| **Fix** | `extractThermalRead` now reads the correct `gamma_posture` field and mirrors the already-established, already-shipped convention in `helix-thermal-compare.ts::thermalReadFromPosture` (also documented in `tool-defs.ts`'s `get_helix_thermal_compare` description): long gamma → `direction: "neutral"` (mean-reverting), short gamma → `direction: "mixed"` (amplifies both ways) — never `"bullish"`/`"bearish"`. Wall proximity is now reported only as text in `basis` (evidence), never folded back into `direction`. `extractRegime` no longer infers any regime from GEX posture at all — there is no honest way to derive a directional market regime from a non-directional signal, so it now only honors an explicit `get_market_regime` tool result and otherwise returns `undefined` (so `regimeAlignment` correctly falls back to `"neutral"`, gating nothing on a phantom signal). |
| **Blast radius** | Two files sharing one root cause: `src/lib/largo/consensus-read-extract.ts` (`extractThermalRead`, feeds `agreement.bullish/bearish/verdict` and the desk-read-decision's `bullishVote`/`bearishVote`/`consensusStrength` inputs) and `src/lib/largo/adaptive-response-orchestrator.ts` (`extractRegime`, feeds `regimeAlignment` → the PLAY gate and a NO_TRADE reason). `src/lib/largo/contract/product-adapters.ts` was already correct (the P0 #2422 fix) and untouched. |
| **Fix rationale** | Matched the ALREADY-SHIPPED, ALREADY-DOCUMENTED convention (`helix-thermal-compare.ts`, `tool-defs.ts`) rather than inventing a third mapping — "neutral"/"mixed" is the terminology the rest of the product surface already uses for long/short gamma, so this makes the two duplicate implementations consistent with the one that was already fixed, instead of just silencing this one differently. Deliberately left `extractRegime` with NO GEX-derived fallback rather than trying to map posture to a "counter/aligned/neutral" 3-way itself — any such mapping would still be asserting a direction the data doesn't carry; only an explicit, real `get_market_regime` tool result is honest evidence of "regime." |
| **Why not caught earlier** | No test exercised the real field name (`gamma_posture`) at all — the one existing test for the near-even-split guard was itself built around the bogus `gamma_flip: "positive"` shape, so it *codified* the bug as intended behavior rather than catching it. There is no test file for `adaptive-response-orchestrator.ts`'s `extractRegime` prior to this fix. |
| **Regression guard** | `consensus-read-extract.test.ts`: new test asserts `gamma_posture: "long"` → `"neutral"` (never bullish), `gamma_posture: "short"` → `"mixed"` (never bearish), and the old bogus `gamma_flip: "positive"` shape no longer revives a fabricated vote; the pre-existing "genuine near-even bull/bear split" test was rewritten to use a real HELIX bullish read instead of the fabricated THERMAL one, since THERMAL can no longer be one of the two real dissenting votes. `adaptive-response-orchestrator.test.ts` (new file): asserts `extractRegime` returns `undefined` for both `gamma_posture` values and both old `gamma_flip` string values, and still honors an explicit `get_market_regime` result. |
| **Gates** | git-stash red/green proof (new tests fail — including a real `TypeError` from `extractRegime` not being exported — against the pre-fix code, pass against the fix) · `npx tsc --noEmit` clean (Node 20.20.2) · targeted suite green: `consensus-read-extract.test.ts`, `adaptive-response-orchestrator.test.ts`, `contract/cross-product.test.ts`, `contract/cross-product-read.test.ts`, `contract/product-adapters.test.ts`, `contract/product-read.test.ts`, `helix-thermal-compare.test.ts` — 76/76 pass. Full `npm test` timed out at 2 minutes in this sandbox (unrelated to this change); CI runs it in full. |
