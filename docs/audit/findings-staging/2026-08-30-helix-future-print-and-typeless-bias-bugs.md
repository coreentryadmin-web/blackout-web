## Helix: unguarded future-dated prints inflate hit-counts/rankings; `printBias` fabricates a side for typeless prints — FIXED

Follow-up to the SPX Slayer product audit (PR #3192). Continuing the user's "check product by
product" sweep, next product: Helix (options-flow/dark-pool signal engine). Found via a
read-against-tests pass over Helix's core files, each bug independently confirmed by hand against
the live source (not taken on the subagent's word) with a constructed repro run under
`node --import tsx --test` on Node 20.

| Field | Detail |
|---|---|
| **Symptom** | (1) `countMatchingContractHits` (`helix-strike-leaders.ts`) and `alertsInWindow` (`helix-top-prints.ts`) both compute freshness as `nowMs - ms <= windowMs` with no lower bound — a future-dated/garbage timestamp makes the subtraction negative, which trivially satisfies `<= windowMs`, so the print is counted as "in the last 15 min." (2) `printBias` (`helix-print-detail.ts`) derives `isCall` as `option_type?.toUpperCase() === "CALL"`; for any non-CALL value — including a missing/typeless `option_type`, the documented "typeless print" case (HELIX-MAP §6) — `isCall` is `false`, which routes into the PUT branch and returns a fabricated `bullish`/`bearish` label instead of `neutral`. |
| **Root cause** | Both are instances of a bug class already found and fixed elsewhere in the same file family but never propagated to these siblings: (1) an unbounded freshness/age check that the codebase already patched in `detectVelocitySpikes`/`detectSplitFlow` via `signalWindowAgeMs`/`FUTURE_PRINT_TOLERANCE_MS` (`helix-signal-detection.ts`) — that guard was never reused by `helix-strike-leaders.ts`/`helix-top-prints.ts`, which reimplemented the same window check independently and without the guard; (2) a boolean derived from "is it CALL" used as a proxy for "is it not PUT" — `flowDirection` in `helix-flow-aggression.ts` was built specifically to close this exact conflation (`type !== "CALL" && type !== "PUT" -> undetermined`), but `printBias` predates/duplicates that logic and never got the same check. |
| **Why this matters** | (1) `countMatchingContractHits` feeds the member-visible "N hits in last 15 min" line on Top Prints/Strike Stacks; `alertsInWindow` (via `selectTopPrints`) both inflates the ranked pool with a stale/garbage print and can flip `sessionFallback` from `true` (honest "tape is quiet, these are stale leaders") to `false` (implying a real recent print exists) when none does. (2) `printBias` backs the Contract Drilldown Drawer's bias display AND `helix-session-correlation.ts`'s leader/follower correlation, which filters on `bias === "neutral"` specifically to exclude unreadable prints — a typeless print silently passing through as `bullish`/`bearish` defeats that filter and corrupts the correlation. |
| **Fix** | `countMatchingContractHits` and `alertsInWindow` now compute age via the shared `signalWindowAgeMs(ms, nowMs)` (returns `null` for anything more than `FUTURE_PRINT_TOLERANCE_MS` ahead of `nowMs`) instead of a raw subtraction, then compare that age to the window — same pattern as `detectVelocitySpikes`/`detectSplitFlow`. `printBias` now checks `type !== "CALL" && type !== "PUT" -> "neutral"` before branching on `isCall`, mirroring `flowDirection`. |
| **Blast radius** | `helix-strike-leaders.ts` (`countMatchingContractHits`), `helix-top-prints.ts` (`alertsInWindow`/`selectTopPrints`), `helix-print-detail.ts` (`printBias`) and its two callers (`ContractDrilldownDrawer.tsx`, `helix-session-correlation.ts`). No other call sites of any of the three functions. |
| **Why not caught earlier** | Every existing test for these three functions only ever exercised well-formed, past-dated inputs (`countMatchingContractHits`'s own tests cover expiry-format variants, half-dollar-strike collision, tape_time_estimated fallback, and a null-strike guard — but never a future timestamp; `helix-top-prints.test.ts` never exercised a future timestamp either; `printBias`'s existing test only ever passed `"CALL"`/`"PUT"`, never a missing/blank/unknown type) — same shape of gap as the SPX Slayer bugs: a branch with zero coverage shipped silently. |
| **Regression guard** | Added: `countMatchingContractHits rejects a future-dated print instead of counting it as a hit` (`helix-strike-leaders.test.ts`); `a future-dated print does not count as in-window (must not falsely clear sessionFallback)` (`helix-top-prints.test.ts`); `printBias returns neutral for a typeless/malformed print instead of fabricating a PUT read` (`helix-print-detail.test.ts`). All fail against the pre-fix code and pass post-fix. |
| **Gates** | `npx tsc --noEmit` clean. `node --import tsx --test` on the three touched files: 17/17 pass. Full `npm test` run in progress at time of writing (Node 20). |
| **Status** | FIXED — PR pending. |
