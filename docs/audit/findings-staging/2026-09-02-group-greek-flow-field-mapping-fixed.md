## 2026-09-02 — [FINDING, P2 SPX Slayer/Largo/Night Hawk data-correctness] `summarizeGroupGreekFlow`/`summarizeTickerGreekFlow` field-name mismatch fixed — dealer greek-flow signal was silently dead everywhere it's used — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What this resolves** | The 2026-08-29 entry `[FINDING, P2 SPX Slayer/Largo data-correctness] summarizeGroupGreekFlow reads field names that don't exist in the real UW response — always returns null — OPEN`, which characterized the bug but deliberately left the fix for a follow-up requiring "a real design decision... a product-facing calibration call." This entry makes that call and ships the fix. |
| **Root cause (as previously found)** | `summarizeGroupGreekFlow` (`src/lib/group-greek-flow-summary.ts`) looked up `net_delta`/`delta`/`net_deltas` and `net_gamma`/`gamma`/`net_gex`/`gex` on each UW group-flow row. The real `fetchUwGroupGreekFlow("mag7")` response carries none of those keys — its real fields are `dir_delta_flow` (signed net delta), `total_delta_flow` (a magnitude/activity sum, not signed), and no gamma field whatsoever. Every real call computed `0`/`0` and returned `null`. |
| **Second instance found while fixing (blast radius wider than originally scoped)** | `summarizeTickerGreekFlow` (`src/features/nighthawk/lib/dossier.ts`) has the IDENTICAL bug against UW's *per-ticker* `/api/stock/{ticker}/greek-flow` endpoint — confirmed live 2026-09-02 (`fetchUwGreekFlow("AAPL")`, real response: `dir_delta_flow`/`total_delta_flow`/`dir_vega_flow`/`total_vega_flow`, no gamma field). This function backs `scorer.ts`'s `scoreCandidate` dealer-greek-flow-alignment bonus (`+3`/`-1` on Night Hawk candidate scoring) — that bonus branch (`src/features/nighthawk/lib/scorer.ts:685-692`) reads `gf.bias`/`gf.row_count`, both of which were unreachable because `gf` (=`dossier.greek_flow`) was always `null`. **The dealer greek-flow alignment bonus has never fired for a single Night Hawk candidate in production.** |
| **The product decision (per the OPEN entry's own "Suggested next step")** | Two calls: (1) map net-delta to `dir_delta_flow` (the real signed/"directional" field) rather than `total_delta_flow` (a magnitude sum — same-row evidence: `dir_delta_flow≈308K` vs `total_delta_flow≈1.58M` on the identical bar, confirming `total_*` is not signed net and would misstate both magnitude and, on some rows, sign). (2) `net_gamma` becomes `number \| null` — `null` when the data source carries no gamma field at all, never a fabricated `0`. This follows the same rule the Largo product contract already states for `confidence`: omission is honest, fabrication is not — a `0` here would read as "measured, dealer gamma flat" instead of "this data source cannot calibrate gamma." |
| **Fix** | `src/lib/group-greek-flow-summary.ts`: added `dir_delta_flow` to the delta-key lookup; added `numPresent()` to distinguish "field absent on every row" from "field present and summed to zero"; `net_gamma` is `null` when never present; bias is now delta-only when gamma is unmeasured (previously `netGamma > 0`/`< 0` could never fire since `netGamma` was always the fabricated `0`, so this is a no-op change in practice — kept as belt-and-suspenders for any future data source that DOES carry gamma); the headline says "dealer delta flow" instead of "dealer gamma" when gamma was never measured, so a member/Largo never reads a gamma claim that wasn't made. `src/features/nighthawk/lib/dossier.ts`'s `summarizeTickerGreekFlow` got the identical fix, extracted to a new pure module `src/features/nighthawk/lib/ticker-greek-flow-summary.ts` (same reason `vector-wall-db-row.ts` exists: `dossier.ts` transitively imports `server-only` providers, which throws on a plain `tsx --test` import — the pure summarizer needed to be outside that boundary to be unit-tested at all). `src/features/nighthawk/lib/format.ts`'s `formatMag7GreekFlow` (the only direct renderer of `net_gamma`) now prints `"gamma n/a"` instead of `Math.round(null)` → `NaN`. |
| **Why not caught earlier** | Same reason the OPEN entry named: no test in the repo constructs a fixture from the REAL UW response shape for either function — `scorer-direction.test.ts`'s fixtures pass already-summarized objects straight to the scorer, never exercising the summarizer against a raw row. |
| **Regression guard** | `src/lib/group-greek-flow-summary.test.ts` (8 tests) and `src/features/nighthawk/lib/ticker-greek-flow-summary.test.ts` (5 tests), both built from the real sampled rows captured live (mag7 group-flow 2026-08-29, AAPL per-ticker 2026-09-02): summary is no longer `null` against a real row, `net_gamma` is `null` not `0`, headline never says "gamma" when ungamma'd, `total_delta_flow` is never mistaken for the signed net, and an explicit `net_gamma` field (a hypothetical future data source) is still honored. |
| **Gates** | `npx tsc --noEmit` clean · `node scripts/audit/client-server-boundary.mjs` OK (356 modules, none reach server-only) · full `npm test` **11617 pass / 0 fail / 2 skip** (Node 20.20.2, up from 11604 baseline — 13 new tests). |
| **Deliberately unchanged** | `bie/spx-desk-intel.ts`'s `mag7BriefLine` only reads `.headline`/`.bias`, never `.net_gamma` — no change needed there. `largo-live-feed.ts`'s "Mag7 dealer greek flow" section and `run-tool.ts`'s `get_group_greek_flow` tool response both consume the summary object as-is; their behavior improves automatically (a real summary instead of `null`) with no code change required on their end. |
| **Status** | FIXED. |
