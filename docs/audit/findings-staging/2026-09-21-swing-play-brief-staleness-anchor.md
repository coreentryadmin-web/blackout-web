## 2026-09-21 — [FINDING, P2 Largo/Night Hawk Swings] Swing play-brief sections independently sampled the wall clock, so two sections could disagree on the SAME "put wall" within one brief — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | Live committed SNXX swing brief (`GET /api/market/swing/play-brief?playId=SWING:SNXX:1196`, 2026-09-21): "Trade manager read"'s `confluenceCoaching` bullet cited `**Confluence 15.50** (put-wall@15.5 + max-pain, score 5.0)`, while the SAME envelope's "What to watch" section (`watchForSection`) rendered `Structural support node: put wall **10.00**`. Both trace back to the identical `vec.gexWalls.putWalls` field on the identical, single, already-fetched Vector snapshot for this ticker — a trader reading the one document sees two different numbers claiming to be "the put wall." |
| **Root cause** | `composeSwingPlayBrief` (`play-brief.ts`) samples `Date.now()` once at the top into a local `readMs`, but that value was never threaded anywhere — every downstream staleness check across `play-brief.ts`/`play-brief-intel.ts`/`play-brief-narrative.ts`/`play-brief-narrative-coaching.ts` (~20 call sites) independently calls `vectorSnapshotStale(vec, Date.now(), ...)` or `gexMatrixStale(..., Date.now())` at whatever real instant that particular section happens to compose. Compose is not instantaneous — Meridian, book-context, archetype-track-record, ticker-track-record reads all run in between — so two sections' own `Date.now()` samples can be real seconds apart within one request. When the SAME cached Vector snapshot's age sits near the 120s `VECTOR_STALE_MS` cutoff, one section's sample can land just inside the window (fresh — renders the live Vector wall) while another's lands just outside it (stale — falls back to the older, structurally different GEX-matrix `put_wall`), producing genuinely different numbers for what both sections present as one fact. |
| **Why it wasn't the already-fixed disambiguation bug** | The codebase already fixed a similarly-shaped defect twice (NRG/MU/SKHY 2026-09-13, NAIL/IONX 2026-09-14): a confluence zone citing a LOWER-RANKED wall than the single "primary" wall shown elsewhere, now disambiguated via `confluenceZoneKindsLabel`'s `kind@price` suffix. That fix is working correctly and is not what's happening here — this is a genuinely different root cause (a staleness-verdict race across independently-sampled clock reads on the SAME primary wall value), which the existing disambiguation has no way to catch because both sections believe they're reporting the primary wall, just from two different fallback tiers. |
| **Evidence** | Live SNXX brief, single fetch, 2026-09-21: "Confluence 15.50 (put-wall@15.5 …)" vs "put wall 10.00" in the same envelope. A second fetch ~60s later showed the confluence bullet disappear entirely (vec aged past the threshold for both sections by then) while "put wall 10.00" stayed unchanged — consistent with the same Vector snapshot straddling the staleness boundary across the two sections' independent clock samples, not with live data actually changing (the GEX-matrix fallback value was stable across both fetches). |
| **Fix** | Added `SwingPlayBriefContext.readMs?: number \| null` — a single canonical "now" the compose stamps ONCE (`ctx = { ...ctx, readMs: ctx.readMs ?? readMs }`, `play-brief.ts`) before any section builds. Wired the two call sites this live repro actually exercised: `watchForSection` (`play-brief-intel.ts`) now uses `ctx.readMs ?? Date.now()` instead of its own fresh `Date.now()`; `confluenceCoaching` (`play-brief-narrative-coaching.ts`) gained an optional trailing `readMs?: number` param (default `Date.now()`, so every existing call site/test keeps working unchanged) and its one live call site now passes `ctx.readMs ?? undefined`. |
| **Deliberately scoped down** | The other ~18 `Date.now()` call sites across the same four files are the identical class of latent risk (any pair of them can, in principle, straddle the same boundary the same way) but were NOT touched here — fixing all of them is a larger, mechanical-but-wide refactor (each non-`ctx`-taking helper needs a new optional `readMs` param plus its call site updated) better done as its own follow-up sweep now that the `ctx.readMs` anchor exists for future call sites to adopt, rather than folded into one PR fixing the two sites with a proven live repro. |
| **Regression guard** | `play-brief-narrative-coaching.test.ts`: `confluenceCoaching: an explicit readMs anchor (not the real wall clock) decides staleness` — proves the new param is load-bearing (same `vec`/`asOf` renders under a nearby anchor, reads as stale with no anchor supplied, i.e. the real wall clock). RED confirmed pre-fix via `git stash` (1 failure), GREEN post-fix (121/121 in the file; 400/400 across the four swing play-brief test files). |
| **Not a trading-behaviour change** | No gate, score, rail, exit rule or grading path is touched — this changes only which wall-clock instant a narrative bullet's staleness check uses, never the levels/data themselves. |
| **Status** | FIXED. |
