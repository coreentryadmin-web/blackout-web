## Note: remaining candidates surveyed but deliberately NOT changed this cycle

The same grep also turned up ~25 more `nowMs - X` / `Date.now() - X` comparisons across the codebase. Most were classified as **not vulnerable** and left untouched: same-process in-memory caches/memoization (`spx-play-claude.ts`, `discord-burst-buffer.ts`, `session-cache.ts`, Vector's various `cachedWallsAt`/`lastSuccessAtMs` checks) where the timestamp is always written by `Date.now()` in the same process shortly before it's read, so a "future" value is not reachable in practice. A handful read a server's own `as_of`/scan-completion timestamp (`ZeroDteBoard.tsx`'s `resolveZeroDteFreshness`, `zerodte-service.ts`'s `localBoardIsServable`) rather than a third-party per-print timestamp — lower-risk, same-origin clocks, deliberately left for a future pass rather than bundled into this PR. The largest remaining cluster is the raw WebSocket ingestion layer (`src/lib/ws/*` — Polygon/UW stock, options, and index sockets) reading upstream tick timestamps directly; that is real infrastructure with a much wider blast radius per file and deserves its own focused review rather than being swept into an unrelated PR — flagged here for whoever next works that layer, not attempted unilaterally.
