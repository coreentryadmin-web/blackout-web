## 2026-09-02 — [FINDING, P2 SPX Slayer] Two more UW-flow-age filters had no lower bound on print age — PB-09's surge precondition and the "HELIX sweeps" confluence factor could both fire on a future-dated flow alert — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Same recurring bug shape fixed 6x earlier this session across the Helix/Discord and 0DTE/zerodte lanes — a fresh angle grep for the pattern (`nowMs - X > threshold` / `<= threshold`, no lower bound on the timestamp) in lanes not yet swept today (SPX Slayer, Swing, BIE) turned up two more instances, both reading the same external, clock-skew-prone source (`SpxFlowBrief.alerted_at`, a UW flow alert). |
| **Symptom** | `matchPb09` (`src/features/spx/lib/playbook-shadow-matcher.ts`) computed `nowMs - alertedAt > 120_000` to decide whether a large SPX sweep counts as PB-09's qualifying "surge." `scoreHelixFlowAlignment` (`src/features/spx/lib/spx-signals.ts`) computed `nowMs - alertedAt > thirtyMinMs` to decide whether a flow counts toward the "HELIX sweeps" confluence factor's bull/bear premium skew. Both used the raw subtraction with no lower bound — a UW flow alert timestamped ahead of `now` (clock skew, or a mis-stamped print) makes the subtraction negative, which never exceeds a positive threshold, so a future-dated print was counted as the freshest possible flow instead of rejected as untrustworthy. |
| **Consequence** | `matchPb09`: `precondition_match`/`trigger_fired`/`direction` could all be set by a single bogus future-dated print, firing PB-09's playbook verdict on data that hadn't actually happened yet. `scoreHelixFlowAlignment`: a future-dated print could singlehandedly produce a ±15/±10 "HELIX sweeps" factor in `computeSpxConfluence`'s score — a real, member-facing input to SPX Slayer's BUY_CALL/BUY_PUT confluence read. |
| **Fix** | Both: replaced the raw comparison with `signalWindowAgeMs(alertedAtMs, nowMs)` — the same Helix-originated guard (60s future tolerance, absorbing ordinary clock skew while rejecting a genuinely mis-stamped print) already reused today across the Dark Pool and Largo lanes. `age == null` (future-dated beyond tolerance) or `age > threshold` (too old) both correctly exclude the row; no behavior change for any print inside the normal window. First instance of this helper being imported into the SPX lane — confirmed via grep that no existing SPX file already had this guard. |
| **Regression guard** | `playbook-shadow-matcher.test.ts`: new test `PB-09: rejects a future-dated flow alert instead of counting it as a fresh surge` — a single qualifying $1.5M SPX sweep dated 5 minutes ahead of `now` must leave `precondition_match: false`. `spx-signals.test.ts`: new test `HELIX sweeps factor: a future-dated flow alert is rejected, not counted as fresh sweep premium` — the same shape against `computeSpxConfluence`'s real `richDesk()` fixture (frozen clock via `node:test`'s `MockTimers`, matching this file's existing convention), asserting the "HELIX sweeps" factor does not fire at all (the future print is the only qualifying flow, so post-fix the factor's premium total is 0). Confirmed RED pre-fix (`git stash` both source files, keep the tests: both new tests fail) and GREEN post-fix (31/31 across both files). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test` (the correct entrypoint, not direct `node --test`): **11798 pass / 0 fail / 2 skipped**. |
