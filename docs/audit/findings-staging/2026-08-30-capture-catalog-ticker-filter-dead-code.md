## 2026-08-30 — [FINDING, P3 X-Content] `searchCaptureCatalog`'s `ticker` filter was dead code — always returned every entry — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | `searchCaptureCatalog({ ticker })` (`src/lib/x-intel/capture-catalog.ts`) is documented as a "tag/franchise/ticker filter" for story planning, but the `ticker` argument had zero effect — every call returned the full 179-entry `VISUAL_CAPTURE_CATALOG` regardless of what ticker was passed, including a ticker that appears nowhere in the catalog. |
| **Root cause** | Inside the `if (opts.ticker)` block, the function computed `idHit` and `defaultTicker`, then nested two more `if` blocks whose bodies were either empty (`/* keep — param override allowed */`) or contained only a comment (`// still allow generic entries`) — **no branch anywhere in the block ever called `return false`**. Execution always fell through to the unconditional `return true;` at the end of the outer `.filter()` callback, so the ticker check computed values and reasoned about them in comments but never acted on the result. |
| **Concrete repro** | Verified live in-process: `searchCaptureCatalog({ ticker: 'NVDA' }).length` → 179 (full catalog). `searchCaptureCatalog({ ticker: 'ZZZNOPE' }).length` → 179 — a ticker string that matches no entry's id, no default ticker param, and no `spx_only` flag still returned everything. |
| **Blast radius** | `searchCaptureCatalog` has no other caller anywhere in the repo today (confirmed via repo-wide grep, both before and after the fix), so nothing in the live pipeline was silently corrupted by this. It is, however, the one function the x-intel content-planning workflow's own docstring points to for scoping a screenshot search to one ticker — any future caller (an admin tool, an agent script, a new PR) would have silently gotten the unfiltered catalog back instead of a ticker-scoped subset, with no error or empty-result signal to notice by. |
| **Fix** | Replaced the dead nested-if scaffolding with the single explicit exclusion the original comments were clearly reasoning toward: an entry is excluded only when it has **no** ticker param (no override path), its id doesn't mention the searched ticker, its default ticker param (if the entry has one — none here) doesn't match, and it isn't the `spx_only` catch-all. Any entry with a `ticker` param stays in scope regardless of its default value, since a default is a placeholder the caller can override at generation time, not a lock — this mirrors the "still allow generic entries" / "keep — param override allowed" comments already in the removed code, just with the return statement that was missing. |
| **Fix rationale** | The removed code's own comments describe exactly this intent (id-hit, default-match, `spx_only`, and "param override allowed" are all real reasons to KEEP an entry) — so the fix is a direct translation of the already-written reasoning into one `if (...) return false;`, not a reinterpretation of what the filter should do. |
| **Why not caught earlier** | `capture-catalog.test.ts` had one test for `searchCaptureCatalog` covering `product`/`story_tag`/`franchise`, but no test ever called it with `ticker` — so the always-`true` fallthrough, which is a no-op exactly when `opts.ticker` is unset, never had a fixture that could observe the missing behavior. |
| **Regression guard** | Five new tests: an unmatched ticker must narrow the result (and every surviving entry must have an override path — a ticker param or `spx_only`); a specific non-generic entry with no override path is excluded by a mismatched ticker; an id-hit entry survives even with no ticker param; every `spx_only` entry survives any ticker search; a generic entry whose default ticker param doesn't match the search is still kept (override-allowed case). All five confirmed **failing** against the pre-fix code (`git stash` toggle: 2/13 failures — the id-hit and spx_only cases already passed by coincidence since `return true` never excludes anything) and passing post-fix. |
| **Gates** | `npx tsc --noEmit` clean · `npx eslint` clean on both touched files · `capture-catalog.test.ts` 13/13 pass · full `npm test` **11424 pass / 0 fail / 2 skipped** (Node 20.20.2). |
| **Status** | FIXED |
