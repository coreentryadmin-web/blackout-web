## 2026-09-03 — [FINDING, P2 performance/correctness, marketing/research] `research/gamma-levels/[ticker]`'s bar loader swallowed Next's `DynamicServerError` — narrow re-throw guard added — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Follow-up to `2026-09-03-research-gamma-levels-dynamic-server-usage-cache-poison.md` (this session, written up but deliberately not fixed there — the writer flagged it OPEN pending an owning-lane architecture decision). That entry root-caused, via direct code read (no live occurrence confirmed at the time — CloudWatch showed 0 hits for this route over 14 days, versus 23 confirmed hits on the pre-fix homepage as the control proving the search methodology actually catches a real occurrence), that `research/gamma-levels/[ticker]` has the SAME structural shape as the homepage bug #3383 fixed: an ISR page (`revalidate`, no `dynamic = "force-dynamic"`) whose `loadWindowBars` (`src/lib/research/gamma-levels.ts`) calls Polygon through `polygonGet` (`cache: "no-store"`), and whose own broad `try/catch` swallows Next's `DynamicServerError` bailout identically to a real Polygon failure, then caches the resulting empty-bars result for 1 hour (`CACHE_TTL_SEC`). |
| **Why this gets a narrow fix (unlike the parent finding)** | The parent finding correctly deferred the *bigger* architectural decision (cache-only-reader-with-pre-warm vs. `force-dynamic`, the pattern #3383 used) as out of scope for a write-up-only PR, since neither a pre-warm cron nor an already-dynamic caller exists for this low-traffic SEO route to absorb that redesign. But it also named a **narrower, self-contained alternative**: a scoped re-throw guard in `loadWindowBars`'s catch that lets Next's own bailout machinery handle the `DynamicServerError` correctly (falling the route back to dynamic rendering, as Next is designed to do) instead of swallowing it into a false "Polygon failed" branch. That fix requires no new infrastructure and changes nothing about the page's ISR/ caching architecture otherwise — worth doing on its own, separate from the larger open architecture question. |
| **Fix** | `loadWindowBars`'s catch block now checks `err instanceof Error && (err as { digest?: unknown }).digest === "DYNAMIC_SERVER_USAGE"` before its existing `console.warn` + empty-Map fallback, and re-throws when true. `"DYNAMIC_SERVER_USAGE"` is the real digest value Next.js stamps on `DynamicServerError` — confirmed by reading `node_modules/next/dist/client/components/hooks-server-context.js` against the installed Next 15.5.23, not assumed from memory. Deliberately duck-typed rather than importing Next's internal `hooks-server-context` module (`isDynamicServerError`) — that module is not part of Next's public API surface and importing from `next/dist/...` is fragile across Next version bumps; the digest string is the stable, documented signal (`err.digest`) other Next.js codebases commonly check this same way. |
| **Blast radius** | `loadWindowBars` is called once, from `loadGammaLevelsResearch` via `Promise.all` with no enclosing try/catch — so a re-thrown `DynamicServerError` propagates cleanly up through `loadGammaLevelsResearch`, through the page/`generateMetadata` call sites, and to Next itself, without ever reaching the `sharedCacheSet(cacheKey, research, CACHE_TTL_SEC)` call (line 229) that would have persisted the poisoned result. Confirmed via `grep -rln "loadGammaLevelsResearch\|research:gamma-levels"` that this loader has exactly one reader and one cache key — no other consumer to check. The sibling `loadWindowSamples` (Postgres via `dbQuery`, not `fetch`) cannot trip this bailout and was correctly left untouched — only `fetch`-backed code paths can throw a `DynamicServerError`. |
| **Regression guard** | `gamma-levels-dynamic-server-usage.test.ts` (new): mocks `../db`, `../shared-cache`, `../providers/polygon`, and `server-only` (this codebase's established convention for testing a `"server-only"`-guarded module under plain `node --test`), then asserts `loadGammaLevelsResearch` (1) re-throws a synthetic `DynamicServerError` (digest `DYNAMIC_SERVER_USAGE`) instance unchanged, and (2) still swallows a genuine Polygon failure and returns a valid degraded result. Confirmed RED pre-fix (`git stash` the source file, keep the test: 1/2 fails — exactly the re-throw assertion, with the caught-and-swallowed error visibly carrying `digest: 'DYNAMIC_SERVER_USAGE'` in the pre-fix log line) and GREEN post-fix (2/2). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: see PR for the run result. |
| **Status** | FIXED |
