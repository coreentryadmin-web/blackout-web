## 2026-10-14 — [Ask Largo / Swing] G-S6 confluence diagnostic could render a passing-shaped label inside a sentence explaining why entry was still blocked — FIXED

> **kind:** `FINDING`

### Root cause

Caught via live verification of #5987 (the same-day fix that threaded `signalKinds`/`archetype`
into the G-S6 confluence gate reason): live AVGO repro — a served WATCH row carried
`commitGateBlockedBy: ["gate:G-S6:confluence"]` (stamped at the last discovery scan) alongside
`signalKinds: [CATALYST, FLOW, POSITIONING, STRUCTURE, VECTOR]` (5 kinds). Recomputing the
diagnostic against those 5 kinds for a `SECTOR_ROTATION` archetype (requires 3) produced a
PASSING-shaped label: `"5/3 kinds agree (CATALYST+FLOW+POSITIONING+STRUCTURE+VECTOR)"` — rendered
directly inside the sentence explaining why entry was still blocked:

> **g_s6_confluence**: Independent signal confluence below commit threshold — 5/3 kinds agree
> (CATALYST+FLOW+POSITIONING+STRUCTURE+VECTOR).

A trader reading this sees a passing confluence count next to a live WAIT verdict — self-
contradictory. Two real gaps can produce this disagreement: (1) `commitGateBlockedBy` is stamped
once per discovery scan (`stampCommitGateBlocksOnPlays`, `discovery.ts`) while the displayed
`signalKinds` can keep accumulating between scans, so the block can be genuinely stale relative to
the live kind count; (2) `commitGateBlocksForVerdict`'s own recompute only type-filters
`signalKinds` (`DISCOVERY_PATH_KINDS`) and never replicates `discoveryPathsForConfluence`'s
POSITIONING-direction-mismatch drop that the real, authoritative gate evaluation applies — so even
a same-moment recompute can disagree with the real gate's own count.

### Fix

The enrichment now only trusts its recomputed label when the recompute AGREES the gate should
still be failing (`verdict && !verdict.pass`). When the recompute disagrees (shows a passing count
next to a live block), it falls back to the prior flat text — never asserting a passing-sounding
count next to a block that's actively still in effect. This is a conservative guard: it doesn't
require fully resolving which of the two root causes fired in a given instance, only that the
enrichment never contradicts the verdict it's attached to.

### Blast radius

`src/lib/swing/entry-verdict.ts` only — same single `commitGateBlocksForVerdict` function #5987
added. No gate/commit logic touched.

### Test

New test: a 5-kind/SECTOR_ROTATION scenario (the exact AVGO shape) asserts the flat fallback text,
not a passing-shaped label. Full swing suite: 1765/1765 pass. `tsc --noEmit` clean.
