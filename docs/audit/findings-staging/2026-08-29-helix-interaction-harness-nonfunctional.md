## 2026-08-29 — [FINDING, P2 Helix ops] The HELIX Phase 1 "Item 7" interaction harness was completely non-functional — every claimed capability was untested against a live page — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | `scripts/audit/helix-interaction-audit.mjs` (merged in PR #2841, marked "FRAMEWORK COMPLETE — ready for deployment" in `docs/audit/HELIX-PHASE1-COMPLETION-STATUS.md` and `docs/audit/FINDINGS.md`) crashed on its very first invocation: `browser.newContext: viewport.width: expected integer, got float NaN`. It had never actually been run against a live page before being marked ready. |
| **Root cause** | Six independent, compounding bugs, each of which alone was enough to make the script produce a wrong or fabricated verdict: (1) `viewport: { width, height }` was passed as an object to `createTunneledContext`, which parses viewport as a `"WxH"` STRING via `.split("x")` — an object stringifies to `"[object Object]"`, which contains no `"x"`, so the split yielded a `NaN` field and `browser.newContext` rejected it outright. (2) The call destructured `{ browser, context }` from `createTunneledContext`, which actually returns `{ browser, ctx, counts }` — `context` was always `undefined`. (3) `cookie` was never passed into `createTunneledContext` at all, and `mintClerkPremiumSession({ email, phone })` was called with parameters that function does not accept (`appUrl` — used to build the FAPI ticket exchange's Origin/Referer headers — was never supplied; there is no `phone` param, the function generates its own per-run identity) and its result was read as `user.session` (a field that does not exist — the real field is `cookieHeader`). Even past the NaN crash, the harness would have authenticated nothing and audited the logged-out page. (4) `page.goto(..., { waitUntil: "networkidle2" })` used a Puppeteer-only value; Playwright accepts only `load\|domcontentloaded\|networkidle\|commit` and rejects the rest. (5) The PAGE-LOADED gate matched `[class*='PageShell'], [class*='Shell']` — case-sensitive substring selectors against class names that do not exist: `PageShell.tsx` renders lowercase `page-shell`, so this gate could never pass on ANY page, healthy or broken, and would have reported `HARNESS` on every future run forever even after bugs 1-4 were fixed. (6) All five `PANELS` entries and the freshness check used `[class*='<ComponentName>']` selectors (e.g. `[class*='Velocity']`) that assumed the rendered CSS class mirrors the React component's name — this codebase's actual convention is shared/generic classes (`flow-panel-title`, `t-label`, `.helix-tape-status-meta`) carrying no per-component identity, so all five selectors matched nothing on a live, fully healthy page. `strike_stacks`'s own display name was also wrong — the real panel title is "Top Strikes", not "Stacked Hits". |
| **Two further defects surfaced once the plumbing worked and the script could reach a real page** | (7) `checkPanelInteractivity` etc. ran immediately after `domcontentloaded`, before HELIX's `FlowFeed` (a `next/dynamic` import with `ssr:false`, `HelixPageShell.tsx`) had hydrated past its loading skeleton — MEASURED live: `.helix-tape` absent at `domcontentloaded`, present ~5s later. Every check ran against the skeleton. (8) Three of the five listed panels (`velocity_radar`, `split_flow`, `route_breakdown`) render inside FlowFeed.tsx's "More panels" overlay `<Modal open={showMorePanels}>`, `showMorePanels` defaulting to `false` — they are not in the DOM at all until that button is clicked, independent of any selector correctness. |
| **User/product impact** | None directly — this harness had never successfully completed a run, so no false verdict had yet reached anyone. The impact is entirely on the certification record: Items 7 was reported "code-complete, ready for deployment" when the code could not execute at all, and even a syntactically-fixed version (bugs 1-6 only) would have reported every panel and the freshness indicator missing on a perfectly healthy production page — a false RED that reads as a real regression, which is worse than the crash it replaces. |
| **Why not caught earlier** | The harness was authored and merged without ever being executed against a live target — every selector was a plausible guess (component name → CSS class) rather than a read of the actual rendered markup, and the call-site mismatches (bugs 2, 3) are exactly the kind of thing a single live run catches immediately, which is why fixing bug 1 alone exposed bugs 2-8 in sequence, one per re-run. |
| **Fix** | `scripts/audit/helix-interaction-audit.mjs`: viewport now passed as `"1440x900"` (the string format the shared tunnel lib expects); `ctx` (not `context`) is destructured and closed; `cookie`/`url` are forwarded into `createTunneledContext`; `mintClerkPremiumSession({ appUrl: BASE })` called correctly, `user.skip` checked, `user.cookieHeader` used as the cookie; `waitUntil` changed to `"domcontentloaded"`; the PAGE-LOADED gate now checks `.helix-page-shell, .page-shell` (the real classes `HelixPageShell.tsx`/`PageShell.tsx` render); a new `page.waitForSelector(".helix-tape", { timeout: 15_000 })` gate waits for the tape to hydrate past its skeleton before any check runs; the "More panels" button (`getByRole("button", { name: /more panels/i })`) is clicked and its modal awaited before panel checks; `PANELS` and the freshness/truncation checks now match real markup — `.helix-tape` (class selector) for the tape, and exact header-text matches (`"Velocity Radar"`, `"Split Flow Radar"`, `"Route Breakdown"`, `"Top Strikes"`) against the shared `.flow-panel-title`/`.t-label` classes for the rest, read from each component's actual JSX (`VelocityRadar.tsx`, `SplitFlowRadar.tsx`, `RouteBreakdown.tsx`, `StrikeStackDetector.tsx`) rather than guessed; `.helix-tape-status-meta` (`HelixCommandBar.tsx`) for the freshness indicator. |
| **Fix rationale** | Every selector was corrected by reading the component that actually renders it, not by pattern-matching a plausible-looking class name a second time — the failure mode being fixed here is exactly "a selector that looks right and was never checked against real output." Kept the existing (admittedly shallow — 3 of the 10 documented capabilities: OVERLAP, CLIP, TAP TARGET, PANEL STATE, KEYBOARD, DEEP LINK, and full NETWORK/DATA-FLOW cross-checks are still unimplemented, only PANEL PRESENCE/VISIBLE, a weak TRUNCATION count check, and CONSOLE-error collection exist) check scope unchanged — implementing the other seven documented-but-missing checks is a separate, much larger feature-build, not a bug fix, and is called out here rather than silently left unfixed-and-unmentioned. No test file exists for this class of file in the audit toolkit (matches `meridian-interaction-audit.mjs` and its siblings — live Playwright orchestration is proven correct by a live, repeatable run, not a unit test); confirmed via three consecutive live runs against production, all `Status: GREEN`, exit code 0, zero console errors, no leaked browser/tunnel processes after cleanup. |
| **Blast radius** | Single file, `scripts/audit/helix-interaction-audit.mjs`. No product code touched, no other harness shares this file. |
