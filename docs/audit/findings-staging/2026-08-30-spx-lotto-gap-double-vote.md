## SPX Slayer: a qualifying gap silently occupied 2 of the 3 required lotto-direction votes — FIXED

> **kind:** `FINDING`

A dedicated SPX Slayer bug-hunt pass (this product surface had only one prior fix today, the
HELIX-sweep direction bug in PR #3206, but no full dedicated audit).

| Field | Detail |
|---|---|
| **Symptom** | `evaluateLottoCatalysts` (`src/features/spx/lib/spx-lotto-catalyst.ts`) requires `playLottoMinDirectionSignals()` (default **3**) *independent* agreeing votes and `playLottoMinDirectionWeight()` (default **3**) weight before qualifying a new SPX Lotto WATCH pick. A qualifying gap (today's SPX/SPY gap% at or above `playLottoGapMinPct()`, default 0.4%) satisfied two of those three votes by itself. |
| **Root cause** | `evaluateLottoCatalysts` computes its own independent `id: "gap"` direction signal (lines 224-239) from `gapPct(desk)`. It then separately calls `technicalDirection(desk)` (line 256) and pushes its result as a second, differently-`id`'d signal (`id: "technical"`). But `technicalDirection`'s *first* branch tested the exact same condition (`gap != null && Math.abs(gap) >= gapMin`) and returned the exact same direction off the exact same underlying evidence — today's gap% — before ever reaching its VWAP/GEX-wall/prior-close fallbacks. So whenever a qualifying gap existed, the SAME evidence was counted TWICE: once as `"gap"`, once as `"technical"`. |
| **Concrete example** | SPX gaps +2.0% (well over the 0.4% floor) with zero other catalysts. Before the fix: `direction_signals` held `[{id:"gap", weight:3}, {id:"technical", weight:3}]` — 2 votes, `longWeight=6 >= 3` — one signal short of the 3-vote bar but visibly closer, and adding just ONE more real signal (e.g. a $6M flow print) would have satisfied `longVotes>=3` on genuinely 2 independent sources, not 3. After the fix: `direction_signals` holds only `[{id:"gap"}]` — 1 vote — correctly still short of the bar with only one real signal present. |
| **Why this matters** | `evaluateLottoCatalysts` is called directly from `tryNewWatch` (`spx-lotto-engine.ts`), the entry point for every real member-facing SPX Lotto WATCH pick. The vote-count gate exists specifically to require multiple *independent* pieces of evidence before committing a lotto pick; a duplicated vote halves the real bar whenever a gap happens to be present, regardless of whether genuinely-independent confirming evidence (flow, dark pool, VIX term structure) exists. |
| **Fix** | Removed the redundant gap branch from `technicalDirection`, restricting it to the VWAP/PDH, GEX-wall, and prior-close fallbacks it was always meant to be a fallback FOR. `technicalDirection` is a module-private function with exactly one call site (inside `evaluateLottoCatalysts`), so this has no other blast radius. The already-independent `id: "gap"` signal a few lines above is unchanged and still fires normally. |
| **Blast radius** | `src/features/spx/lib/spx-lotto-catalyst.ts` only — single function, single call site. Live-reachable via the real SPX Lotto watch-creation path. |
| **Why not caught earlier** | `spx-lotto-catalyst.test.ts` only ever exercised the `"flow"` signal (a three-way UNKNOWN-premium fix from an earlier pass); no test constructed a gap-qualifying desk and inspected `direction_signals` for duplicate entries. |
| **Regression guard** | Two new tests: a qualifying gap produces exactly one `direction_signals` entry (no `"technical"` duplicate), and a lone gap (weight bar satisfied, vote bar not) correctly fails to qualify rather than silently supplying a phantom second vote. Confirmed **failing** pre-fix (`git stash` toggle: 2 failures) and passing post-fix (6/6). |
| **Gates** | `npx tsc --noEmit` clean · `spx-lotto-catalyst.test.ts` 6/6 pass · full `npm test` 11468 pass / 0 fail / 2 skipped (Node 20.20.2). |
| **Status** | FIXED |
