## 2026-10-18 — [FINDING, P3, Ask Largo swing play-brief] CLOSED-bucket `lessonsSection`'s "Executable vs mid exit" slippage bullet was dead code — `execPnlPct` can never be non-null for a CLOSED swing play — DEAD BRANCH REMOVED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Severity** | P3 (LOW) — silent, cosmetic dead code with no member-facing wrong data (the Lessons section simply renders without the bullet; no crash, no incorrect value shown). Matches the severity already assigned to this exact gap in `docs/audit/SWING-SYSTEM-CTO-AUDIT-2026-09-06.md` item #52. |
| **Trigger** | Standing Ask Largo deep-dive sub-mandate (5-engine live monitor cycle), a background Workflow deep-dive scoped to the OPEN/CLOSED-bucket play-brief sections. This is a correct independent re-discovery of a gap already catalogued 6+ weeks ago (2026-09-06) and never actioned — not a fresh finding, and the write-up cross-references the prior audit entry per that discovery's own recommendation. |
| **Root cause** | `lessonsSection` (`src/lib/swing/play-brief-intel.ts`) gated an "Executable vs mid exit ... slippage on the tape" bullet on `play.execPnlPct != null && play.exitPnlPct != null && Math.abs(play.execPnlPct - play.exitPnlPct) > 5`. `terminalPlayFromHorizon` — the function every swing `TerminalPlay` (live, pre-entry, and closed, via `terminalPlayFromClosedSwing`'s delegation) is built through — unconditionally sets `execPnlPct: status === "WATCH" \|\| status === "SKIP" \|\| status === "CLOSED" ? null : exec.pnl_pct` (`adapters.ts`), and `SwingClosedDeckSource`/`terminalPlayFromClosedSwing`'s own field list never supplies an alternate value (zero occurrences of `execPnlPct` anywhere in `closed-plays.ts`). So the null branch always wins for `status === "CLOSED"` regardless of what the caller passes in — the gate could never clear for any real closed swing position. |
| **Evidence** | Pulled all 56 real `closedDeck` entries from `GET /api/market/swing/record?days=90`: every single one has `execPnlPct: null` (field present, always null). Fetched 4 real closed-position play-briefs and grepped every "Lessons" body for "slippage"/"Executable vs mid exit" — zero matches in all 4, including on positions whose Lessons section DOES render other conditional bullets (confirming the specific gate never clears, not the whole section being empty). Cross-referenced `docs/audit/SWING-SYSTEM-CTO-AUDIT-2026-09-06.md` item #52, which documents this exact defect (same root cause, same code path, same conclusion) dated 2026-09-06 — never fixed since. RED→GREEN proven: a new regression test supplying a hand-built fixture with a non-null `execPnlPct` diverging from `exitPnlPct` by >5 (which would have fired the old gate, since the unit test calls `lessonsSection` directly rather than through the normal adapter pipeline that forces the null) failed against unmodified `main` (`git stash` isolating `play-brief-intel.ts`) and passed after the dead branch was removed. `npx tsc --noEmit` clean; full `play-brief-intel.test.ts` suite (264 tests) green. |
| **Blast radius** | One production file, one deleted branch: the `if (play.execPnlPct != null && ...)` block in `lessonsSection` (`play-brief-intel.ts`). Single call chain affected (`terminalPlayFromClosedSwing` → `terminalPlayFromHorizon`, `adapters.ts`) — no other section, desk, or bucket touched. No type/signature change — `lessonsSection`'s parameter list is unchanged by this fix. |
| **Fix rationale** | Swing has no executable-fill-vs-mid grading concept anywhere (confirmed: zero occurrences of `execPnlPct` in `closed-plays.ts`, and no "executable" grading in `src/lib/swing` outside adapter/test code borrowed from 0DTE). Fabricating one to make this bullet fire would require adding a genuine fill-price field swing doesn't track anywhere — a materially larger, separately-scoped feature, and it would violate the Largo product contract's "omission is honest, fabrication is not" rule to invent a number just to satisfy an existing bullet. Minimal correct fix: delete the dead branch, with a short in-code comment explaining why (no executable-fill concept exists today; re-add a real exec-vs-mid comparison only if/when `SwingClosedDeckSource` gains a genuine fill-price field) and a regression test pinning the intentional omission so a future refactor can't silently resurrect unreachable code. |
| **Status** | FIXED — see PR (branch `fix/swing-lessons-execpnlpct-dead-code`). |
