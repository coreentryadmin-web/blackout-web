## 2026-09-03 — [FINDING, P2 Public Gamma / SPX Slayer / Vector / Thermal] The shared GEX matrix carried no way for two products to PROVE they were reading the same compute — only `asof`, which two live reads would trivially disagree on by design — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Operator escalation (2026-09-03, same message as the homepage Gamma incident): "conflicting refresh contracts between the free Gamma Snapshot (5s TTL) and Slayer's GEX/VEX/DEX/CHARM matrix... wanting ONE canonical payload carrying `calculation_id`, `market_timestamp`, `spot_timestamp`, `chain_timestamp`, `calculated_at`, `expires_at` so Slayer/Thermal/Vector/Largo can prove they're reasoning from the same positioning state." |
| **Investigation** | The premise — that the free snapshot and Slayer's matrix are two independent computations that can disagree — does NOT hold: `fetchGexHeatmap` (`polygon-options-gex.ts`) is already the ONE shared cache-reader every product sits on top of (confirmed: the public snapshot, `getGexPositioning`, Vector's snapshot builder, and 66 files total all import from this single source; `gex-positioning.ts`'s own header comment already documents this: "a strict CACHE-READER over the shared `fetchGexHeatmap(ticker)` matrix... it NEVER hits a second upstream"). So two reads within the same 5s cache window are already byte-identical. The real gap: nothing on the payload let a consumer PROVE that without diffing every field by hand — `asof` alone describes one read's own compute time, not cross-read identity, and the existing Largo `ProductReadMeta` contract (which does carry generic freshness fields) isn't even wired into the GEX code path. |
| **Fix** | Added five additive, optional fields to the ONE shared type (`GexHeatmap` in `polygon-options-gex.ts`) at all three construction sites (main happy-path build, the UW strike-exposure fallback, and `emptyHeatmap`): `calculation_id` (`${root}:${epochMs}` — two reads with the same id are the same cache entry), `calculated_at` (same instant as `asof`, exposed under the requested name), `spot_timestamp` / `chain_timestamp` (genuinely distinct instants — spot resolves before the chain fetch completes, captured separately in the main build path), and `expires_at` (`calculated_at` + the TTL this build was cached under). Propagated verbatim (never re-derived) through `GexPositioning` (`gex-positioning.ts`, the canonical cross-tool contract 66 files already import) and through `PublicGexSnapshot` (`public-gex-snapshot-types.ts` / `public-gex-snapshot.ts`, the free lead-magnet payload explicitly named in the operator's report) — both are pass-through mappers over the same `GexHeatmap`, so this required no change to any of the 66 existing consumers; they gain the fields automatically once their upstream matrix carries them. |
| **Blast radius** | Additive-only — every existing field on `GexHeatmap`/`GexPositioning`/`PublicGexSnapshot` is untouched, so no existing consumer's behavior changes. The 5 new fields are optional (`?:`) specifically so a matrix payload sitting in a live cache entry at deploy time (built before this change) degrades to "field omitted," never a crash or a fabricated value — consistent with this codebase's "never fabricate, omit instead" convention. Not touched: the 66 individual consumer files (no code change needed), the Largo `ProductReadMeta` contract (a separate, broader contract that still isn't wired into GEX — left as a follow-up, not this fix's scope), `market_timestamp` (the operator's requested name was folded into the existing `asof`/new `calculated_at` pair rather than adding a fourth near-duplicate timestamp field). |
| **Regression guard** | `polygon-options-gex.test.ts`: new source-text test asserting `calculation_id` is stamped at all 3 construction sites and that `spot_timestamp`/`chain_timestamp` are captured as genuinely separate instants (not aliases of `asof`). `gex-positioning.test.ts`: two new tests — verbatim passthrough of all 5 fields from a heatmap that carries them, and correct omission (not fabrication) when the heatmap predates them. `public-gex-snapshot-degraded.test.ts`: new test proving the free snapshot passes the envelope through on a live read — this is the direct proof for the operator's specific ask (the free snapshot and a paid surface reading the same `calculation_id` are provably the same compute). Confirmed RED pre-fix (`git stash` the 4 source files, keep the 3 test files: 3/69 tests fail, exactly the 3 new passthrough/stamping assertions) and GREEN post-fix (69/69). |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test`: see PR for the run result. |
| **Status** | FIXED |
