## Thermal: intraday-adjusted (0DTE) GEX wall picker had no spot constraint — could serve a call wall below spot or a put wall above it — FIXED

Sixth product in the "check product by product" audit sweep (SPX Slayer #3192, Helix #3193, Vector #3194, Meridian #3195, Night Hawk #3196). Confirmed by hand against source (not taken on a subagent's word) — including the module's own test, which locked the buggy behavior in as "expected."

| Field | Detail |
|---|---|
| **Symptom** | `walls()` in `src/lib/providers/gex-intraday-adjust-core.ts` picked `call = argmax(g>0 strike)` and `put = argmin(g<0 strike)` over the front-expiry-adjusted per-strike totals with **no spot constraint** — it could report a call wall below spot or a put wall above spot (inverted resistance/support). |
| **Root cause** | This is the exact bug class the codebase already found and fixed once, in `gex-cross-validation-core.ts`'s `wallsFromStrikeTotals(strikeTotals, spot)` — that function's own doc comment documents the live 2026-08-20 measurement (AAPL/SPY/META all served an inverted wall) and states "NO FALLBACK TO THE WRONG SIDE... inventing one below spot is not [a true statement]." `gex-intraday-adjust-core.ts` reimplemented the same unconstrained scan a THIRD time in its own local `walls()` function instead of importing the already-fixed shared one — even though `spot` was already a parameter in scope at the only call site. The bug was confirmed live in the module's own test: `gex-intraday-adjust-core.test.ts` asserted `put_wall_adjusted === 105` for a fixture with `spot: 100` — strike 105 is ABOVE spot, so a "put wall" (support) there is inverted by construction, and the test had locked that inversion in as expected. |
| **Why this matters** | This view is served, not dead code: `gex-positioning.ts`'s `gexContextBlock()` (the canonical AI-prompt text) prints `call_wall_adjusted`/`put_wall_adjusted` verbatim into the text Largo can relay to a member; `spx-desk-intel.ts` folds both into the SPX desk intel level set; `largo-live-feed.ts` also reads `gex_intraday_adjusted`. On a real 0DTE session where front-expiry intraday flow pushes an above-spot strike's adjusted total net-negative (or a below-spot strike net-positive) — plausible whenever customers are heavily buying/selling one side of the front-expiry chain — Largo/BIE could state a call wall below spot or a put wall above spot for the 0DTE estimate lens, while the canonical (OI-based) `call_wall`/`put_wall` on the SAME payload stayed correctly constrained: two fields on one object, one fixed, one not. |
| **Fix** | `walls()` now delegates to the canonical `wallsFromStrikeTotals(strikeTotals, spot)` (already imported in the same file for `cumulativeGammaFlip`), taking `spot` as a required parameter. The call site already had `spot` in scope, so the only change there is passing it through. |
| **Blast radius** | `gex-intraday-adjust-core.ts` (`walls`, `gexIntradayAdjustedFrom`), `gex-positioning.ts` (`gexContextBlock` text), `spx-desk-intel.ts` (level set), `largo-live-feed.ts` (reads the same field). |
| **Why not caught earlier** | The module's own test asserted the buggy behavior as the expected result (see above) — a test that encodes a bug as a spec is worse than no test, since it actively defends the defect against a future fix. |
| **Regression guard** | Updated the two existing tests that exercised `walls()`/`gexIntradayAdjustedFrom` to assert the constrained (correct) result instead of the inverted one: `walls picks largest-positive (call) and largest-negative (put) strikes, SIDE-CONSTRAINED to spot` and `flip + walls are recomputed on the ADJUSTED totals` (now asserts `put_wall_adjusted === 95`, the correct below-spot strike, instead of `105`, the above-spot one). Both fail against the pre-fix code. |
| **Gates** | `npx tsc --noEmit` clean. `node --import tsx --experimental-test-module-mocks --test` on the touched file plus `gex-cross-validation-core.test.ts`/`gex-positioning.test.ts`/`spx-desk-intel.test.ts`: 17 + 42 = 59/59 pass (Node 20). |
| **Status** | FIXED — PR pending. |
