## Server-side dark-pool `bias` fabricated "mixed" from a field the endpoint never carries — FIXED

> **kind:** `FINDING`

Helix data-correctness audit pass, focused on the Helix flow/dark-pool intelligence lane
(`src/lib/helix/`, `src/features/helix/`, and the Helix dark-pool data source shared with Meridian,
SPX, Night Hawk and Largo), per the standing audit policy.

| Field | Detail |
|---|---|
| **Symptom** | `src/lib/providers/unusual-whales.ts`'s `darkPoolBias(call, put, total)` — the server-side classifier behind every `DarkPoolSnapshot.bias` value — returns `"mixed"` for **every ticker with any dark-pool premium at all, permanently**, regardless of whether flow actually leaned bullish, bearish, or was ever measured. |
| **Root cause** | `darkPoolBias` classifies on `call`/`put` premium, which `fetchUwDarkPool`/`fetchUwDarkPoolMarketWide` derive from `row.type ?? row.option_type` on a UW **dark-pool** print. Dark-pool prints are equity block trades, not options. VERIFIED LIVE against the real endpoints (2026-08-30, `curl /api/darkpool/recent` and `/api/darkpool/NVDA` with a live `UW_API_KEY`): every returned row carries `ticker`/`price`/`size`/`premium`/`nbbo_bid`/`nbbo_ask`/`market_center`/`sale_cond_codes`/`trade_code`/etc — **never** a `type` or `option_type` field. So `optType` is always `""`, and `call`/`put` are always **0** for a real, positive `total` — not intermittently, but as a structural fact about the endpoint. `darkPoolBias`'s branches then fall through: `call >= total*0.65`? no. `put >= total*0.65`? no. `Math.abs(call - put) < total*0.15`? `Math.abs(0-0)=0 < total*0.15`, **true for any positive `total`** → returns `"mixed"`. A confident "measured, balanced institutional flow" verdict, computed from a 0/0 split — i.e. from nothing. |
| **Why not caught earlier** | The client-side twin of this exact bug (`readDarkPoolBias` in `helix-darkpool-bias.ts`, gating the `DarkPoolPanel` buy/sell label off `side`) was already found and fixed on 2026-08-23 — but that fix covers a *different* field (`side`, buy/sell) on a *different* code path (the client `/api/market/dark-pool` route). This server-side `call`/`put` (option-type) classifier, used by a much wider set of consumers, was never revisited under the same scrutiny — no test exercised it with a realistic (zero-typed) input; the only existing coverage was `emptyDarkPoolSnapshot`'s `total<=0` branch. |
| **Evidence** | Live UW API calls (redacted key) confirm the row shape has no type/option field — see root cause. `node --import tsx --test`: added `darkPoolBias(0, 0, 2_190_000) === "neutral"` (was `"mixed"` pre-fix — confirmed RED via `git stash`, then GREEN after the fix, 19/19 pass in `unusual-whales.test.ts`). |
| **Blast radius** | `bias: "mixed"` from this function reaches: Meridian's Earnings Intel panel verbatim (`MeridianEarningsIntelPanel.tsx`: `"$X total · mixed"`, member-facing), Night Hawk's dossier text (`nighthawk/lib/format.ts`: `"bias mixed"`), and Largo's `dark_pool_bias: "mixed"` (`meridian-earnings-intel.ts`, both the report and the raw-intel path) — every one a specific, false claim about institutional call/put positioning that was never actually measured. Checked every scoring/weighting consumer for a behavior change: `nighthawk/lib/scorer.ts`'s `darkPoolBiasMatchesDirection` already treats `"neutral"` and `"mixed"` identically (both → `null` → half credit); `spx-signals.ts` excludes both (`dpBias !== "neutral" && dpBias !== "mixed"`); `spx-play-confirmations.ts` passes both (`dp === "neutral" \|\| dp === "mixed"`); `meridian-earnings-report-core.ts`'s `biasScore` scores both `0`; `spx-lotto-catalyst.ts`'s `darkPoolDirection` never reaches the `bias` check at all (its own `call+put < 500_000` gate bails first, since `call+put` is always 0). So this is a pure truthfulness fix to the **displayed/exposed claim** — zero scoring or ranking behavior change anywhere it was checked. |
| **Fix rationale** | Added a guard returning the function's own pre-existing `"neutral"` ("nothing to say") value when `call + put <= 0`, rather than falling through to the ratio branches. Reused `"neutral"` instead of inventing a new value (e.g. `"unknown"`) so every downstream type union (`"bullish" \| "bearish" \| "mixed" \| null` in `evidence-bundle-map.ts`/`legacy-bridge.ts`/`play-similarity.ts`/`scan.ts`) stays valid with no signature change — `total<=0` already produces `"neutral"` through those exact same paths today, so this only makes an already-handled state trigger under its real (much more common) cause. Exported `darkPoolBias` (previously module-private) so the fix is directly unit-testable rather than only reachable through a network+cache-mocked integration test. Deliberately left the ratio thresholds (`0.65`/`0.15`) and the genuinely-typed classification branches untouched — those are correct if UW ever adds an option-type field to this endpoint, or for a caller that does carry real typed premium. |
