## 2026-08-30 — [FINDING, P4 marketing/public-site] Homepage's `revalidate = 3600` is intermittently defeated by a nested `no-store` fetch — OPEN, write-up only

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Severity** | P4 — low frequency (8 occurrences in a 3-hour CloudWatch sample, off-peak), and Cloudflare already edge-caches `/` for up to 7200s per the existing cache-rule documented elsewhere in this file, which shields the origin from most of the practical cost. Flagged because it's a real, traceable defect with a concrete root cause, not because it's urgent. |
| **Symptom** | `/ecs/blackout-production` logs recurring `Error: Page changed from static to dynamic at runtime /, reason: no-store fetch https://api.massive.com/v2/aggs/ticker/SPY/prev` (and the `I:SPX/prev` equivalent), immediately followed by `[polygon-largo] /v2/aggs/ticker/SPY/prev failed: Dynamic server usage: Route / couldn't be rendered statically...`. Found via a live CloudWatch sweep (2026-08-30, ~01:15-04:15 UTC window): 8 matching events in 3 hours. |
| **Root cause, traced end to end** | `src/app/(marketing)/page.tsx` declares `export const revalidate = 3600` (intending hourly ISR) and calls `buildPublicGexSnapshot("SPX")` at render time. `buildPublicGexSnapshot` (`src/lib/public-gex-snapshot.ts`) wraps the real work in a 5s shared Redis cache — on a cache MISS it calls `fetchGexHeatmap("SPX")` (`src/lib/providers/polygon-options-gex.ts`), whose **last-resort spot fallback** `fetchSpotFromPrevBar` (used "when live WS + snapshot endpoints are unavailable" — line ~1218) dynamically imports and calls `fetchPreviousDayBar` from `polygon-largo.ts`, which calls the shared `polygonGet` helper — and `polygonGet` hardcodes `cache: "no-store"` on every request it makes (line 33 of `polygon.ts`). A `no-store` fetch anywhere in a route's render tree forces Next.js to abandon static/ISR rendering for that request and fall back to fully dynamic, which is exactly the logged error — the fallback itself is graceful (the page still renders correctly), but the page's own `revalidate = 3600` annotation is misleading: it does not reliably hold. |
| **Why it's intermittent, not constant** | Two layers of protection already limit how often this path executes: (1) `buildPublicGexSnapshot`'s 5s shared cache means most requests short-circuit before ever reaching a fetch; (2) `fetchSpotFromPrevBar` is explicitly a *last-resort* fallback, only reached when the primary live-WS and snapshot-endpoint paths are both unavailable. The 8-in-3h rate is consistent with low weekend-night traffic (cache expiring between visits) combined with the last-resort path firing occasionally, not with every homepage load hitting it. |
| **Why not fixed directly this cycle** | `polygonGet`'s `cache: "no-store"` is almost certainly correct for the vast majority of its callers — live member-facing desk data (Largo tools, Night Hawk, real-time quotes) genuinely must never be served stale. Changing it globally risks staling real trading data; scoping an override to just this one last-resort GEX-snapshot call path means either threading a cache-option parameter through `polygonGet`/`fetchPreviousDayBar`/`fetchSpotFromPrevBar` (a shared-infrastructure change touching a function used across many lanes) or accepting the page can never truly be static and removing the misleading `revalidate = 3600` instead — both are real design decisions for whoever owns the public/marketing site and the shared Polygon provider layer, not a call to make unilaterally in an unrelated sweep session. |
| **Two options for whoever picks this up** | (1) Give `fetchSpotFromPrevBar`'s inner fetch an explicit cache override (e.g. thread an optional `{ cache }` param down to `polygonGet` for just this call site) so the last-resort GEX spot lookup doesn't defeat the page's ISR — the freshest-price guarantee doesn't meaningfully matter for a last-resort *previous-day close* fallback anyway. (2) If ISR was never realistically achievable given the dependency chain, drop `revalidate = 3600` (or document that it's aspirational) rather than leave an annotation that silently doesn't hold. |
| **Status** | OPEN — flagged for the owning lane (public/marketing site + shared Polygon provider), no code change made |
