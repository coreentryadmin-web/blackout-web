## 2026-09-02 — [FINDING, P2 0DTE/Nighthawk] `isZeroDteMarkStale` — the canonical "every renderer must apply" freshness gate — had no lower bound on mark age, so a future-dated quote read as the freshest possible mark instead of untrustworthy — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What prompted this** | Same recurring bug shape fixed 4x earlier this session in the Helix/Discord digest lane (`contractStackHitsFromFlows`, `selectHelixDiscordDigest`, `selectDarkpoolDigestPrints`, `computeFlowStrikeStacks`) — a fresh angle grep for the pattern (`nowMs - X >`/`<=` with no lower bound) across files touched by today's new Legacy Discord bot work turned up the same shape in a completely different subsystem: 0DTE live-mark freshness. |
| **Symptom** | `isZeroDteMarkStale` (`src/lib/zerodte/marks-math.ts`) — documented in its own comment as "the staleness predicate every renderer must apply" — computed `nowMs - asOfMs > staleAfterMs` with no lower bound. A WS tick or REST snapshot timestamped AHEAD of `now` (clock skew between the quote source and the app server, or a corrupted timestamp field) makes that subtraction negative, which never exceeds a positive `staleAfterMs` — so a garbage future-dated mark read as trustworthy/fresh instead of stale. `src/features/nighthawk/lib/legacy-option-mark-row.ts` (added today for the Legacy Discord bot) additionally REIMPLEMENTED the identical unguarded check inline rather than calling the canonical helper, so it carried the same gap independently. |
| **Blast radius** | `isZeroDteMarkStale` is not a display-only nicety — it gates `PlayTerminal.tsx`, `CommandDeck.tsx`, `ZeroDteBoard.tsx` (board/UI rendering), `zerodte-service.ts` (the board payload every consumer reads), and `exit-sync.ts` (the live TRIM/HOLD/CLOSE decision engine that acts on real committed 0DTE plays). A mark that should have been rejected as untrustworthy could instead drive a real exit decision. |
| **Fix** | `isZeroDteMarkStale` now rejects a mark timestamped further ahead of `now` than a new, separate `ZERODTE_MARK_FUTURE_TOLERANCE_MS` (60s) — the same two-tier shape Helix's `signalWindowAgeMs`/`FUTURE_PRINT_TOLERANCE_MS` already uses: a tight staleness window for the backward-looking case (`ZERODTE_MARK_STALE_MS`, 5s) and a separate, more generous bound for rejecting a genuinely corrupted/future-dated timestamp, rather than conflating the two. `legacy-option-mark-row.ts`'s duplicate inline check was replaced with a call to the now-fixed canonical helper, removing both the duplication and its independent copy of the bug. |
| **Why two tiers, not a simple `Math.abs()` symmetric bound (caught by the test suite, not by inspection)** | The first version of this fix used a fully symmetric `Math.abs(nowMs - asOfMs) > staleAfterMs`. Full `npm test` caught 2 real regressions: `exit-sync.test.ts`'s "freshest mark wins" test and `zerodte-service-marks.test.ts`'s board-ledger integration test both deliberately future-date a "definitely fresh" fixture seed by **+30s**, specifically so the test stays correct even if a slow CI runner or a scheduler stall delays the real-clock check that reads it — `zerodte-service-marks.test.ts` carries a full "TIMING DISCIPLINE" comment documenting a real, previously-fixed CI flake (run 29296357116) this exact pattern exists to prevent. A tight symmetric bound at the 5s staleness threshold would flag that legitimate, load-bearing test-fixture technique as stale. Widening the future-side tolerance to 60s (matching Helix's own already-vetted value) keeps both existing tests passing with margin while still rejecting a mark claiming to be minutes ahead of `now`, which is unambiguously corrupted rather than merely "very fresh." |
| **Regression guard** | `marks-math.test.ts`: new test asserting a mark 30s ahead stays fresh (the exact fixture pattern this codebase relies on), the boundary at exactly `ZERODTE_MARK_FUTURE_TOLERANCE_MS` is fresh, and one ms further is stale. `legacy-option-mark-row.test.ts`: new test with a mark 5 minutes ahead of `now` — unambiguously beyond any legitimate skew/fixture headroom — asserting `stale: true`. **Confirmed RED pre-fix and GREEN post-fix**: `git stash` both source files (keeping the tests) → both new tests fail; `git stash pop` → all 64 tests across both files pass. |
| **Gates** | `npx tsc --noEmit` clean (Node 20.20.2). Full `npm test` (the correct entrypoint, not direct `node --test`): **11793 pass / 0 fail / 2 skipped** — including the 2 previously-broken `exit-sync.test.ts`/`zerodte-service-marks.test.ts` tests, now passing against the two-tier fix. |
| **Status** | FIXED |
