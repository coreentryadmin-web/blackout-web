## Thermal: `wallsOf()` was a fourth independent copy of the already-fixed unconstrained wall-pick bug — silently defeats `wall_broken` push alerts on SPY/SPX — FIXED

> **kind:** `FINDING`

Eleventh product-surface pass in the "check product by product" audit sweep — a second, deeper pass on Thermal after the earlier `gex-intraday-adjust-core.ts` fix (`docs/audit/findings-staging/2026-08-30-thermal-intraday-adjusted-walls-unconstrained.md`).

| Field | Detail |
|---|---|
| **Symptom** | `wallsOf()` (`src/lib/providers/polygon-options-gex.ts`) picked the strike with the largest positive net dealer gamma as the "call wall" and the largest negative as the "put wall" — anywhere in the book, with no check that the call wall sits above spot or the put wall below it. |
| **Root cause** | This is the identical "argmax anywhere" bug already found and fixed in `gex-intraday-adjust-core.ts`'s `walls()` and in the shared helper itself, `wallsFromStrikeTotals` (`gex-cross-validation-core.ts`, which documents live-measured cases of an inverted call/put wall on AAPL/SPY/META). `wallsOf` was a fourth, independent reimplementation in this file that was never updated to use the fixed helper — even though this same file already imports and correctly uses `wallsFromStrikeTotals` directly at line 989 for the base matrix scan. |
| **Why this matters** | `wallsOf`'s output feeds two live paths: (1) `computeMetricShift`'s `wall_changes` — the "the X call wall built/melted N%" narration text every Thermal panel shows — and (2) `computeGexEvents`'s `wall_broken` alert, one of only two event types that page members directly via web push (`WALL_BROKEN_TICKERS` = SPY, SPX). Concrete trace: strikes `{495: -80k, 500: +50k, 510: +30k}`, prior spot 501. The real, side-correct call wall (nearest positive-gamma strike actually above spot) is **510**; `wallsOf` picked **500** instead (bigger magnitude, but below spot — already "broken", not resistance). The `wall_broken` check (`priorSpot <= priorWalls.callWall`) then evaluates `501 <= 500` = false, so the alert **never fires** even when spot genuinely crosses the real wall at 510 — a bigger-magnitude support-side strike below spot silently defeats the resistance-break alert. The inverse also happens: a smaller, already-crossed strike below spot can fire a false "gamma resistance gave way" alert while the real, larger resistance level above spot remains fully intact. |
| **Fix** | `wallsOf` now delegates to `wallsFromStrikeTotals(strikeTotals, spot)` (added an optional `spot` parameter). Threaded the correct spot through both call sites: `computeMetricShift` now accepts an optional `spot` on its `current` param (supplied only by `computeGexShift`, since VEX/DEX/CHARM shifts have no spot-relative resistance/support concept and keep their historical unconstrained behavior via `spot: undefined`) and uses `current.spot` for the current wall, `baselineSnap.spot` (already available on every `GexHistorySnapshot`) for the earlier wall; `computeGexEvents`'s `priorWalls` now passes `prior.spot`. |
| **Blast radius** | `wallsOf`'s two call sites in `polygon-options-gex.ts`. VEX/DEX/CHARM shifts are unaffected (spot stays `undefined` there, preserving prior behavior exactly, matching `wallsFromStrikeTotals`'s own documented backward-compatible default). |
| **Why not caught earlier** | The existing `wall_broken` regression test's fixture happened to already be spot-consistent (the only positive-gamma strike in its fixture was already above spot), so it could not distinguish the constrained from the unconstrained rule. |
| **Regression guard** | New test: a fixture where the biggest-magnitude positive strike (500) sits below spot (501) and the real above-spot wall (510) is smaller — `wall_broken` must fire on the 510 crossing, not silently drop it. Confirmed **failing** against pre-fix code (`git stash` toggle) and passing post-fix. |
| **Gates** | `npx tsc --noEmit` clean · `polygon-options-gex.test.ts` 55/55 pass (Node 20.20.2) · full `npm test` — see PR. |
| **Status** | FIXED |
