## Night Hawk: thesis-first POSITIONING rail was long-biased — short setups earned no VACUUM/WALL_REJECTION/short-gamma credit under mirrored geometry — FIXED

> **kind:** `FINDING`

A dedicated Night Hawk second-pass bug hunt (the product has had extensive prior coverage — see
CLAUDE.md's audit toolkit and dozens of already-fixed findings — but not a dedicated pass today).

| Field | Detail |
|---|---|
| **Symptom** | `scorePositioningRail`'s `VACUUM`/`WALL_REJECTION` archetypes, and its short-gamma `+4` bonus, only ever fired for `direction === "long"`. A short thesis candidate under **geometrically mirrored** dealer positioning — room to run down toward the put wall, or pinned just under the call wall — earned zero POSITIONING archetype credit and no short-gamma bonus, where a long candidate under the mirror-image setup earned a 74/70/76/68-range score plus a further +4. |
| **Root cause** | `detectPositioningArchetype` (`src/lib/zerodte/thesis/rails/positioning.ts`) computed `pctUp` (room toward the call wall) and a "near put wall" proximity check, both gated `&& input.direction === "long"`, with **no symmetric branch** computing `pctDown` (room toward the put wall) or "near call wall" proximity for `direction === "short"`. The short-gamma bonus (`if (input.gamma_posture === "short" && input.direction === "long") score += 4`) was gated the same way, despite dealer short-gamma amplifying a move in **either** direction — the exact "gamma is not directional, it's an amplifier" principle this repo already documents and applies correctly elsewhere (e.g. Thermal's `thermalReadFromPosture` in `helix-thermal-compare.ts`). Every sibling thesis rail (`rs.ts`, `breakout.ts`, `vol.ts`, `reversal.ts`) is already direction-symmetric — this was the one rail that wasn't. |
| **Concrete example** | `spot=100, call_wall=104, put_wall=80` (4% headroom to the call wall): `direction:"long"` → archetype `"VACUUM"` → score 74. The geometric mirror, `spot=100, call_wall=120, put_wall=96` (4% headroom to the put wall): `direction:"short"` → **no branch matched → archetype `null` → score fell to the default 50, below the `score < 52 && !archetype` cutoff → the rail returned `null` entirely** — zero evidence for a setup with equivalent real positioning support. |
| **Why this matters** | `attachThesisFirstShadow` runs on every scan pass by default (`ZERODTE_THESIS_FIRST_SHADOW` defaults to shadow-ON), and its `rail_scores`/`rank_tier`/`archetype_gate` output is already persisted into `entry_context.thesis_first` on every commit today, feeding `rank-calibration.ts`'s live calibration report and Largo's `desk_evidence` lines — so today's blast radius is asymmetrically wrong shadow/display data for short setups. `ZERODTE_THESIS_FIRST` (the full commit-gating flag) is off by default today, but the moment it flips on, `archetype-gates.ts`'s `GAMMA_BREAK` gate (which hard-requires `positioning(rail_scores) >= 55` or BLOCKs) and `MEAN_REVERSION`'s `positioning < 50` watch would apply this exact asymmetry to real commit decisions, not just calibration data. |
| **Fix** | Added the symmetric `direction === "short"` branches: `pctDown` (room toward the put wall) for VACUUM, "near call wall" proximity for WALL_REJECTION, mirroring the existing long-side math exactly. Removed the `&& input.direction === "long"` restriction from the short-gamma bonus so it applies to both directions, consistent with gamma being a directionally-neutral amplifier. `WALL_BREAK` and `GAMMA_FLIP` (already direction-agnostic) are unchanged. |
| **Blast radius** | `src/lib/zerodte/thesis/rails/positioning.ts` only — single function (`detectPositioningArchetype`) and its one caller (`scorePositioningRail`), used by `legacy-bridge.ts`'s single call site for `PIN`-origin setups. Long-direction behavior is byte-identical (verified by the existing long-path assertions in the new test file). |
| **Why not caught earlier** | No test file existed for `positioning.ts` at all — nothing exercised a short-direction VACUUM/WALL_REJECTION scenario or the short-gamma bonus symmetry. |
| **Regression guard** | New `positioning.test.ts` (6 tests): long VACUUM/WALL_REJECTION (baseline, unchanged); short VACUUM/WALL_REJECTION under mirrored geometry (the fix); `scorePositioningRail` no longer silently drops a short VACUUM setup to a null rail hit; the short-gamma bonus scores identically for long and short. Confirmed **failing** pre-fix (`git stash` toggle: 4/6 failures) and passing post-fix (6/6). |
| **Gates** | `npx tsc --noEmit` clean · `positioning.test.ts` 6/6 pass · full `npm test` 11490 pass / 0 fail / 2 skipped (Node 20.20.2). |
| **Status** | FIXED |
