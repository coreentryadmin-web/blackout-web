## Thermal: GEX Heatmap's per-expiry Key Levels row reintroduced the spot-unconstrained wall inversion — FIXED

> **kind:** `FINDING`

A second, deeper Thermal bug-hunt pass (the product's first fix today — `wallsOf` in
`polygon-options-gex.ts` was an unconstrained fourth copy of wall-finding logic, fixed by
delegating to `wallsFromStrikeTotals`, merged PR #3214 — was a *server-side* fix; this is a
*client-side* sibling of the same bug that #3214 never touched).

| Field | Detail |
|---|---|
| **Symptom** | On `/heatmap`, filtering the GEX matrix to a specific expiry (rather than "All") could render a "Call Wall" tile below spot or a "Put Wall" tile above spot — resistance already broken / support not yet reached, backwards from what the tile means. |
| **Root cause** | `GexHeatmap.tsx`'s client-side `recomputeLevels` (used only when a member scopes the matrix to a specific expiry) called `gexWallsFromStrikeTotals(totals)` — the **unconstrained** sibling of `wallsFromStrikeTotals` (same source file, `gex-cross-validation-core.ts`) — which picks the max-positive/max-negative-GEX strike **anywhere**, with no regard for which side of spot it sits on. This is the exact defect class PR #3214 fixed server-side in `computeGexRegime` (`polygon-options-gex.ts`'s `wallsOf`), and the exact class `wallsFromStrikeTotals`'s own doc comment measured live on prod (AAPL spot 312.66 served call_wall 310 — resistance BELOW price; SPY spot 763.11 served put_wall 765 — support ABOVE price; META spot 545.91 served put_wall 550) — but #3214 only touched the server path. The client's own `recomputeLevels` had a stale doc comment claiming it was "shared with the server's computeGexRegime," which became false the moment #3214 shipped without updating this file too — bug class (f), a fix landing in one copy of duplicated logic while a sibling copy silently un-fixes it. |
| **Why the unscoped view was safe** | The unscoped ("All expiries") path keeps the server's already-constrained `data.gex.call_wall`/`put_wall` directly — it never calls `recomputeLevels` at all. Only the per-expiry-**filtered** path (any time `selectedExpiries` narrows the matrix) invoked the unconstrained client recompute, so this bug was invisible on the default view and only appeared once a member filtered to a specific expiry. |
| **Blast radius** | Every UI surface fed by `filteredLevels`: the Key Levels row's Call Wall/Put Wall tiles, the vertical exposure profile's wall markers, and the depth/curve component's `callWall`/`putWall` props — all downstream of the same `recomputeLevels(filteredTotals, spot)` call. Also found: `METRIC_HELP`'s dedicated disclosure copy for exactly this "call wall below spot" / "put wall above spot" scenario is dead code — never referenced anywhere in the file or codebase — so even the intended caveat wasn't wired up to soften a wrong-side render. |
| **Fix** | Extracted `recomputeLevels` out of the component into a new pure, testable module (`src/features/thermal/lib/gex-heatmap/recompute-levels.ts`, matching the existing `per-expiry-levels.ts` pattern in the same directory for the same reason — client-safe pure derivations get their own testable file rather than living inline in the component). It now calls `wallsFromStrikeTotals(totals, spot)` (the side-constrained function, passing spot) instead of the unconstrained `gexWallsFromStrikeTotals(totals)`. `GexHeatmap.tsx` now imports the extracted function instead of defining it inline. Left the dead `METRIC_HELP` disclosure-copy issue and the dormant `gex-matrix-delta.ts` `gex_call`/`gex_put` net-vs-side mislabeling (no live consumer found) as separate, lower-priority items — not touched in this fix to keep scope to the one live, reachable defect. |
| **Why not caught earlier** | `recomputeLevels` was defined inline in a large client component (`GexHeatmap.tsx`), never extracted to a testable pure module the way `per-expiry-levels.ts`'s `gammaShareByExpiry` was for the identical reason stated in that file's own doc comment — so nothing exercised it directly, and the existing `wall-side-constraint.test.ts` only asserts the *server* matrix scan doesn't call the unconstrained function; it never looked at this file. |
| **Regression guard** | New `recompute-levels.test.ts` (5 tests): call wall constrained above spot even when a larger-magnitude strike sits below it (the exact live AAPL pattern); put wall constrained below spot even when a larger-magnitude strike sits above it (the exact live SPY pattern); no qualifying strike on a side returns `null`, never a wrong-side fallback; invalid spot returns all nulls; flip crossing math unchanged. Confirmed **failing** pre-fix (manually reverting to the unconstrained call: 3/5 failures) and passing post-fix (5/5). |
| **Gates** | `npx tsc --noEmit` clean · `recompute-levels.test.ts` 5/5 pass · full `npm test` 11482 pass / 0 fail / 2 skipped (Node 20.20.2). |
| **Status** | FIXED |
