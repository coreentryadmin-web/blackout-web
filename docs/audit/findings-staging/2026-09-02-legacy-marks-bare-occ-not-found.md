## 2026-09-02 — [FINDING, P1 correctness] Legacy edition live option marks were always null/stale — the shared REST snapshot fetcher never added the `O:` prefix Massive/Polygon requires — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What this resolves** | A new finding surfaced live 2026-09-02 by the 4-engine live monitor cycle while checking Night Hawk's Legacy digest board (`GET /api/market/nighthawk/legacy-marks`, `/edition`) for whether marks are populated on actually-open plays. Not previously logged. |
| **Root cause** | `fetchOptionsUnifiedSnapshot` (`src/lib/providers/options-snapshot.ts`) calls Massive/Polygon's `GET /v3/snapshot?ticker.any_of=<csv>` with whatever OCC strings its caller passes, unmodified. That endpoint requires the canonical `O:`-prefixed form (e.g. `O:MU260904C00930000`) — a **bare** OCC (`MU260904C00930000`, no prefix) resolves to `{"error":"NOT_FOUND"}`. But the two OCC builders this codebase uses everywhere (`buildOccContractId` in `src/lib/helix/occ-contract-id.ts`, `buildOcc` in `src/lib/ws/options-socket.ts`) deliberately return **bare** OCC — their own header comments say so explicitly, because Unusual Whales wants it bare. Only one caller, `occSymbolFromSwingRow` (`src/lib/swing/occ-from-row.ts`), was already normalizing to `O:`-prefixed before calling `fetchOptionsUnifiedSnapshot` (its own doc comment: "Returns a Massive/Polygon-style `O:` prefixed symbol"). Every other caller — including `legacy-marks/route.ts`, whose `occs` come straight from `resolveLegacyPlayOcc` → `buildOccContractId` (bare) — passed bare OCC straight through and got an unfound-ticker error row back for every single contract, every single call. |
| **Evidence** | Live production, 2026-09-02 ~18:04 UTC, RTH open: fetched the day's real Legacy edition (`GET /api/market/nighthawk/edition`, 5 open plays: MU, MRNA, META, TGTX, UBS), derived each play's real OCC via the actual `resolveLegacyPlayOcc` production function, then called `GET /api/market/nighthawk/legacy-marks?occs=<those 5 OCCs>` — every row came back `mark:null, bid:null, ask:null, asof:null, stale:true`, despite the market being open and the underlyings actively trading. Direct raw-provider proof, same OCC (`MU260904C00930000`, MU's real $930C 9/4 contract): `ticker.any_of=MU260904C00930000` → `{"error":"NOT_FOUND"}` on **both** `api.massive.com` and `api.polygon.io`; `ticker.any_of=O:MU260904C00930000` (identical contract, `O:`-prefixed) → full live quote (`bid:24.75, ask:25.75, delta:0.66, open_interest:1021`, etc.) on both. |
| **Fix** | `fetchOptionsUnifiedSnapshot` now normalizes every OCC to the required `O:`-prefixed form **only for the outgoing wire request** (new exported helper `withOccPrefix`), via a per-chunk reverse map (`normalizedOcc → caller's original string`). The returned `Map` (and every `diag` list: `unfound`/`missing`/`noQuote`) stays keyed by whatever format the **caller** originally passed — bare or `O:`-prefixed — so every existing caller's own `snaps.get(occ)` lookup keeps working unchanged with zero caller-side edits. `mapUnifiedSnapshotResult` (the per-row mapper) and the separate `getOptionSnapshot`/`setOptionSnapshots` in-mem cache are both untouched. |
| **Blast radius** | `fetchOptionsUnifiedSnapshot` is the shared snapshot fetcher for: `legacy-marks/route.ts` (this finding's trigger), `vector/contract-picks/live/route.ts`, `vector-pick-sweep.ts`, `zerodte/scan.ts`, `zerodte/live-marks.ts`, `zerodte/thesis/contract-attach.ts`, `banger-live-sync/route.ts`, and `nighthawk/option-chain-prompt.ts` (Largo's option-chain tool) — every one of these passes bare OCC (via `buildOcc`/`buildOccContractId`) and was equally affected; only `swing-active-refresh.ts` (via `occSymbolFromSwingRow`'s explicit `O:` normalization) was unaffected. Because the fix lives in the ONE shared choke point rather than each call site, all of them are corrected by this single change with no other file touched. Several of these have their OWN fallback layer (e.g. `scan.ts`/`live-marks.ts` degrade to a full-chain fetch, and WS coverage exists for actively-scanned 0DTE tickers) which is very likely why this was not previously visible as a hard product outage elsewhere — Legacy's REST snapshot is the ONE path with no such fallback for its (non-0DTE, not-necessarily-WS-subscribed) contracts, which is exactly why it surfaced there first. |
| **Fix rationale** | Fixing inside the shared function (rather than patching each of the 7 broken call sites to call `withOccPrefix`/normalize before invoking it) removes the whole class of bug at its one true root — a NEW caller written the same way `zerodte/scan.ts` or `vector-pick-sweep.ts` already are (bare OCC in) would otherwise silently reproduce this defect again. Keeping the returned map keyed by the CALLER's original string (rather than always keying by the canonical `O:`-prefixed form) was deliberate: switching every caller to expect `O:`-prefixed keys would have meant editing all 7 call sites anyway, with much larger blast radius and more surface for a second, unrelated regression — the chosen fix is provably a no-op for the one caller that was already correct (Swing) and a pure fix for the rest, verified by the new tests below. |
| **Regression guard** | 5 new tests in `src/lib/providers/options-snapshot.test.ts` (module-mocked `polygonRawJson` via `mock.module("./polygon-options-gex", ...)`, the same established pattern as `gex-positioning.test.ts`): `withOccPrefix` unit behavior; a bare OCC is sent `O:`-prefixed on the wire; the returned map is keyed by the caller's ORIGINAL bare OCC (not the canonical form); an already-`O:`-prefixed caller (Swing's convention) is unaffected; `diag.unfound`/`missing`/`noQuote` stay keyed by the caller's original OCC. Git-stash proven: reverting only `options-snapshot.ts` reproduces exactly 4 failures (the wire-format and map-key assertions — the fifth, Swing's already-correct path, still passes unchanged) against pre-fix source; restoring returns 23/23 pass. |
| **Gates** | `npx tsc --noEmit` clean (Node 20) · `options-snapshot.test.ts` 23/23 · downstream caller test files (`live-marks.test.ts`, `exit-sync.test.ts`, `scan.test.ts`, `swing/contract-ranker.test.ts`, `swing/live-plays.test.ts`) 98/98, all green — confirms the fix is a no-op for their existing (already-correct or already-mocked) behavior · full `npm test` (Node 20): **11760 pass / 0 fail / 2 skipped** (11762 total). |
| **Status** | FIXED. |
