## Vector: HELIX flow bias/conviction scoring conflated option TYPE with market direction, ignoring aggressor side — FIXED

Third product in the "check product by product" sweep (after SPX Slayer PR #3192, Helix PR #3193). Found via a read-against-tests pass over Vector's core files, confirmed by hand against the actual source (not taken on the subagent's word) with constructed repros run under `node --import tsx --test` on Node 20.

| Field | Detail |
|---|---|
| **Symptom** | Vector's HELIX-flow bias/scoring functions treated "CALL premium" as bullish and "PUT premium" as bearish purely from `option_type`, with no regard for whether the print was bought or sold: `summarizeSessionFlowBias`/`largestAlignedFlowPremium` (`vector-play-platform.ts`), `flowPremiumAtStrike`/`largestFlowPremium`/`specsForContext`'s whale-print candidate generation (`vector-play-candidates.ts`). |
| **Root cause** | This is an unfixed instance of a bug class this same codebase already found and fixed in HELIX itself: a sold call is bearish and a sold put is bullish, not the reverse (`helix-flow-aggression.ts`'s own doc comment cites a live 2026-08-23 measurement — 44.6% of tickers sign-flip between the option-type-only rule and the aggressor-aware `flowDirection` rule). Vector's own `vector-pulse.ts` (`flowAlertToPulseSignal`) already uses the correct pattern (`option_type × direction`) in the same feature folder, so the fix pattern was already proven and available — it just wasn't applied to the play-platform/candidate-scoring path. Root cause of *why* it could conflate: the wire-boundary flow print type (`PlayPlatformFlowPrint`, and its two serialization points in `use-vector-contract-picks.ts` and `contract-picks/route.ts`) never carried `ask_pct` in the first place, so the aggressor-aware helper had no way to be reached even if someone had reused it. |
| **Why this matters** | This is a direct conviction-score and contract-recommendation corruption, not just a display glitch. A sold $3M SPY call print (dealers absorbing size, actually bearish) previously: (1) read as `flowBias: "bull"` in `summarizeSessionFlowBias`, (2) added +8 to conviction for a "long" play via `platformConvictionDelta` (agreeing bias) or docked -7 from a "short" play that the real bearish flow should have supported, (3) contributed +10 more via `largestAlignedFlowPremium` misreporting it as `flowConfirmPremium` ≥ $2M, and (4) via `specsForContext`, generated an explicit top-ranked **buy-the-call** contract-pick candidate (+18 "HELIX whale print", +8 more "Mega-whale flow") at the exact strike whales were selling into — the ranked picks members act on. |
| **Fix** | Added `ask_pct?: number | null` to `PlayPlatformFlowPrint` and threaded it through both wire-boundary serialization points. All four scoring functions now gate on `flowDirection(f)` (imported from `helix-flow-aggression.ts`, reused rather than reimplemented) instead of raw `option_type`: bullish premium counts toward "long"/call-confirming signal, bearish toward "short"/put-confirming signal, and an undetermined print (no `ask_pct`, or midpoint) contributes to neither rather than being guessed from its option type. Display-only literal call/put premium totals (`callPremium`/`putPremium`, shown as "$XM calls / $YM puts") are left as a true, aggressor-independent fact — only the *bias inference* built on top of them was fixed. |
| **Blast radius** | `vector-play-platform.ts` (`summarizeSessionFlowBias`, `largestAlignedFlowPremium`), `vector-play-candidates.ts` (`flowPremiumAtStrike`, `largestFlowPremium`, `specsForContext`'s flow-whale candidate direction), `use-vector-contract-picks.ts`, `src/app/api/market/vector/contract-picks/route.ts` (`parsePlatform`). Explicitly investigated and ruled OUT of scope: `vector-pick-evidence.ts`'s `flowsAtStrike` (only surfaces raw "print at strike" facts, not an inferred bias — not the same conflation), `vector-flow-markers.ts` (its call=green/put=red marker color is a deliberate, documented visual convention matching other chart layers — not a bias claim), and `vector-flow-confluence.ts`'s `toneFromFlowSide` (confirmed dead code — zero callers anywhere in the codebase, so it currently affects nothing live; left unfixed as out of scope for this PR, flagged here for whoever wires it up). |
| **Why not caught earlier** | Every existing test for `summarizeSessionFlowBias`, `platformConvictionDelta`, `platformStarredLine`, and the "HELIX whale print" candidate test constructed prints with `option_type` only, never `ask_pct` — so every test passed regardless of which rule (type-only vs aggressor-aware) was used, and a branch that could never diverge from correct in any existing test shipped silently. Same shape of gap as the SPX Slayer and Helix findings. |
| **Regression guard** | Added: `summarizeSessionFlowBias: a SOLD call reads bearish, not bullish, from its option type alone`; `summarizeSessionFlowBias: prints with no ask_pct (undetermined direction) are excluded, never guessed`; `largestAlignedFlowPremium: a sold call must not confirm a long bias` (`vector-play-platform.test.ts`); `a SOLD call whale print does not surface as a bullish HELIX candidate` (`vector-play-candidates.test.ts`). All fail against the pre-fix code and pass post-fix. Existing tests updated to carry a determined `ask_pct` so they keep testing the intended (now-correct) behavior rather than the accidental one. |
| **Gates** | `npx tsc --noEmit` clean. `node --import tsx --test` on the four touched test files: 24 + 30 = 54/54 pass (Node 20). Full `npm test` run as secondary confirmation. |
| **Status** | FIXED — PR pending. |
