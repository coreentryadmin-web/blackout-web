## 2026-08-29 — [FINDING, P2 Helix ops] HELIX Phase 1 "Item 8" RTH measurement script was a stub that measured nothing and always exited 0 — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **Symptom** | `scripts/audit/helix-rth-measurement.mjs`, merged in PR #2841 and marked **"FRAMEWORK COMPLETE — ready for RTH execution"** in `docs/audit/HELIX-PHASE1-COMPLETION-STATUS.md` and `docs/audit/FINDINGS.md` (2026-08-24), did not measure anything. Its `measureHelix()` function returned `{ timestamp, market_phase, measurements: {} }` and printed `"This is a stub — actual implementation would call helix-tape-inventory.mjs..."` followed by a suggestion of the command a human could run manually. The `--compare` flag printed `"⚠️ --compare requires output from: node scripts/audit/helix-tape-inventory.mjs --json"` and performed no comparison. The script always exited `0`. |
| **Root cause** | The script was never implemented past a scaffold — the comment inside `measureHelix()` is honest about this ("This is a stub") but that honesty never reached the certification status doc, which recorded it as complete and ready to run. A run of the stub was indistinguishable from a run of a real, healthy measurement: both print a banner, both exit 0, and the stub's own baseline/expected-value tables (hardcoded from the 2026-08-22 weekend run) made the output look like it was reporting something, when it was just echoing constants. |
| **User/product impact** | None directly — nobody had acted on a false result, because the script had (as far as the repo history shows) never been run since being marked ready. The impact is entirely on the certification record, same shape as the sibling Item 7 finding filed alongside this one: a "framework ready" claim that was never exercised. |
| **Why not caught earlier** | Same root cause as Item 7 (filed separately, `2026-08-29-helix-interaction-harness-nonfunctional.md`): neither script had ever been executed before being marked ready. A stub that prints plausible-looking output and exits 0 is a harder failure mode to catch by inspection than a crash — there is no error to notice, only an absence of real work that reads, at a glance, like a working tool. |
| **Fix** | Rewrote `measureHelix()`'s replacement to spawn the REAL `helix-tape-inventory.mjs --json` (already a working, unit-tested harness — see `docs/audit/HELIX-MAP.md`) via `execFile`, parse its JSON, and report genuine live numbers: signal eligibility, writer group split, live route breakdown, GEX proximity, IV distribution, and real-print span. Two correctness issues found while building the real version: (1) the original `BASELINE.route_other_pct` compared against a bucket vocabulary (`OTHER`/`FLOOR`/`SWEEP`) that #2647 already replaced (`UNREPORTED`/`REPEAT`/`FLOOR`/`SWEEP` — no `OTHER` key exists any more), so route breakdown is now reported standalone rather than force-diffed against retired names; (2) `getMarketPhase()` never distinguished weekends from weekday off-hours, so a Saturday run would have read the same generic "OFF-HOURS" as a weekday evening — added an explicit `WEEKEND` phase, and every run now says plainly whether it satisfies Item 8's actual purpose (`is_rth: true/false` in `--json`, and an explicit warning line in text mode) rather than letting an off-hours run be silently mistaken for RTH validation. |
| **Fix rationale** | Kept the signal-eligibility baseline comparison for the historical record even though that specific question is already settled (fixed by #2723, re-measured 100%, documented via #2744's HELIX-MAP.md framing inversion) — labeled explicitly as settled rather than presented as something this run tests, so a reader does not re-open a closed question from stale-looking baseline text. No `--compare` flag distinction kept: the original design implied a "measure only" vs. "measure and compare" split that never made sense once the underlying data always comes from one live fetch — the script now always fetches and always compares. |
| **Blast radius** | `scripts/audit/helix-rth-measurement.mjs` and its status entry in `docs/audit/HELIX-PHASE1-COMPLETION-STATUS.md` (corrected in place — the doc previously asserted "code-complete... ready for market-hours execution" for a stub; now states what was actually verified and what still needs an actual RTH-hours run). No product code touched. |
| **Found by** | Checking Item 8 immediately after fixing the sibling Item 7 interaction-harness finding, since both were built in the same PR (#2841) under the same "framework ready" claim and the same failure mode (never executed before being marked ready) was worth checking for. |
| **Gates** | `npx tsc --noEmit` clean · `npx eslint scripts/audit/helix-rth-measurement.mjs` clean · `node scripts/check-brand.mjs` clean · 2 consecutive live runs against `https://blackouttrades.com` (text and `--json` modes), both completing with real numbers, exit 0. Run during actual RTH hours (9:30 AM-4:00 PM ET, weekday) still outstanding — this run was WEEKEND/off-hours and the script says so honestly rather than claiming otherwise. |
| **Status** | FIXED (implementation); Item 8's original purpose — confirming the baseline holds under live RTH conditions — still needs one run during actual market hours, which this fix makes possible for the first time. |
