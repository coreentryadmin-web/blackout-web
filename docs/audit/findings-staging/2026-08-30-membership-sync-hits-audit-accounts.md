## 2026-08-30 — [FINDING, P4 billing] `/api/membership/sync`'s automatic sign-in sync hit Whop for every internal audit account too — same root cause as the Clerk webhook fix, different call site — FIXED

> **kind:** `FINDING`

| Field | Detail |
|---|---|
| **What this follows up on** | Earlier this cycle: `docs/audit/findings-staging/2026-08-30-clerk-webhook-whop-sync-hits-audit-accounts.md` (PR #3212) fixed the Clerk `user.created`/`user.updated` webhook calling `syncWhopMembershipForEmail` unconditionally for every internal audit account. Per this lane's PR write-up policy ("every other call site/consumer touched by the same root cause"), swept for other callers of `syncWhopMembershipForEmail` and found a second, distinct one. |
| **Symptom** | `AuthSignedInRedirect.tsx` fires `POST /api/membership/sync` automatically on every authenticated sign-in paint ("Pay-before-sign-up: match Whop membership to this Clerk account on first authenticated paint"), fire-and-forget (`.catch(() => undefined)`, response never inspected). `scripts/audit/*.mjs` mint dozens of temp Clerk accounts against production every day and sign each one in at least once — every one of those sign-ins was hitting Whop's real membership-lookup API for an account that can never have a Whop membership. |
| **Why this is a smaller finding than the webhook one, not a no-op** | Unlike the webhook version, this path doesn't obviously throw/404 — the audit account is still alive when the client fires this request (unlike the webhook's async race against the account's own `finally`-block deletion), so `syncWhopMembershipForEmail` resolves cleanly to `tier: "free"` without an ERROR-level log. The cost here is purely wasted outbound Whop API calls on every audit sign-in, not log-channel noise — real but lower-severity than the webhook case. |
| **Fix** | Added the same `isInternalAuditEmail(email)` gate, returning the same success shape (`{ ok: true, tier: "free", updated: 0 }`) a genuinely membership-less real account would get from the real sync — so neither caller (`AuthSignedInRedirect.tsx`'s discarded response, or the member-facing `SyncMembershipButton.tsx`, which no internal-audit account would ever click) sees a behavior change. |
| **Blast radius checked, nothing else found** | `syncWhopMembershipForEmail` has 6 other callers besides these two routes: `src/app/api/admin/users/sync/route.ts` and `src/app/api/admin/users/create/route.ts` (admin-only, operator-triggered, correctly unconditional — an admin explicitly syncing/creating a specific user should always run for real), `src/lib/billing-lifecycle-email.ts` and `src/lib/tier-cache.ts` (internal library callers, not request-triggered by arbitrary sign-ins). None of those fire automatically for every audit-account sign-in the way `AuthSignedInRedirect.tsx` does — no further gate needed. |
| **Regression guard** | New `src/app/api/membership/sync/route.test.ts` (`mock.module` on `@clerk/nextjs/server`, `@/lib/membership`, `@/lib/membership-sync-limit`, `@/lib/tier-cache`, `@/features/spx/lib/spx-play-notify`; `isInternalAuditEmail` left REAL). One test with an audit email asserts `syncWhopMembershipForEmail` is never called and the response still reads `{ok:true, tier:"free"}`; one with a real email asserts the sync IS called. Confirmed **failing** (1/2) against the pre-fix route via `git stash` toggle, passing (2/2) post-fix. |
| **Gates** | `npx tsc --noEmit` clean · `npx eslint` clean on both touched files · `route.test.ts` 2/2 pass (Node 20.20.2, `--experimental-test-module-mocks`, run WITHOUT `WHOP_COMPANY_ID`/`WHOP_API_KEY` set — this route's dependencies are fully mocked so, unlike the webhook fix earlier this cycle, no fake env fixture was needed) · full `npm test` at this commit: **11448 pass / 0 fail / 2 skipped**. |
| **Status** | FIXED |
