## 3.1.1 IN-APP PURCHASE-UI AUDIT — BlackOut iOS shell

**How detection works (the architectural fact that drives every finding):** the `html.ios-app` marker is set **client-side only** by an inline `<head>` script (`src/app/layout.tsx:80-84`) that reads `navigator.userAgent` for `BlackOutiOSApp`. `src/middleware.ts` is auth-only and never inspects the UA, so **the server always renders the full pricing/purchase HTML and ships it to the app** — compliance rests entirely on CSS class coverage (`globals.css:12-14`: `html.ios-app .hide-in-ios-app{display:none!important}`). The inline script runs before body paint, so CSS-hidden content does not visually flash — but anything a class does **not** cover leaks fully, and everything hidden still ships in the DOM. `isIosAppShell()` (`src/lib/ios-app-shell.ts`) and `useIosNativeShell()` only swap copy at runtime; they are not the primary gate.

---

**BLOCKER — `src/components/landing/RedesignHome.tsx:269-293` (also hero 73-76, closing 307-309)** — The marketing homepage `/` renders a full three-tier pricing block: Community **$75/mo** (285), Premium **$199/mo** (289) with a **"Start now →"** CTA (291), Premium Yearly **$1,999/yr** (293), plus a **"See pricing"** link to `/pricing` (309). **Hidden in-app? NO.** There is zero iOS guard on this section — no `hide-in-ios-app`, no `isIosAppShell()`. The CSS that trims marketing chrome in-app (`globals.css:1782` `html.ios-app #features,#edge`) targets **legacy ids**; the redesign section id is `#rl-pricing` and is never matched (confirmed: no `ios` rule touches `rl-pricing/rl-tier/rl-tiers`). The Capacitor `server.url` is the site root (`apps/blackout-ios/capacitor.config.ts`), so **this pricing block is the app's cold-start screen** for any not-yet-signed-in reviewer, and there is no UA/redirect that steers the app away from `/`. **Rejection risk: very high — reviewer sees subscription prices on first launch.** **Fix:** wrap the `#rl-pricing` section (and the hero/closing "See pricing" links) in `hide-in-ios-app`, or better, gate the pricing block out of the server render for the app; add a `show-in-ios-app` neutral "membership managed on the web" block like `/pricing` already has.

**RISK (elevated) — `apps/blackout-ios/capacitor.config.ts:47` (`"*.whop.com"` in `allowNavigation`) + `src/components/upgrade/PlanLadder.tsx:16,34-42,71-84`** — `/upgrade`'s `PlanLadder` emits real external checkout anchors (`<a href={WHOP_CHECKOUT.*} target="_blank">` "Join Community →", "Unlock Premium →", "View plans →") and the footer emits the Whop store link (`StaticLandingFooter.tsx:79-86`). These are wrapped in `hide-in-ios-app`, so they are `display:none` — **but they still ship in the DOM**, and because `*.whop.com` is on the WKWebView navigation allowlist, if any such link is reached in-app it opens the checkout **inside the app** rather than bouncing to Safari. The CSS hide removes the visible path but not the safety net. **Rejection risk: high if any Whop link is exposed (see the homepage blocker) — a checkout that renders in the WKWebView is the exact 3.1.1 violation.** **Fix:** don't render Whop `<a>` markup at all when the request is the app (server-side UA gate), and/or remove `*.whop.com` from `allowNavigation` so a checkout URL can never load in-app.

**RISK — CSS-only concealment ships purchase DOM to the app (systemic)** — Every neutralized purchase surface is present in the shipped HTML, hidden only by `html.ios-app .hide-in-ios-app{display:none}`:
- `/pricing` `RedesignPricing` (`src/app/(marketing)/pricing/page.tsx:15` → `RedesignPricing.tsx:44-75`): $75/$199/$1,999 tiers + "Start monthly / Go yearly" all present in DOM (wrapped `hide-in-ios-app`; neutral `show-in-ios-app` card shown instead).
- `/upgrade` `PlanLadder` + `FeatureComparison` + `SyncMembershipButton` (`UpgradePageShell.tsx:69-82`) all present in DOM under `hide-in-ios-app`.
Because there is no SSR UA gate, a DOM inspection, a CSS-load failure, or a future edit that drops the class re-exposes pricing. **Rejection risk: low-moderate** (not visible in normal tapping; no flash). **Fix (durable):** read the `BlackOutiOSApp` UA on the server (middleware/RSC header) and render the neutral variant instead of `display:none`-ing the real one — so the app literally never receives pricing markup.

**NOTE / low — `src/components/landing/StaticLandingFooter.tsx:37`** — Footer "Instruments" list has `{ label: "Vector", href: "/pricing" }` with **no `iosHide`**, so this link is visible in-app (the sibling "Pricing"/"Upgrade" rows at 42/44 correctly set `iosHide`). Destination `/pricing` is neutralized in-app, so it is not a purchase leak, but it is an un-hidden link into the pricing route and reads as mislabeled. **Fix:** add `iosHide: true` (and correct the label/target).

**OK — `/upgrade` neutralization** (`UpgradePageShell.tsx` + `app/(marketing)/upgrade/page.tsx`): purchase pieces are `hide-in-ios-app`; a `show-in-ios-app` "managed on the web / Open SPX desk" card (58-67) replaces them; layout/copy swap via `useIosNativeShell()`. `AuthProofRail variant="upgrade"` returns `null` (`AuthProofRail.tsx:29`) — no price leak.
**OK — SpxDashboard paywall** (`src/features/spx/components/SpxDashboard.tsx:139-170`): dual-rendered — web shows "Upgrade… Unlock Premium"; in-app shows "Membership is managed on the web" + "Check membership" → `/upgrade` (neutralized). Correct pattern.
**OK — gated desks** (`flows/heatmap/terminal/nighthawk`): `requireTier` server-redirects non-premium users to `/upgrade` (`src/lib/auth-access.ts:39`), which is neutralized in-app.
**OK — in-app native menu** (`src/components/ios/IosNativeMenu.tsx:124`): "Membership" → `/upgrade` (neutral). Desk `Nav.tsx` Pricing link is `iosHide` (34,303); "Get access →" CTAs render only when signed-out. `StaticMarketingNav.tsx:23` hides the whole marketing link row in-app.
**OK — no in-app account billing surface:** `src/app/(site)/account/page.tsx` has no pricing/upgrade/Whop links; billing controls are admin-only (`UserManagement.tsx`, `admin/users`) and are sync/tier tools, not checkout — a concern only if the reviewer demo account is granted `role:admin` (it should not be).

**VERDICT: NOT 3.1.1-submittable as-is.** One hard blocker must be fixed first — the `/` homepage renders a full subscription pricing table ($75/$199/$1,999) with a "Start now" CTA and is completely un-gated in-app, making it the app's launch screen. Fix that (wrap/omit `#rl-pricing` + hero/closing pricing links for the app), and pair it with removing `*.whop.com` from the WKWebView `allowNavigation` allowlist so a checkout URL can never open in-app; the remaining CSS-only-concealment items are a strong follow-up (move detection server-side) but are not on their own visible-in-use blockers.
